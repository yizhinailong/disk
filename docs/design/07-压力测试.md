# 网盘系统 - 压力测试

## 1. 概述

### 1.1 压测目标

本测试旨在评估网盘系统在高并发场景下的性能表现，主要关注以下指标：

1. **吞吐量（QPS/TPS）**：系统每秒能处理的请求数量
2. **响应延迟**：请求从发出到收到响应的时间
3. **并发处理能力**：系统同时处理请求的最大能力
4. **错误率**：在高负载下系统的稳定性

### 1.2 工具选型

本系统采用 `drogon_ctl press` 作为压测工具。

### 1.3 为什么选择 drogon_ctl press

| 优势 | 说明 |
|------|------|
| 无需额外安装 | Drogon 框架内置工具，随框架提供 |
| 与框架紧密集成 | 原生支持 Drogon 应用的压测 |
| 功能足够 | 支持并发、持续时间、请求数等核心参数 |
| 输出直观 | 提供 TOTALS、TRAFFIC、TIMING、SPEED 等关键指标 |

## 2. 压测环境

### 2.1 前置条件

在执行压测前，确保以下条件满足：

1. 后端服务已启动并运行
2. MySQL 数据库服务正常
3. Redis 服务正常
4. `drogon_ctl` 工具已安装并可用

### 2.2 服务配置

| 配置项 | 默认值 |
|--------|--------|
| 服务地址 | http://127.0.0.1:8080 |
| 压测工具 | drogon_ctl press |
| 测试账户 | admin |
| 测试密码 | Admin123 |

### 2.3 数据库状态

压测默认使用空数据库状态：

- 用户表：默认存在 admin 用户
- 文件列表：空（无文件）
- 测试场景：反映空目录下的性能表现

### 2.4 环境变量

| 变量名 | 说明 | 默认值 |
|--------|------|--------|
| BENCH_HOST | 服务地址 | http://127.0.0.1:8080 |

| BENCH_PASSWORD | 测试密码 | Admin123 |

## 3. 压测接口

### 3.1 接口列表

| 接口 | 方法 | 路径 | 认证 | 速率限制 | 说明 |
|------|------|------|------|---------|------|
| 健康检查 | GET | /api/health | 无 | 无 | 基线性能测试 |
| 用户登录 | POST | /api/auth/login | 无 | 无 | 登录吞吐量测试 |
| 文件列表 | GET | /api/file/list | JWT | 无 | 文件浏览性能测试 |
| 上传初始化 | POST | /api/file/upload/init | JWT | 240/min/用户 | 上传性能测试（受速率限制） |

### 3.2 接口详细说明

#### 3.2.1 健康检查接口

**路径**：`GET /api/health`

**说明**：用于测试系统基线性能，不涉及任何业务逻辑。

**请求参数**：无

**响应示例**：
```json
{
  "code": 0,
  "message": "success"
}
```

#### 3.2.2 用户登录接口

**路径**：`POST /api/auth/login`

**说明**：测试用户认证的吞吐量。

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| account | string | 是 | 账户名 |
| password | string | 是 | 密码 |

**请求示例**：
```json
{
  "account": "admin",
  "password": "Admin123"
}
```

**响应示例**：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expiresIn": 7200
  }
}
```

#### 3.2.3 文件列表接口

**路径**：`GET /api/file/list`

**说明**：测试文件列表查询性能。

**认证**：需要携带有效的 JWT 令牌。

**请求头**：
```
Authorization: Bearer <accessToken>
```

**查询参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| parent_id | string | 否 | 文件夹 ID，默认为根目录（0 表示根目录） |
| page | int | 否 | 页码，默认为 1 |
| page_size | int | 否 | 每页数量，默认为 20 |

#### 3.2.4 上传初始化接口

**路径**：`POST /api/file/upload/init`

**说明**：测试文件上传初始化的性能。该接口受速率限制约束（240次/分钟/用户）。

**认证**：需要携带有效的 JWT 令牌。

**请求头**：
```
Authorization: Bearer <accessToken>
Content-Type: application/json
```

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| filename | string | 是 | 文件名 |
| file_size | int64 | 是 | 文件大小（字节） |
| file_hash | string | 是 | 文件内容哈希（MD5） |
| parent_id | string | 否 | 父文件夹 ID，默认为根目录 |

**请求示例**：
```json
{
  "filename": "test.txt",
  "file_size": 1024000,
  "file_hash": "098f6bcd4621d373cade4e832627b4f6",
  "parent_id": "root"
}
```

## 4. 脚本使用

### 4.1 目录结构

```
test/benchmark/
├── run_all.sh              # 全量压测编排脚本
├── get_token.sh            # JWT 令牌获取辅助脚本
├── bench_health.sh          # 健康检查压测脚本
├── bench_login.sh          # 登录压测脚本
├── bench_file_list.sh      # 文件列表压测脚本
├── bench_upload_init.sh    # 上传初始化压测脚本
└── requests/               # JSON 请求模板目录
    ├── health.json
    ├── login.json
    ├── file_list.json
    └── upload_init.json
```

### 4.2 运行方式

#### 4.2.1 全量压测

执行所有压测脚本的编排脚本：

```bash
bash test/benchmark/run_all.sh
```

该脚本会按顺序执行健康检查、登录、文件列表、上传初始化四个接口的压测。

#### 4.2.2 单个接口压测

执行单个接口的压测：

```bash
bash test/benchmark/bench_health.sh -n 10000 -c 100 -t 4
bash test/benchmark/bench_login.sh -n 10000 -c 100 -t 4
bash test/benchmark/bench_file_list.sh -n 10000 -c 100 -t 4
bash test/benchmark/bench_upload_init.sh -n 200 -c 10 -t 2
```

### 4.3 参数说明

| 参数 | 说明 | 默认值 | 备注 |
|------|------|--------|------|
| -n | 总请求数 | 10000（上传初始化: 200） | 压测发送的请求总数 |
| -c | 并发连接数 | 100（上传初始化: 10） | 同时建立的连接数 |
| -t | 线程数 | 4（上传初始化: 2） | 压测使用的线程数 |
| BENCH_HOST | 服务地址 | http://127.0.0.1:8080 | 压测目标服务器地址 |

### 4.4 请求模板格式

JSON 请求模板格式：

```json
{
  "method": "POST",
  "header": {
    "Content-Type": "application/json",
    "Authorization": "Bearer <token>"
  },
  "body": {
    "field1": "value1",
    "field2": "value2"
  }
}
```

## 5. 压测策略

### 5.1 分阶段方法

采用渐进式压测策略，逐步增加负载以确定系统性能边界：

| 阶段 | 总请求数 | 并发连接数 | 线程数 | 说明 |
|------|----------|-----------|--------|------|
| 基线 | 1000 | 10 | 2 | 验证服务正常运行 |
| 中等 | 10000 | 50 | 4 | 模拟常规负载 |
| 高并发 | 50000 | 200 | 8 | 模拟峰值场景 |
| 极限 | 100000 | 500 | 16 | 寻找系统性能边界 |

### 5.2 压测执行流程

1. **准备阶段**：启动服务，确认环境变量配置正确
2. **基线测试**：使用低并发验证系统可用性
3. **负载测试**：逐步增加并发，观察系统表现
4. **结果记录**：记录各阶段的性能指标
5. **瓶颈分析**：分析结果定位性能瓶颈

### 5.3 测试顺序建议

建议按以下顺序执行压测：

1. 健康检查（无外部依赖，最快定位问题）
2. 登录（验证认证性能）
3. 文件列表（验证数据库查询性能）
4. 上传初始化（验证业务逻辑和速率限制）

## 6. 结果分析

### 6.1 输出解读

`drogon_ctl press` 的输出包含四个部分：

#### TOTALS（总体统计）
| 字段 | 说明 |
|------|------|
| Total requests | 总请求数 |
| Requests/sec | 每秒请求数（QPS） |
| Duration | 测试持续时间 |
| Failed requests | 失败请求数 |

#### TRAFFIC（流量统计）
| 字段 | 说明 |
|------|------|
| Received | 收到的数据量 |
| Sent | 发送的数据量 |

#### TIMING（延迟统计）
| 字段 | 说明 |
|------|------|
| Avg req time | 平均请求时间 |
| Min req time | 最小请求时间 |
| Max req time | 最大请求时间 |

#### SPEED（速度统计）
| 字段 | 说明 |
|------|------|
| Transfer/sec | 传输速度（字节/秒） |

### 6.2 关键指标

| 指标 | 说明 | 健康阈值 |
|------|------|----------|
| QPS | 每秒处理的请求数 | 越高越好 |
| 平均延迟 | 请求的平均响应时间 | < 100ms |
| 错误率 | 失败请求占总请求的比例 | < 0.1% |

### 6.3 瓶颈排查路径

| 现象 | 可能原因 | 排查方向 |
|------|----------|----------|
| QPS 上不去 | CPU 瓶颈、线程数不足、连接池耗尽 | 检查 CPU 使用率、线程配置、连接池大小 |
| P99 延迟高 | 数据库慢查询、Redis 超时、IO 阻塞 | 分析慢查询日志、检查 Redis 连接、分析 IO 使用率 |
| 错误率升高 | 连接池耗尽、请求超时、资源不足 | 检查连接池配置、调整超时时间、监控资源使用 |

## 7. 局限性说明

### 7.1 延迟统计局限

`drogon_ctl press` 仅提供平均延迟，无法获取延迟分布：

- 无 P50/P95/P99 分位值
- 无法判断延迟抖动情况
- 如需更详细的延迟分析，可通过多次运行并记录结果来估算延迟分布

### 7.2 链路测试局限

该工具不支持多步骤链路测试：

- 无法模拟「登录 -> 浏览 -> 上传」的完整流程
- 每个接口独立压测，无法反映真实用户操作路径
- 建议手动串联多个接口进行链路压测

### 7.3 空数据库影响

压测在空数据库状态下进行：

- 文件列表查询反映的是空目录性能
- 无法反映有大量文件时的查询性能
- 分页、排序等操作在有数据时表现可能不同

### 7.4 单用户测试局限

所有请求共用同一个 admin 账户：

- 受单用户速率限制约束（上传初始化 240 次/分钟）
- 无法模拟多用户并发场景
- 认证服务的实际并发压力被低估

### 7.5 静态请求体局限

每次请求发送相同的请求体：

- 无动态参数变化
- 无法模拟真实用户的数据多样性
- 缓存命中等场景无法真实反映
