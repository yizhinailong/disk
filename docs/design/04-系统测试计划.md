# 网盘系统 - 系统测试计划

## 1. 测试概述

### 1.1 测试目标

本测试计划旨在确保网盘系统的功能正确性、性能达标、安全可靠。测试覆盖以下方面：

1. **功能测试**：验证所有功能模块按需求正确实现
2. **性能测试**：验证系统在高并发场景下的表现
3. **安全测试**：验证系统的安全防护机制
4. **兼容性测试**：验证系统在不同网络环境下的稳定性

### 1.5 后端集成测试服务生命周期

CTest 中访问本地 Disk HTTP API 的 Python 集成脚本必须在进入业务测试前调用 `ensure_server()`，不得仅调用 `check_server()` 并假定前序脚本已启动服务。共享 helper 的所有权合同如下：

- 目标地址已就绪时，helper 只借用外部服务，不获得其停止权。
- 目标地址未就绪时，helper 启动 `SERVER_BIN`，等待 readiness，并只在当前脚本退出时停止该脚本自己启动的进程。
- 启动失败必须立即回收已创建的子进程和日志句柄；`cleanup()` 必须幂等。
- CTest 注册函数在 configure 阶段检查普通 HTTP 集成脚本的 `ensure_server()` 合同；新脚本缺少该合同时配置失败。
- 集成测试继续使用 `RUN_SERIAL TRUE`，因为 PostgreSQL、Redis 和本地存储夹具仍是共享状态。串行约束不得被解读为服务启动顺序依赖。

`test_server_lifecycle.py` 对“借用外部服务不停止”、“自启动服务在退出时回收”、“启动失败不泄漏进程”和幂等清理提供回归覆盖。`S3StorageAdapterIntegration` 不启动 Disk，`S3AppFlowIntegration` 使用独立端口和 S3 专用配置自行管理服务，因此两者不应用上述普通 HTTP 脚本合同。

### 1.6 禁用与跳过用例审计

Issue #29 所引用的 `eea1077` 基线包含 20 个 disabled GoogleTest；其中一个 `DownloadMeta` 查询占位项已在后续主线删除，因此本次审计的当前集合为 19 个 disabled 和一个无条件 migration skip。审计结论是不保留默认 disabled 或无条件 skip：

| 原用例组 | 数量 | 处置 | 可执行替代覆盖 / 理由 |
|----------|------|------|----------------------------|
| `ShareServiceQueryBaselineTest` DB 查询观测占位 | 1（基线为 2） | 删除 | 占位体只执行 `SUCCEED()`，无 DB 计数仪器；响应与下载行为由已启用的 `ShareServiceQuery_test.cpp` 和 `test_download_flow.py` 验证。 |
| `FileUploadConsistencyFaultInjection` 旧 Zone B/C 基线 | 4 | 删除 | 用例描述已被事务化重构替代的 MySQL 失败状态，且只执行 `SUCCEED()`；`test_safety_upload_invariants.py` 和 `test_safety_content_quota.py` 在真实 PostgreSQL 上验证回滚、配额和过期任务语义。 |
| `CleanupServiceIntegrationTest` 空占位 | 5 | 删除 | 用例体只执行 `GTEST_SKIP()`；已启用的 `CleanupService_test.cpp`、`test_safety_upload_invariants.py` 和 `test_safety_content_quota.py` 覆盖分批、过期上传、过期回收站、配额与 blob 引用。 |
| `JwtAuthFilterTest` Redis / Drogon 占位 | 9 | 删除 | 用例体只执行 `SUCCEED()`；已启用的 filter 错误合同、`TokenServiceRevocation_test.cpp`、`test_auth_flow.py` 和 `test_auth_lifecycle.py` 覆盖 header、签名、过期、撤销及认证属性行为。 |
| `MigrationContinuityLegacyTokenVerifiableByUnified` | 1 skip | 删除 | 旧分享 Token 服务已删除，仓库中没有可执行的旧产物或兼容输入；当前统一 Token 及 scope 合同已由同文件的启用用例覆盖。 |

S3 两项不属于 disabled 或无条件 skip，而是可审计的环境门控。CTest 必须通过 `SKIP_REGULAR_EXPRESSION` 将未打开 gate 的输出记为 `Skipped`，不得显示为 `Passed`；只有设置 2.8.2 节变量并实际执行后才能作为 S3 通过证据。

### 2.8 后端重构收尾验证

#### 2.8.1 配额数据库行为

`QuotaService` 的正确性依赖 PostgreSQL 条件更新的 `affectedRows()`、事务回滚和真实并发可见性。现有轻量 `MockDbClient` 不能证明这些数据库语义，因此 `test/integration/test_safety_content_quota.py` 是 reserve/commit/release/reconciliation 的权威安全网；C++ 单元测试仅检查纯契约和不依赖数据库的结构。

该脚本会在串行全量集成套件中复用共享数据库：人为破坏配额的用例必须先快照精确行值，以不依赖其他进行中任务的值强制命中目标条件，并在清理本用例前恢复快照。因此欠预留提交必须将 `storage_reserved` 强制设为小于本上传任务的 `reserved_bytes`，不能仅从全局预留值中减去本用例字节。

过期上传清理同样作用于共享数据库中的全部到期任务。需要精确断言本夹具预留量变化的用例，必须先执行一次确定性过期清理，再采集配额基线并创建本夹具，避免把前序串行用例遗留的到期任务释放量错误计入当前断言。

文件列表类集成用例不得假设共享根目录的夹具数量少于单页上限。若断言刚创建的文件出现在列表中，应显式使用受支持的确定性排序让新夹具进入当前页，或按响应分页遍历全部结果。

| DIST-JOB-001 | 24 个 Worker 同时认领同一批到期任务 | `SKIP LOCKED` 使每条任务只被一个 owner 认领，无重复 ID |
| DIST-JOB-002 | Worker 租约过期后由新 owner 接管，旧 owner 再续租/回写 | 新 owner 成功，旧 owner 所有更新均受条件拒绝 |
| DIST-JOB-003 | 临时失败达到 `max_attempts` 或最后一次执行崩溃 | 前者立即、后者在租约过期后进入 `DeadLetter`，可人工重放 |

S3 存储单元测试使用可观测的内存客户端验证：分片条件写与重复校验、错误 key/大小/ETag/MD5
拒绝、Range 短读、组装 multipart part 顺序和大小、assembled 到 SHA-256 final 的 server-side
multipart copy 范围、任一 part/complete 失败后的 Abort、final 大小冲突、数据库 `storage_path`
读取、指定 assembled 对象幂等删除，以及超过 1000 个对象时仅在会话精确前缀内分页清理。
环境门控的 MinIO 测试再验证真实服务对 `If-None-Match`、multipart ETag、UploadPartCopy、Range
和删除不存在对象的兼容行为。

#### 2.9.3 Worker 与迁移

| 用例ID | 测试项 | 预期结果 |
|--------|--------|----------|
| DIST-JOB-001 | 两 Worker 竞争任务 | `SKIP LOCKED` 认领，逻辑副作用唯一 |
| DIST-JOB-002 | Worker 租约到期 | 第二 Worker 在目标 RTO 内接管 |

| DIST-MIGRATION-002 | 迁移重复执行 | forward 验证可重复，rollback 前置条件可诊断且不丢数据 |
