# 代码注释规范

## 概述

本文档定义了 Disk 项目的统一代码注释规范，涵盖 C++ 后端（Drogon框架）和 Qt/QML 桌面客户端。规范旨在提高代码可读性、可维护性，并确保全项目使用一致的中文术语。

### 目标

- 统一 C++ 和 QML 代码的注释风格
- 规范中文术语的使用
- 提供可直接复制的注释模板
- 通过 PR 自检命令确保规范落地

### 适用范围

- C++ 后端代码：`src/` 目录（Drogon 框架）
- Qt/QML 前端代码：`ui/diskqml/src/` 和 `ui/diskqml/qml/` 目录
- 测试代码：`test/` 目录

### 关键术语速查

| 类别 | 规范中文 | 禁止使用的英文变体 |
|------|----------|-------------------|
| 认证与授权 | 认证服务, 用户注册, 用户登录, 用户登出 | AuthService, Register, Login, Logout |
| 令牌管理 | 访问令牌, 刷新令牌, 令牌验证, 令牌刷新 | access_token, refresh_token, VerifyToken |
| 用户管理 | 用户名, 邮箱, 密码, 用户ID, 昵称, 账号 | username, email, password, user_id |
| 文件管理 | 文件上传服务, 文件列表, 文件名, 文件夹 | FileService, file list, filename |
| 分片上传 | 文件哈希, 分片索引, 分片数据, 上传会话 | file_hash, chunk_index, chunk_data |
| 高级特性 | 秒传, 断点续传 | instant upload, resume upload |
| 存储管理 | 存储配额, 存储使用量 | storage_quota, storage_used |
| 分享管理 | 分享服务, 分享码, 分享令牌 | ShareService, share_code, share_token |
| 回收站管理 | 回收站服务, 回收站项目, 恢复, 彻底删除 | TrashService, restore, delete |
| 请求响应 | 请求, 响应, 验证规则, 必填字段 | Request, Response, validation |

### 术语使用原则

1. **必须使用规范中文术语**：注释中禁止使用英文变体
2. **保持术语一致性**：同一概念在整个项目中使用相同术语
3. **术语来源可追溯**：所有术语均来自后端代码实际使用

## C++ Doxygen 注释模板

### 文件头注释模板

所有 C++ 头文件必须包含以下文件头注释：

```cpp
/**
 * @file AuthService.hpp
 * @brief 认证服务
 * @details 处理用户认证相关的业务逻辑，包括注册、登录、登出、令牌刷新等功能
 * @author LiuFeng (liufeng.code@outlook.com)
 * @date 2026-01-14
 *
 * @copyright Copyright (c) 2026
 */
```

**模板变量**：
- `@file`：文件名（与实际文件名一致）
- `@brief`：一句话简要描述（使用规范中文术语）
- `@details`：详细描述（可选，用于复杂文件）
- `@author`：作者姓名和邮箱
- `@date`：创建日期（格式：YYYY-MM-DD）

### 类/结构体注释模板

```cpp
/**
 * @brief 认证服务类
 * @details 提供用户注册、登录、登出、令牌刷新等认证相关功能
 */
class AuthService {
    // ...
};
```

### 方法注释模板

#### 基础方法注释

```cpp
/**
 * @brief 用户注册
 *
 * 业务规则：
 * - 验证用户名和邮箱的唯一性
 * - 密码使用 libsodium 的 Argon2id 算法加密存储
 * - 分配默认存储配额（10GB）
 *
 * @param request 注册请求
 * @return drogon::Task<Result<RegisterResponse>> 成功返回用户信息，失败返回错误
 */
[[nodiscard]]
auto Register(RegisterRequest request) -> drogon::Task<Result<RegisterResponse>>;
```

#### 私有方法注释

```cpp
private:
    /**
     * @brief 检查用户名是否已存在
     * @param username 用户名
     * @return drogon::Task<bool> 用户名是否存在
     */
    [[nodiscard]]
    auto IsUsernameExists(std::string username) const -> drogon::Task<bool>;
```

#### 静态方法注释

```cpp
    /**
     * @brief 用户模型转响应结构
     * @param user 用户模型
     * @return RegisterResponse 响应结构
     */
    [[nodiscard]]
    static auto UserToResponse(const drogon_model::disk::Users& user) -> RegisterResponse;
```

### 成员变量注释模板

```cpp
private:
    drogon::orm::DbClientPtr m_db_client;                          ///< 数据库客户端
    std::shared_ptr<disk::services::RedisService> m_redis_service; ///< Redis服务
    static constexpr uint64_t DEFAULT_STORAGE_QUOTA = 10737418240; ///< 默认存储配额 10GB
```

**注意**：
- 使用 `///<` 进行单行注释
- 成员变量命名使用 `m_` 前缀（`m_snake_case`）
- 常量使用 `UPPER_SNAKE_CASE` 命名

### Doxygen 标签说明

| 标签 | 用途 | 必需性 |
|------|------|--------|
| `@file` | 文件名 | 文件头必需 |
| `@brief` | 简要描述 | 所有注释必需 |
| `@details` | 详细描述 | 可选 |
| `@author` | 作者 | 文件头必需 |
| `@date` | 日期 | 文件头必需 |
| `@param` | 参数说明 | 有参数时必需 |
| `@return` | 返回值说明 | 有返回值时必需 |
| `@copyright` | 版权声明 | 文件头必需 |

## 正例与反例

### 示例 1：认证相关注释

#### ✅ 正例（符合规范）

```cpp
/**
 * @file AuthService.hpp
 * @brief 认证服务
 * @author LiuFeng (liufeng.code@outlook.com)
 * @date 2026-01-14
 */

/**
 * @brief 用户登录
 *
 * 业务规则：
 * - 支持用户名或邮箱登录
 * - 密码错误5次锁定账户15分钟
 * - 检查账户禁用/锁定状态
 * - 登录成功后更新登录信息
 *
 * @param request 登录请求
 * @param ip_address 客户端IP地址
 * @return drogon::Task<Result<LoginResponse>> 成功返回令牌和用户信息，失败返回错误
 */
[[nodiscard]]
auto Login(LoginRequest request, std::string ip_address) -> drogon::Task<Result<LoginResponse>>;

drogon::orm::DbClientPtr m_db_client; ///< 数据库客户端
std::shared_ptr<disk::services::RedisService> m_redis_service; ///< Redis服务
```

#### ❌ 反例（违反规范）

```cpp
/**
 * @file AuthService.hpp
 * @brief Authentication service
 * @author LiuFeng (liufeng.code@outlook.com)
 * @date 2026-01-14
 */

/**
 * @brief User login
 *
 * Business rules:
 * - Support login with username or email
 * - Lock account after 5 failed password attempts
 * - Check account disabled/locked status
 * - Update login info after successful login
 *
 * @param request Login request
 * @param ip_address Client IP address
 * @return drogon::Task<Result<LoginResponse>> Returns token and user info on success, error on failure
 */
[[nodiscard]]
auto Login(LoginRequest request, std::string ip_address) -> drogon::Task<Result<LoginResponse>>;

drogon::orm::DbClientPtr m_db_client; // Database client
std::shared_ptr<disk::services::RedisService> m_redis_service; // Redis service
```

**问题说明**：
- 简要描述使用了英文（`Authentication service`, `User login`）
- 业务规则使用了英文（`Business rules`, `Support login with`）
- 参数和返回值说明使用了英文（`Login request`, `Client IP address`, `Returns token`）
- 成员变量注释使用了英文（`Database client`, `Redis service`）

### 示例 3：DTO 验证规则注释

#### ✅ 正例（符合规范）

```cpp
/**
 * @file LoginRequest.hpp
 * @brief 登录请求数据传输对象
 * @details 封装登录请求的数据结构，用于 API 层和 Service 层之间的数据传递
 */

/**
 * @brief 登录请求结构体
 * @details 验证规则：
 * - 账号（用户名或邮箱）：必填，长度 3-50 字符
 * - 密码：必填，长度 8-50 字符
 * - 字符类型验证：账号只允许字母、数字、下划线、@、. 符号
 */
struct LoginRequest {
    std::string account;   ///< 账号（用户名或邮箱）
    std::string password;  ///< 密码

    /**
     * @brief 从 HTTP 请求解析登录请求
     * @param req HTTP 请求对象
     * @return Result<LoginRequest> 成功返回解析后的请求结构，失败返回验证错误
     */
    static auto FromRequest(const drogon::HttpRequestPtr& req) -> Result<LoginRequest>;

private:
    /**
     * @brief 验证账号字段
     * @return bool 验证是否通过
     */
    auto ValidateAccount() const -> bool;

    /**
     * @brief 验证密码字段
     * @return bool 验证是否通过
     */
    auto ValidatePassword() const -> bool;
};
```

#### ❌ 反例（违反规范）

```cpp
/**
 * @file LoginRequest.hpp
 * @brief Login request DTO
 * @details Encapsulates login request data structure for API and Service layer data transfer
 */

/**
 * @brief Login request struct
 * @details Validation rules:
 * - Account (username or email): Required, length 3-50 characters
 * - Password: Required, length 8-50 characters
 * - Character type validation: Account only allows letters, numbers, underscores, @, . symbols
 */
struct LoginRequest {
    std::string account;   // Account (username or email)
    std::string password;  // Password

    /**
     * @brief Parse login request from HTTP request
     * @param req HTTP request object
     * @return Result<LoginRequest> Returns parsed request structure on success, validation error on failure
     */
    static auto FromRequest(const drogon::HttpRequestPtr& req) -> Result<LoginRequest>;

private:
    /**
     * @brief Validate account field
     * @return bool Whether validation passed
     */
    auto ValidateAccount() const -> bool;

    /**
     * @brief Validate password field
     * @return bool Whether validation passed
     */
    auto ValidatePassword() const -> bool;
};
```

**问题说明**：
- 所有注释均使用了英文
- 验证规则使用了英文

## PR 自检命令

### 1. 范围检查（Scope Gate）

在提交代码前，必须运行范围检查命令，确保只修改允许的文件：

```bash
# 完整检查（范围 + 仅注释检查）
.sisyphus/scripts/scope-gate.sh full

# 仅检查文件范围
.sisyphus/scripts/scope-gate.sh scope

# 仅检查是否为注释修改
.sisyphus/scripts/scope-gate.sh comments
```

**允许修改的文件**：
- QML 源代码：`ui/diskqml/src/**`
- QML 视图文件：`ui/diskqml/qml/**`
- 本文档：`docs/07-代码注释规范.md`

**禁止修改的文件**：
- 后端代码：`src/**`
- TUI 代码：`ui/tui/**`
- 构建目录：`build/**`
- 对象文件：`*.o`, `*.a`

### 2. 术语一致性检查

检查新增或修改的注释是否使用了规范中文术语：

```bash
# 检查特定术语的使用（以"访问令牌"为例）
grep -r "访问令牌" ui/diskqml/ docs/07-代码注释规范.md

# 检查是否使用了禁用的英文术语
grep -r "access_token" ui/diskqml/ docs/07-代码注释规范.md
```

### 3. 注释完整性检查

检查文件头注释是否完整：

```bash
# 检查所有头文件是否有 @file 标签
grep -L "^/\*\*" ui/diskqml/src/**/*.hpp ui/diskqml/src/**/*.h 2>/dev/null | head -20

# 检查所有 @brief 标签
grep -r "@brief" ui/diskqml/ | wc -l

# 检查 QML 文件头注释
grep -L "^/\*\*" ui/diskqml/qml/**/*.qml 2>/dev/null | head -20
```

### 4. Doxygen 语法检查

检查 Doxygen 注释语法是否正确：

```bash
# 检查是否有未闭合的注释块
grep -r "/\*\*" ui/diskqml/ | grep -v "\*/" | head -20

# 检查 @param 和 @return 标签配对
grep -A 10 "@brief.*(" ui/diskqml/src/**/*.hpp | grep -E "@param|@return" | head -30
```

### 5. 提交前完整检查流程

```bash
# 1. 运行范围检查
.sisyphus/scripts/scope-gate.sh full
if [ $? -ne 0 ]; then
    echo "范围检查失败！请检查修改的文件是否在允许范围内。"
    exit 1
fi

# 2. 检查新增注释是否使用规范中文术语
echo "检查注释中的英文术语..."
grep -r "@brief.*[A-Za-z]" ui/diskqml/ docs/07-代码注释规范.md | grep -v "@date\|@author\|@file" | head -20

# 3. 检查文件头完整性
echo "检查文件头完整性..."
find ui/diskqml/src ui/diskqml/qml -name "*.hpp" -o -name "*.h" -o -name "*.qml" | while read file; do
    if ! grep -q "^/\*\*" "$file"; then
        echo "缺少文件头注释：$file"
    fi
done

# 4. 代码格式化（C++）
echo "格式化 C++ 代码..."
find ui/diskqml/src -name '*.cpp' -o -name '*.hpp' | xargs clang-format -i

# 5. 运行测试（如果适用）
echo "运行测试..."
cd ui/diskqml/build && make && ./appdiskqml --version

echo "所有检查通过，可以提交。"
```
