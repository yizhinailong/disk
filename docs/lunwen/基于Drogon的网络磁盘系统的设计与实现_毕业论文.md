# 基于Drogon的网络磁盘系统的设计与实现

## 摘　要

近年来，个人和团队产生的文档、图片、代码资料不断增加，在线存储、集中管理和便捷共享逐渐成为常见需求。公有云网盘使用门槛低，但数据由第三方平台托管，带宽、容量和服务策略也受平台限制；一些自建网盘方案虽然能增强可控性，却常在性能、部署复杂度或使用体验上存在不足。基于这样的背景，本文设计并实现一个面向私有化部署的网络磁盘系统。

本文按照软件工程流程完成系统设计与实现。后端使用C++23和Drogon框架，通过非阻塞异步I/O和C++协程处理文件传输、认证鉴权和管理接口；桌面客户端使用Qt 6与QML，通过RESTful API与后端交互。数据层中，MySQL保存用户信息、文件元数据、目录结构、上传任务、分享记录、回收站和操作日志等持久化数据；Redis保存刷新令牌、令牌黑名单、登录失败计数、分享访问状态和限流计数等短时状态；文件实体按内容哈希落盘到服务器本地文件系统。系统功能按普通用户、访客和管理员三类场景展开，主要包括注册登录、令牌刷新、个人资料与存储空间查看，文件和目录的列表、搜索、重命名、移动、复制、软删除，大文件分片上传、断点续传、秒传、Range下载，外链分享、分享访问、回收站管理，以及后台用户、分享、日志和系统状态管理。

目前系统已经跑通私有化网盘的主要流程。普通用户可以在桌面端管理文件、执行传输任务和创建分享，管理员可以查看用户、分享、日志和系统状态。测试结果显示，注册登录、文件传输、目录管理、分享访问和权限控制等流程与设计要求一致；文件传输和异步接口处理场景中，Drogon的协程与非阻塞I/O机制能够保持较稳定的响应。本文实现的系统可作为C++技术栈下文件服务后端与桌面客户端配套开发的一个实践样例。

关键词：网络磁盘；文件管理；Drogon；C++23；RESTful API

## ABSTRACT

In recent years, with the rapid growth of personal digital content and team collaboration materials, users have placed higher demands on online file storage, management, and sharing. Although public cloud storage services are convenient, they still have limitations in data privacy, upload and download bandwidth, and service controllability. Some self-hosted network disk solutions are also constrained by performance, deployment, and usability. Therefore, designing and implementing a high-performance network disk system that is suitable for private deployment and independent operation has practical application value.

This thesis completes the system design and implementation according to the software engineering process. The backend adopts C++23 and the Drogon Web framework, using non-blocking asynchronous I/O and C++ coroutines to process file transfers and business interfaces. The desktop client is built with Qt 6 and QML and interacts with the backend through RESTful APIs. MySQL is used to store core data such as user information, file metadata, directory structures, upload tasks, share records, trash records, and operation logs. Redis is introduced to manage short-lived states including refresh tokens, token blacklists, login failure counters, share access states, and rate-limiting counters. File entities are stored on the server's local filesystem using content-addressed storage. The system covers regular-user, visitor, and administrator scenarios, supporting registration and login, token refresh, profile and storage querying, file and folder listing, searching, renaming, moving, copying, soft deletion, resumable chunked upload with instant deduplication, Range download, external sharing, share access, trash management, and backend management of users, shares, logs, and system status.

The system currently covers the main business requirements of a private network disk. Users can complete online file management, file transfer, and file sharing through the desktop client, while administrators can perform platform operation and maintenance through the management interface. Test results show that the core workflows run stably with clear permission boundaries, and the backend maintains good response efficiency in asynchronous API processing and file transfer with the support of Drogon. This thesis completes a runnable private network disk system and provides an engineering practice reference for building file-service Web backends and supporting desktop clients with the C++ technology stack.

KEYWORDS: Network Disk; File Management; Drogon; C++23; RESTful API

## 前　言

现在学习、工作和生活中产生的数字资料越来越多。课程文档、个人笔记、项目代码、图片和视频都需要稳定的存储位置，也需要在不同设备之间方便访问。网络磁盘把文件保存和网络访问结合起来，已经成为日常资料管理中常用的工具。与此同时，公有云盘也有一些现实限制，例如隐私风险、带宽限速、免费空间有限以及对平台策略的依赖。对于希望自己掌握数据和服务环境的用户来说，私有化网盘仍然有需求。

从使用流程看，网盘的核心仍然是上传、下载和分享。用户需要一个统一入口来上传文件、整理目录，并在需要时快速找到目标文件；遇到大文件时，断点续传也很重要，否则网络中断后重新上传会浪费大量时间。分享则是另一个常见场景，用户往往希望通过外链把文件发送给他人，同时控制链接有效期和访问权限。即时通信软件或传统文件传输工具虽然也能传文件，但文件管理分散，后续查找和权限控制都不够方便。

运维也需要单独考虑。管理员日常关注的不仅是用户数量和存储占用，还包括数据库、Redis和磁盘这些基础组件是否正常。如果账号管理、配额调整、访问规则和状态检查分散在不同工具里，维护成本会被抬高，故障定位也会变慢。因此，本系统在设计时没有只围绕普通用户的文件操作展开，而是把后台管理效率一并纳入实现范围。

后端采用C++23和Drogon，原因在于文件服务对I/O处理和资源占用比较敏感。Drogon底层通过epoll（在macOS/FreeBSD下为kqueue）处理网络事件，并支持协程化请求处理，适合上传、下载这类等待时间较长的接口。相较于脚本语言或阻塞式Web框架，C++后端更便于控制内存使用和请求处理细节，部署到个人服务器或资源有限的私有环境时也更有余量。系统的数据部分使用MySQL保存关系型元数据，使用Redis保存令牌和限流等短时状态，文件内容落在本地内容寻址目录中，依赖关系相对简单。

基于上述考虑，本文围绕一个私有化网络磁盘系统展开设计与实现，内容包括需求分析、总体结构、数据库设计、详细设计、功能实现和测试验证。本课题一方面用于验证Drogon、MySQL和Redis等技术在中小型文件服务系统中的适用性，另一方面也完成了一次从需求抽象、接口设计到客户端交互实现的完整实践。相关实现可以为私有化存储平台和C++文件服务后端开发提供一定参考。

## 第1章 绪论

### 1.1研究背景

近几年，移动互联网和个人数字内容持续增长，在线存储服务的使用频率也随之提高。云存储技术让文件不再固定在某一台设备上，用户可以通过网络访问和管理资料，这确实提高了个人和团队协作的便利性。但公有云网盘并不是所有场景下的最佳选择：文件存放在第三方服务器上，隐私和商业资料保护存在不确定性；免费套餐通常限制容量和传输速度，高级功能需要持续付费；服务商一旦调整策略、停止服务或发生安全事故，用户对数据和服务可用性的控制能力较弱。对部分有合规要求的机构或团队来说，数据必须保存在自主可控的基础设施中，公有云网盘也就难以满足要求。

私有化自建网盘因此有了实际使用空间。与公有云网盘相比，私有化网盘把文件实体和元数据保存在用户自己的服务器上，数据存放位置和访问策略更容易掌握；存储空间和网络带宽也可以按自身条件配置，不必完全受第三方平台套餐限制。这类方案更适合个人开发者、高校师生和中小型团队使用。不过，做一个功能完整、运行稳定、部署方便的网盘并不容易。传统脚本语言或解释型语言的Web框架在高并发文件传输场景下，可能出现吞吐量不足或CPU占用偏高的问题。针对这些问题，本文采用C++语言配合Drogon Web框架，实现一个适合私有化部署的网络磁盘系统，并以此验证相关技术路线的可行性。

### 1.2研究意义

本课题面向私有化网络磁盘的实际业务场景，设计并实现一个功能较完整的网盘服务系统。系统把用户文件管理、目录组织、大文件上传、文件分享和管理员后台等业务统一纳入后端服务，并利用C++与Drogon的高性能I/O处理能力，为私有化文件存储平台提供可验证的工程方案。

从实际应用看，本系统可以为有私有化部署需求的个人开发者、高校师生和中小团队提供一套文件存储与管理工具。文件上传、目录整理、检索和分享都集中在同一界面中完成，用户不需要在多个传输工具之间来回切换；系统也会记录存储配额和已用空间，便于用户了解资源占用情况。管理员则可以通过后台查看用户、分享和系统状态，处理账号管理和存储统计等日常运维工作。

从学习角度看，本课题涉及C++系统编程、异步网络I/O、Web框架、关系型数据库设计、缓存状态管理和RESTful API架构等多个方面，贯穿需求分析、系统设计、编码实现和测试验证整个流程。完成该系统有助于理解Drogon框架的工作机制、MySQL数据库的设计原则和RESTful接口规范，也能在模块划分、接口设计和异常处理等方面积累C++工程经验。

### 1.3国内外研究现状

云存储与网络磁盘相关技术已经有较多研究和工程实践，但面向高性能C++框架的私有化网盘实现仍然不多，公开资料也相对有限。

在国外，云存储领域的学术研究起步较早，分布式文件系统、对象存储架构和数据去重技术等方向已有大量成熟论文与工程案例。Google文件系统（GFS）、Amazon S3以及OpenStack Swift等系统在架构层面为大规模云存储提供了经典范式，但这些系统的设计目标是面向数据中心级别的水平扩展，对于资源受限的单机私有化部署而言过于复杂，部署和维护成本极高。在开源网盘领域，Nextcloud和ownCloud是比较具有代表性的PHP实现，功能丰富但对服务器配置要求较高，性能也受限于PHP的运行模型。SeaweedFS和MinIO则是基于Go语言实现的对象存储系统，在性能和部署便捷性上有明显进步，但API面向对象存储协议设计，并不直接提供网盘形态的用户交互界面。

在国内，随着百度网盘、阿里云盘等公有云网盘产品的快速发展，相关技术研究也日益增多，重点集中在文件秒传、内容去重、传输加速和版权保护等方向。自建私有网盘的研究与实践则主要集中在基于Java Spring Boot、Python Django/Flask框架的Web应用开发上，面向教学或毕业设计目的的实现案例中，大多采用关系型数据库配合本地文件系统的存储方式，功能覆盖基本够用，但在高并发性能和资源占用方面仍有提升空间。基于C++ Web框架（尤其是Drogon）构建文件存储服务的研究与工程实践目前较少见，与本课题相关的开源项目也处于起步阶段，尚未形成成熟的设计范式和参考实现。

现有研究和实践已经为云存储架构设计、私有网盘开发提供了基础，但C++高性能框架在网盘场景中的工程化应用仍有探索空间。本文结合Drogon的异步高并发特性和私有化部署需求，给出一个可参考的设计与实现方案。

### 1.4本文的组织结构

本文围绕私有化网络磁盘系统的设计与实现展开，结合文件存储访问、大文件传输、目录树管理、分享链接控制和后台运维管理等需求，说明系统的需求分析、总体架构、数据库设计、模块设计与实现以及测试验证。课题目标是构建一个同时面向普通用户和管理员的网络磁盘服务平台，覆盖文件存储生命周期中的主要业务，并验证其部署可行性和可用性。

在功能设计上，系统主要面向普通用户文件管理和管理员运维管理两类需求。用户侧接口包括账号注册、登录、令牌刷新与登出，个人资料与存储空间统计，文件和目录的分页列表、搜索、详情、重命名、移动、复制、软删除，目录树与面包屑路径查询，文件上传（含断点续传、秒传去重和后台合并的分片上传机制）、文件下载（含Range断点下载）、文件外链分享、分享密码校验、分享内容浏览与下载，以及回收站列表、批量恢复、彻底删除和清空等功能。管理员侧接口包括用户账号查询、状态切换、角色变更、软删除、用户文件与存储查看、全局存储统计、分享列表与强制取消、系统概览和系统状态查询等功能。

在性能设计方面，系统主要依靠Drogon的异步非阻塞I/O和C++协程模型处理文件上传、下载等I/O密集型请求。上传任务和分片状态会写入数据库，客户端中断后可以继续补传缺失分片；文件内容哈希与引用计数用于秒传和去重，避免相同内容重复落盘；Redis负责保存短时状态、限流计数和登录失败次数，减少部分高频状态对MySQL的依赖。

在安全性设计上，系统通过登录认证、Access Token、Refresh Token轮换和JWT令牌鉴权区分不同角色的访问边界。普通用户只能访问自己名下的文件和目录，管理员接口另设角色鉴权，非管理员账号不能调用后台接口。用户密码使用Argon2id哈希后存储，登录失败计数和短时锁定机制用于降低暴力破解风险。文件分享通过分享短码、可选访问密码、短期分享访问令牌和有效期共同限制公开访问范围，失效或取消后的分享链接不再允许访问。

在可扩展性设计上，系统按低耦合方式划分认证、用户、文件、目录、分享、回收站、运维统计和操作日志等模块。控制器负责解析请求和转换响应，核心业务集中在服务层。存储层通过IFileStorage抽象隔离本地文件系统实现，后续可在尽量少改动业务接口的情况下扩展对象存储、文件版本历史、WebDAV接口和缩略图预览等功能。

## 第2章 相关技术分析

### 2.1 Drogon框架与C++23协程

Drogon是一个高性能HTTP Web应用框架，其底层网络库基于epoll（在macOS/FreeBSD下为kqueue）实现非阻塞I/O，采用异步请求处理模型，能够以较少的线程资源支撑高并发的HTTP请求处理，非常适合文件传输这类I/O密集型服务。本系统在项目实现中采用C++23标准，结合Drogon的HttpController、HttpCoroFilter和drogon::Task协程接口组织控制器、过滤器和服务层逻辑，并使用std::expected风格的Result<T>统一表达业务成功或失败，减少异常控制流对业务代码的侵入。

### 2.2 MySQL数据库

MySQL是一种广泛使用的关系型数据库管理系统，具有稳定性高、社区资料丰富、查询性能良好等特点，适合作为中小规模业务系统的持久化数据存储后端。本系统通过MySQL保存用户账号信息、文件内容哈希、文件元数据、目录树结构、上传任务、上传分片、回收站记录、分享记录、分享文件关联和操作日志等核心数据，并通过联合索引、全文索引和唯一约束支撑文件列表查询、目录树遍历、秒传查重、配额统计和分享访问等高频操作。

### 2.3 Redis缓存与状态管理

Redis是一种高性能内存键值数据库，适合保存短生命周期状态和计数器。本系统使用Redis保存Refresh Token、Access Token黑名单、登录失败计数、分享访问令牌、密码尝试次数和接口限流计数等数据，从而将高频、短时、易过期的状态从MySQL中剥离出来，提高鉴权、限流和安全控制逻辑的执行效率。

### 2.4 JWT身份鉴权机制

JWT（JSON Web Token）是一种基于JSON格式的开放标准（RFC 7519），用于在各方之间以紧凑、自包含的方式安全地传递身份认证信息。本系统在用户登录成功后签发Access Token与Refresh Token，普通业务请求通过Authorization: Bearer <token>携带访问令牌，令牌刷新和登出依赖Redis中保存的刷新令牌与黑名单状态实现轮换和失效控制；公开分享访问则使用独立的分享令牌并通过X-Share-Token请求头传递，避免将用户JWT暴露给未登录访客。

### 2.5 CMake构建工具与安全基础库

CMake是一种跨平台的构建系统生成工具，被Drogon生态所推荐使用。本系统通过CMakeLists.txt、CMakePresets.json和vcpkg manifest管理后端项目的编译依赖、构建预设和第三方库，简化了Linux与Windows环境下的编译、测试和部署流程。密码哈希方面，系统使用libsodium提供的Argon2id算法保存用户密码，避免明文密码或弱哈希方案带来的安全风险。

### 2.6 Qt框架与QML

Qt是跨平台C++应用程序开发框架，常用于桌面端和嵌入式界面开发。本系统桌面客户端基于Qt 6实现，网络请求部分使用Qt Network访问后端RESTful API，承担文件分片上传、断点下载和JSON数据解析等工作。界面层采用QML（Qt Modeling Language）配合Qt Quick Controls 2编写文件列表、目录导航、传输进度、分享管理和后台管理页面。在实现分工上，QML主要负责界面声明和状态绑定，C++侧保存网络请求与业务状态，两者通过属性绑定和信号槽机制连接，避免界面代码与通信逻辑过度耦合。

## 第3章 需求分析

### 3.1系统需求概述

在私有化网络磁盘系统建设前，需要先评估系统是否具备开发和应用基础。本文从技术可行性、经济可行性和操作可行性三个方面进行分析。结合课题目标和所选技术栈的成熟度，系统具备实施条件。

从技术可行性看，C++23、Drogon、MySQL和Redis都能满足本课题的实现需要。Drogon提供HTTP路由、过滤器、控制器、协程任务、异步数据库访问和配置文件管理等能力，后端主体功能不需要从零搭建；MySQL适合保存用户、文件、目录、分享和日志等结构化数据；Redis适合处理令牌、限流、登录失败计数这类生命周期较短的状态。C++23中的协程、std::expected和std::filesystem，也能分别用于异步流程、错误返回和文件路径处理。JWT鉴权、Argon2id密码哈希以及CMake/vcpkg构建体系已有成熟库可用，技术路线具备实施基础。

从经济可行性看，本系统依赖的软件工具和运行环境均可使用开源免费版本，包括Drogon、MySQL社区版、CMake、GCC/Clang以及常用Linux系统工具，开发成本较低。系统对硬件要求不高，在普通个人计算机或低配云服务器上即可编译和运行。对于毕业设计课题而言，所需软硬件资源可以在个人环境中准备，经济层面不存在明显障碍。

从操作可行性看，系统面向普通用户和管理员两类主要账号角色设计，并为未登录访客提供受限分享访问流程。后端接口围绕账号认证、个人资料、文件上传下载、目录管理、分享、回收站、日志和运维统计等操作展开，接口路径清晰，参数和响应格式统一。桌面客户端通过RESTful API接入后端，管理员可通过受保护的管理接口完成用户、分享、存储和系统状态管理。权限校验、错误响应和业务状态由后端统一封装，后续二次开发按接口规范调用即可，操作复杂度可控。

### 3.2系统功能需求分析

私有化网络磁盘系统的需求主要来自两类角色：普通用户需要在线存储、管理和共享文件，管理员需要统一管理平台用户、存储资源和系统参数。结合实际业务场景，系统需求可分为功能需求和非功能需求两部分。

#### 3.2.1账号与用户模块需求分析

账号与用户模块需要为普通用户提供注册、登录、令牌刷新、登出、个人资料查询与更新、密码修改和存储空间查看等基础能力。系统应在注册阶段校验用户名和邮箱唯一性，在登录阶段校验账号状态、密码正确性和失败次数，并在认证成功后签发Access Token与Refresh Token，以支持后续业务接口鉴权和登录态续期。用户中心还需要展示已用空间、预占用空间、剩余配额、文件数和目录数，使用户能够清晰了解个人存储资源使用情况。

管理员侧需要在账号维度提供用户列表查询、关键字与状态筛选、用户详情查看、用户存储使用量查询、可用空间调整、账号禁用或启用、角色变更和软删除等功能。所有管理员操作均应建立在普通JWT鉴权和管理员角色鉴权之上，防止普通用户越权访问后台运维接口。

#### 3.2.2文件与目录模块需求分析

文件模块需要覆盖文件从上传、访问、组织到删除的完整生命周期。系统应支持文件和目录的混合分页列表展示、按名称搜索、文件详情查询、文件重命名、批量移动、批量复制和软删除；对于文件下载，需要支持普通完整下载和HTTP Range断点下载，以便客户端在网络不稳定场景下恢复下载进度。

上传功能是文件模块的核心需求。系统需要支持初始化上传、上传分片、完成合并和取消上传四个阶段，并通过上传任务与分片状态记录实现断点续传；当服务器已经存在相同内容文件时，应能够基于内容哈希完成秒传，避免重复上传和重复存储。目录模块需要支持多级目录创建、目录树查询和面包屑路径查询，并保证同一用户同一父目录下的目录名称不重复。

#### 3.2.3分享、回收站与管理模块需求分析

分享模块需要支持用户为文件或目录生成外链分享，并能够设置有效期、访问密码和查看或下载权限。未登录访客访问分享时，系统应先校验分享短码、分享状态、有效期和访问密码，校验成功后再签发短期分享访问令牌；访客浏览分享内容或下载分享文件时，需要通过独立的分享令牌完成鉴权，避免公开访问流程与登录用户JWT混用。

回收站模块需要支持误删除恢复场景。用户删除文件或目录时，系统应先将项目移动到回收站，保留原路径、原所属目录、项目类型、内容引用和恢复所需数据；用户可以查看回收站列表，执行批量恢复、彻底删除或清空回收站。管理员与运维模块则需要提供全局存储统计、分享记录查看、违规分享强制取消、系统概览、数据库状态、Redis状态和磁盘空间状态查询等能力。

#### 3.2.4系统用例分析

本系统主要涉及普通用户和管理员两个账号角色，并包含未登录访客访问分享的公开场景。普通用户通过用户端完成注册登录、文件上传与下载、目录管理、文件分享等操作；访客通过分享短码、访问密码和分享令牌浏览或下载授权内容；管理员通过后台完成用户管理、存储统计查看和系统参数配置等操作。

普通用户的核心用例主要包括：账号注册、账号登录、刷新令牌、登出、查看和更新个人资料、修改密码、查看存储空间、初始化上传、上传分片、完成上传、取消上传、下载文件、查看文件列表、搜索文件或目录、创建目录、查看目录树、查看面包屑路径、重命名文件或目录、移动或复制文件和目录、删除到回收站、查看回收站、恢复回收站项目、彻底删除回收站项目、生成分享链接、查看我的分享、更新或取消分享、通过分享密码访问分享、浏览分享内容、下载分享文件以及保存分享内容到个人网盘；管理员的核心用例则包括：管理员登录、查看全部用户列表、查看用户详情、禁用或启用用户账号、修改用户角色、调整用户可用空间、软删除用户、查看全平台存储统计、查看分享列表、查看分享详情、强制取消分享、查看操作日志、查看系统概览以及查看系统状态。

### 3.3系统非功能需求分析

#### 3.3.1系统性能需求分析

系统需要能够在单机私有化部署环境下稳定运行，利用Drogon框架的异步I/O能力提升文件传输吞吐量。对于文件列表、目录导航、存储配额查询等元数据请求，后端应在较短时间内完成响应；对于文件上传和下载操作，系统应利用流式处理机制避免将大文件全量加载入内存，减少内存峰值占用。上传任务和分片状态需要具备持久化能力，以便在客户端网络中断后继续上传缺失分片。

#### 3.3.2系统安全性与可维护性需求分析

系统需要对不同用户的文件资源严格隔离，普通用户只能访问自己名下的文件和目录，不能通过接口越权访问或下载他人文件；管理员接口需要单独鉴权，普通用户令牌无法访问管理员功能。文件分享链接需要使用随机短码、可选访问密码、有效期和短期分享访问令牌共同控制公开访问范围。用户密码必须经过安全哈希后存储，不得以明文形式保存在数据库中。

在可维护性方面，后端代码需要按认证、用户、文件、目录、分享、回收站、管理员、日志和系统状态等功能模块清晰划分。控制器只负责解析请求和转换响应，核心业务集中在服务层实现；数据库表结构应做到字段含义清晰、约束合理，方便后期维护和Schema演进。

#### 3.3.3数据字典

本系统涉及的核心数据对象主要包括用户信息、文件内容、文件元数据、目录信息、上传任务、上传分片、回收站记录、分享记录、分享文件关联和操作日志等，以下分别对主要数据对象的字段组成和含义进行说明。

用户信息（users）是整个系统的基础数据对象，主要用于保存用户的账号凭据、个人资料、登录安全状态和存储配额信息，是登录鉴权、文件归属判断和存储限额控制的核心依据。其主要字段包括用户主键ID、用户名、邮箱、哈希后的密码、昵称、头像、存储配额、已用存储、上传预占用存储、账号状态、角色类型、登录失败次数、锁定截止时间、最后登录时间、最后登录IP、创建时间和更新时间。

文件内容（file_contents）用于保存物理文件内容的索引信息，是秒传去重和内容寻址存储的基础。其主要字段包括内容主键ID、MD5哈希、SHA256哈希、文件大小、实际存储路径、MIME类型、引用计数和创建时间。多个用户文件记录可以引用同一个内容对象，从而避免相同内容被重复存储。

文件元数据（files）是文件管理功能的核心数据对象，用于保存每一个用户可见文件的描述性信息，而不直接存储文件二进制内容。其主要字段包括文件主键ID、所属用户ID、关联的内容ID、所属文件夹ID、文件名、扩展名、文件大小、MIME类型、完整路径、收藏标记、下载次数、最后访问时间、创建时间和更新时间。

目录信息（folders）用于维护用户的目录树结构，是目录导航和文件路径组织的基础数据表。其主要字段包括目录主键ID、所属用户ID、父目录ID（根目录以0表示）、目录名称、完整路径、目录深度、子项数量、创建时间和更新时间。通过父目录ID字段形成的递归引用关系，可以构建出任意层级深度的目录树结构。

上传任务（upload_tasks）用于支持大文件分片上传和断点续传机制，保存每个进行中、已完成、已取消或已过期上传任务的总体状态。其主要字段包括上传任务ID、用户ID、目标文件夹ID、文件名、文件大小、文件MD5、分片大小、总分片数、预占用字节数、临时存储路径、任务状态、过期时间、完成时间、失败原因、创建时间和更新时间。上传分片（upload_task_chunks）则以任务ID和分片索引作为联合主键，记录每个分片是否已经上传成功。

回收站记录（trash）用于保存软删除文件或目录的恢复信息。其主要字段包括回收站记录ID、用户ID、项目类型、原项目ID、项目名称、项目大小、关联内容ID、原所属文件夹ID、原完整路径、项目完整数据备份、删除时间和过期时间。通过回收站表，系统可以在彻底删除之前恢复误删项目，也可以在过期清理时减少内容引用计数并释放物理存储。

分享记录（shares）用于保存用户发起的分享操作的基础信息，是外链分享功能的数据基础。其主要字段包括分享ID、分享短码、分享者用户ID、访问密码哈希、权限类型、访问次数、下载次数、分享状态、过期时间、创建时间和更新时间。分享文件关联（share_files）用于描述某个分享包含的文件或目录，主要字段包括关联记录ID、分享ID、项目类型、项目ID和创建时间。该设计使一个分享可以关联一个或多个文件或目录，并支持后续扩展分享目录浏览能力。

操作日志（operation_logs）保存上传、下载、删除、分享等关键动作的记录。表中字段包括日志ID、用户ID、操作类型、目标类型、目标ID、目标名称、操作详情、IP地址、客户端信息和创建时间。当出现异常下载、误删文件或分享访问问题时，管理员可以先从这些记录中确认操作对象和发生时间。

上述对象基本覆盖了系统运行时需要保存的业务数据，后续数据库设计和服务层逻辑也围绕这些对象展开。

## 第4章 系统设计

### 4.1系统架构设计

本系统采用RESTful后端服务与桌面客户端分离的架构，将客户端展示与后端业务能力解耦。后端通过标准化HTTP接口暴露认证、文件、目录、分享、回收站、日志和管理能力；桌面端基于Qt/QML实现普通用户、访客和管理员界面，并通过统一网络层调用后端接口。这样可以保持接口契约清晰，便于后期维护、测试和功能扩展。

系统整体由客户端接入层、过滤器层、控制器层、服务层和数据存储层组成。客户端接入层通过RESTful HTTP请求调用系统能力；过滤器层基于Drogon全局过滤器完成JWT鉴权、管理员鉴权、分享令牌鉴权和接口限流；控制器层负责解析请求并返回统一响应；服务层划分为认证、用户、文件、目录、分享、回收站、管理员、日志、健康检查和系统信息等模块，集中处理业务逻辑；数据存储层由MySQL、Redis和本地文件系统组成，其中MySQL保存结构化业务数据，Redis保存刷新令牌、黑名单、登录失败计数、分享访问状态和限流计数，本地文件系统按内容哈希保存物理文件对象。

### 4.2系统模块设计

系统按角色划分为普通用户端和管理员端两大模块，并包含访客分享访问页面。普通用户端包含账号管理、用户中心、文件管理、目录管理、分享管理、回收站管理和存储空间查看七个子模块。账号管理包括注册、登录、刷新令牌和登出；文件管理支持分片上传（初始化、上传分片、完成合并、取消上传）、秒传去重、下载、重命名、移动、复制、删除和搜索；目录管理提供创建目录、目录树和面包屑路径查询；分享管理覆盖生成分享链接、访问密码、有效期、查看/下载权限、我的分享、取消分享、浏览和下载分享文件以及保存分享内容；回收站管理包括回收站列表、批量恢复和彻底删除/清空。管理员端包含用户管理、存储统计、分享管理、操作日志和系统状态等子模块。用户管理支持查看用户列表、搜索用户、查看用户详情、禁用或启用账号、修改角色、调整用户可用空间和软删除用户；存储统计提供全平台统计和各用户占用排行；分享管理支持查看分享列表、分享详情和强制取消分享；系统状态包括系统概览以及数据库、Redis和磁盘的运行状态。图4-1和图4-2分别展示普通用户端和管理员端的功能结构。

### 4.3系统功能设计

#### 4.3.1用户认证模块设计

用户认证模块是整个系统的安全基础，主要负责用户注册、登录、令牌刷新、登出和接口鉴权。用户注册时，后端校验用户名和邮箱唯一性，使用libsodium的Argon2id算法生成密码哈希，并在users表中写入默认存储配额。用户登录时，后端校验账号状态、锁定时间和密码哈希；登录成功后签发Access Token与Refresh Token，并将刷新令牌写入Redis。登录失败时系统会累计失败次数，达到阈值后短时锁定账号，从而降低暴力破解风险。

JWT过滤器是认证模块与各业务控制器之间的桥梁。需要登录的接口统一通过Authorization: Bearer <access_token>携带访问令牌，过滤器负责验证签名、过期时间和黑名单状态，并将用户ID、用户名和角色等上下文写入请求对象。管理员接口在JWT校验之后还会经过管理员鉴权过滤器，只有角色为管理员的账号才能继续访问。Refresh Token采用Redis存储和轮换机制，登出时会使访问令牌进入黑名单并删除刷新令牌，实现较完整的登录态生命周期管理。

#### 4.3.2文件与目录模块设计

（1）文件管理模块

文件管理模块是普通用户最核心的业务模块，围绕文件列表、搜索、上传、下载、重命名、移动、复制和删除等操作展开设计。后端通过FileController暴露/api/file/* 系列接口，控制器仅负责解析请求和转换响应，具体业务由FileService完成。

在文件列表展示方面，系统根据当前用户ID、目录ID、类型筛选、排序字段和分页参数，从files与folders表中查询当前目录下的文件和文件夹，并以统一DTO返回给客户端。搜索功能通过文件名和目录名索引支持按关键词、类型和目录范围检索。文件详情接口会返回文件或目录元数据及面包屑路径，便于客户端构建导航视图。

在文件变更方面，重命名会校验名称长度、非法字符、保留名称以及同目录冲突；移动和复制支持批量操作，其中复制文件时不会重复写入物理文件，而是复用file_contents中的内容对象并增加引用计数。删除操作采用回收站机制：普通删除会将文件或目录的恢复信息写入trash表，并从正常文件或目录列表中移除；彻底删除时才会减少内容引用计数，引用计数归零后再清理物理文件。

（2）目录管理模块

目录管理模块负责维护用户的多级目录树结构。系统通过folders表保存目录名称、父目录ID、完整路径、深度和子项数量，其中根目录以parent_id = 0表示。创建目录时，后端校验目标父目录是否属于当前用户，并通过(user_id, parent_id, name)唯一约束保证同级目录名称不重复。

目录树接口通过递归查询返回当前用户的目录层级结构，面包屑接口返回从根目录到指定目录的路径链路。为了避免异常数据导致无限递归，服务层会限制目录树深度并在面包屑构建过程中检测循环引用。目录删除不直接丢弃数据，而是进入回收站流程，保留恢复所需的原始路径和项目数据。

图4-4创建目录流程图

![图4-4创建目录流程图](assets/创建目录流程图.png)

（3）文件上传模块

文件上传模块是整个系统中技术实现复杂度最高的部分。当前系统采用统一的分片上传流程，默认分片大小为5MB，并支持初始化上传、上传分片、完成合并和取消上传四个阶段。上传初始化请求会携带文件名、文件大小、目标目录、文件MD5等信息，后端首先进行配额预检查，并根据MD5查询file_contents表。如果相同内容已经存在，系统无需再次上传物理文件，只需要创建新的files记录并增加内容引用计数，即可完成秒传。

如果文件内容不存在，系统会创建upload_tasks记录并预占用用户存储空间。客户端随后按分片索引上传数据，后端将分片写入临时目录，并在upload_task_chunks表中记录已上传分片。断点续传的关键在于初始化接口会返回已上传分片列表，客户端恢复上传时只需补传缺失分片。所有分片完成后，后端通过AssemblyWorkerPool控制并发合并，将临时分片按顺序合并为完整文件，计算并校验内容哈希，随后写入file_contents和files表，释放预占用空间并将上传任务标记为完成。

#### 4.3.3分享模块设计

文件分享模块允许用户将自己的文件或目录通过外链方式分享给他人。创建分享时，后端在shares表中写入分享短码、分享者ID、可选访问密码哈希、权限类型、有效期和状态，并在share_files表中写入被分享的文件或目录关联。分享权限支持查看和下载两类，分享状态支持有效、取消和过期。

公开访问分享时，访客首先通过分享短码和可选密码调用访问接口。后端校验分享是否存在、是否过期、是否取消以及密码是否正确；校验通过后签发短期分享访问令牌。后续浏览分享目录或下载分享文件时，访客需要在X-Share-Token请求头中携带该令牌，由分享鉴权过滤器完成校验。系统会分别记录浏览次数和下载次数，并使用Redis对分享密码尝试进行限流，避免暴力猜测分享密码。

（1）回收站模块

回收站模块用于降低误删除风险。普通删除操作不会立即物理删除文件，而是将项目类型、原项目ID、原路径、项目名称、内容ID和完整数据备份写入trash表。用户可以分页查看回收站项目，也可以批量恢复、彻底删除或清空回收站。恢复时，如果原目录不存在，系统会回退到根目录；如果名称发生冲突，系统会自动生成新的名称以避免覆盖现有文件。系统还通过定时清理任务删除过期回收站记录和过期上传任务，保证长期运行时临时数据不会无限累积。

#### 4.3.4管理员与运维模块设计

（1）用户管理模块

管理员用户管理模块通过/api/admin/users系列接口提供平台账号维护能力。管理员可以查看用户列表、按条件筛选用户、查看用户详情和存储使用情况，也可以修改用户状态、修改角色、调整用户可用空间或软删除用户。用户状态在数据库中以数值表示，包括禁用、正常和锁定；角色也以数值表示，包括普通用户和管理员。所有管理员接口都需要同时通过JWT鉴权和管理员角色鉴权。

（2）存储统计与分享管理模块

存储统计模块通过聚合users、files、file_contents、folders等表，统计全平台用户数、文件数、内容对象数、存储占用和各用户使用情况。由于系统采用内容寻址和引用计数，逻辑文件大小与物理内容占用并不总是完全一致，因此统计时需要区分用户视角的文件大小和物理内容对象的实际存储。

分享管理模块允许管理员查看全平台分享列表、查看单个分享详情并强制取消违规分享。该功能主要用于处理公开链接滥用、误分享和过期分享治理等场景，能够与分享状态、访问次数和下载次数统计结合，为平台安全运维提供依据。

（3）系统状态与日志模块

系统状态模块主要面向部署和维护场景，页面中展示服务运行时间、版本信息、数据库连接、Redis连接和磁盘空间等指标；公开健康检查接口用于判断服务是否存活。操作日志模块把上传、下载、删除、分享等动作按分页形式提供给管理员。当出现异常请求或用户反馈问题时，管理员可以结合状态指标和日志记录缩小排查范围。

## 第5章 系统实现

本章结合项目的实际代码，从后端RESTful服务和Qt/QML桌面客户端两个层面说明系统功能的实现方式。后端按控制器、过滤器、服务层、数据模型和存储抽象组织代码：控制器负责路由绑定、参数解析和响应转换，服务层处理业务规则、数据库事务和Redis状态。桌面端通过AuthShell、OwnerShell、VisitorShell和AdminShell区分认证、普通用户、访客分享和管理员场景，各页面再通过对应Manager调用后端接口。

### 5.1用户与认证模块功能实现

（1）注册与登录实现

账号注册和登录接口由AuthController提供，具体业务由AuthService完成。注册时，后端接收用户名、邮箱和密码等字段，先通过DTO校验格式，再查询users表确认用户名和邮箱未被占用。校验通过后，服务层使用libsodium提供的Argon2id算法生成密码哈希，并写入默认昵称、头像、存储配额、账号状态和角色等基础字段。桌面端对应RegisterPage页面，注册成功后提示用户返回登录页。

登录接口支持用户名或邮箱两种方式。服务层读取用户账号状态、锁定截止时间和密码哈希后进行判断：账号被禁用或仍在锁定期内时直接拒绝登录；密码错误时累计失败次数，达到阈值后设置短时锁定；认证成功时重置失败计数，签发Access Token与Refresh Token，并返回用户ID、用户名、昵称和角色等会话信息。桌面端LoginPage通过AuthService发起请求，SessionStore保存登录态，ShellController再根据角色切换到普通用户界面或管理员界面。

（2）令牌生命周期与鉴权过滤

令牌相关逻辑集中在TokenService中。Access Token采用JWT格式，携带用户ID、用户名、角色和过期时间等声明；普通业务接口统一通过JwtAuthFilter校验Authorization: Bearer <token>请求头。Refresh Token保存在Redis中，用于续期访问令牌。刷新成功后，旧Refresh Token被替换，新的Access Token和Refresh Token返回客户端。用户登出时，系统删除Redis中的刷新令牌，并把当前访问令牌加入黑名单，使其在自然过期前也不能继续访问受保护接口。

不同访问边界使用不同过滤器。管理员接口在JWT校验后还要经过AdminAuthFilter，只有管理员角色可以访问/api/admin/* 路由；公开分享的浏览和下载接口使用ShareAuthFilter校验X-Share-Token，避免访客流程与登录用户JWT混在一起。桌面端网络层通过RequestFactory按请求类型附加用户令牌、分享令牌或两者组合，使客户端请求的认证上下文更清楚。

（3）个人资料、密码与存储空间实现

用户中心由UserController和UserService实现，主要包括个人资料查询、资料更新、密码修改和存储空间查看。资料更新接口支持修改昵称和头像URL，服务层只更新请求中实际传入的字段，并同步更新时间。密码修改接口要求用户提交当前密码，校验通过后重新生成Argon2id哈希并更新users.password_hash，避免明文密码出现在客户端或数据库中。

存储空间接口读取users表中的storage_quota、storage_used和storage_reserved字段，并结合文件数、目录数等统计信息，返回已用空间、预占用空间、剩余配额和资源数量。桌面端SettingsPage和ProfileManager负责加载这些数据，用户修改资料或密码后，页面会根据接口返回结果给出成功或失败提示。

### 5.2文件传输模块功能实现

（1）分片上传初始化与秒传判断

文件上传由FileController提供初始化、上传分片、完成上传和取消上传接口，主要路径包括/api/file/upload/init、/api/file/upload/chunk和/api/file/upload/complete等。控制器继承Drogon的HttpController，通过METHOD_LIST_BEGIN和ADD_METHOD_TO绑定路由、HTTP方法和过滤器，上传相关接口统一接入JWT鉴权和上传限流过滤器。各处理函数返回drogon::Task<drogon::HttpResponsePtr>，控制器通过co_await调用服务层异步逻辑，等待数据库或文件状态处理时不会长时间占用请求线程。

客户端选择文件后，TransferManager先提交文件名、文件大小、目标目录和文件MD5。FileService根据当前用户的已用空间和预占用空间检查配额，如果上传后会超过配额上限，初始化阶段就返回空间不足错误，不再接收后续分片。

初始化阶段还会根据文件哈希查询file_contents表。如果系统中已经存在相同内容对象，服务层不要求客户端继续上传分片，而是直接创建新的files元数据记录，增加内容对象引用计数，并返回秒传结果。若内容不存在，则创建upload_tasks记录，写入任务ID、目标目录、文件名、文件大小、分片大小、总分片数、临时路径、预占用字节数和过期时间，并查询upload_task_chunks表返回已上传分片列表，为断点续传提供依据。

（2）分片写入、断点续传与后台合并

分片上传接口按任务ID和分片索引接收二进制数据。Drogon把HTTP请求体封装在HttpRequest对象中，控制器可以直接通过request->body()取得application/octet-stream形式的分片内容，减少接口层的JSON编解码开销。服务层先校验上传任务是否属于当前用户、状态是否仍为进行中，再把分片写入任务临时目录，并在upload_task_chunks表中记录该分片已完成。

上传过程被拆成固定大小的分片后，单次请求只处理有限数据量，可以降低大文件一次性进入服务端造成的内存峰值。Drogon基于事件循环的非阻塞网络模型，也便于同时处理多个用户或多个分片请求。客户端恢复上传时重新调用初始化接口即可获得已上传分片索引，只补传缺失部分，从而完成断点续传。

所有分片上传完成后，客户端调用完成上传接口。后端通过AssemblyWorkerPool控制同一上传任务的合并并发，避免同一任务被重复合并。合并过程按分片顺序读取临时文件，生成完整文件后计算MD5和SHA256，并与初始化阶段提交的哈希比对。校验通过后，系统通过IFileStorage的本地实现把文件移动到内容寻址存储路径，写入file_contents和files表，释放预占用空间并更新用户已用空间。用户取消上传或任务过期时，系统会删除临时分片、更新任务状态并释放预占用空间；CleanupService和定时任务负责后续清理。

（3）文件下载与Range断点下载

文件下载分为下载信息查询和实际文件流下载。客户端下载前可以先获取文件名、大小和MIME类型等元数据，再调用下载接口获取文件内容。服务层会校验文件归属，确认当前用户只能下载自己名下的文件；校验通过后，通过IFileStorage定位内容寻址文件，并由DownloadResponder构造HTTP下载响应。

下载响应使用Drogon的HttpResponse::newStreamResponse实现流式返回。回调函数按照固定大小从文件流中逐块读取数据并写入响应缓冲区，而不是把完整文件一次性加载到内存。这样可以降低大文件下载时的内存占用，也让服务端在网络发送过程中继续处理其他连接。

当请求头包含Range字段时，后端解析起止字节位置，只返回指定区间的内容，并设置206 Partial Content、Content-Range、Accept-Ranges和Content-Length等响应信息；当请求范围超出文件大小时，系统返回416 Requested Range Not Satisfiable，并在响应头中给出当前文件长度。普通下载、断点续传下载和非法Range响应都复用同一套流式响应构造逻辑。桌面端下载任务由TransferManager和DownloadTaskModel管理，传输中心展示下载进度、状态和失败原因，并支持取消、重试以及基于Range的暂停后继续下载。

（4）传输中心实现

桌面端通过TransferCenterPage集中展示上传和下载任务。上传任务模型记录文件名、目标目录、已上传字节数、总字节数、状态和错误信息；下载任务模型记录保存路径、下载进度、暂停状态和完成状态。用户可以在传输中心查看正在进行和已经完成的任务，也可以执行取消、重试、暂停、继续和清理已完成任务等操作。文件传输从文件列表页面中独立出来后，用户在长时间上传或下载过程中仍能继续浏览目录和管理文件。

图5-4为传输中心页面，页面包含上传任务列表、下载任务列表、传输进度、任务状态和操作按钮。TransferCenterPage集中展示TransferManager维护的任务模型，上传任务记录文件名、目标目录、总大小、已传输大小和错误信息，下载任务记录保存路径、Range续传状态和完成情况。用户可以在该页面处理传输任务，而不必停留在文件列表页等待任务完成。

### 5.3文件与目录管理模块功能实现

（1）文件列表与资源管理器实现

### 5.4回收站模块功能实现

回收站功能由TrashController和TrashService实现，后端提供回收站列表、批量恢复、批量彻底删除和清空回收站接口。普通删除不会立即释放存储空间，而是把项目类型、原项目ID、项目名称、原目录、原路径、大小、内容引用和必要的JSON备份写入trash表，并从正常文件或目录列表中移除。桌面端DriveTrashView展示回收站记录，用户可以多选项目进行恢复或彻底删除，也可以一次性清空回收站。

图5-8 回收站管理功能截图

![图5-8 回收站管理功能截图](assets/回收站管理功能截图.png)

图5-8为回收站页面，页面包含已删除项目列表、恢复按钮、彻底删除按钮和清空回收站入口。用户删除文件或目录后，TrashService将项目类型、原项目ID、原路径、名称、大小和必要的JSON备份写入trash表，并从正常列表中移除。DriveTrashView负责展示这些记录，用户可以选择单个或多个项目进行恢复、彻底删除，或清空当前账号的回收站数据。

恢复操作会先校验回收站记录是否属于当前用户。系统优先恢复到原父目录；如果原父目录已经不存在，则恢复到根目录；如果目标目录中存在同名文件或目录，服务层会自动生成name (n).ext或name (n)形式的新名称，避免覆盖现有数据。当前实现中，文件夹恢复只恢复文件夹记录本身，不递归恢复文件夹子树，这与服务层V1规则保持一致。

彻底删除会永久移除回收站记录，并根据文件内容引用计数决定是否删除物理文件。对于文件项目，服务层减少file_contents.ref_count，引用计数归零后再通过IFileStorage删除本地内容寻址文件，并更新用户已用空间。清空回收站时，系统会批量处理当前用户的所有回收站记录并汇总释放空间。后台清理服务还会定期处理过期回收站记录，防止临时数据和删除数据长期累积。

（1）分享创建与所有者管理

（2）访客访问、浏览与下载实现

访客访问分享时，首先通过分享短码进入VisitorShell，桌面端ShareVerifyPage显示访问校验界面。后端公开访问接口查询shares表，检查分享是否存在、是否过期、是否已取消以及密码是否正确。对于设置密码的分享，Redis会记录密码尝试次数并进行限流，以降低暴力猜测风险。校验通过后，系统签发短期Share Token，访客后续请求通过X-Share-Token请求头访问。

分享浏览接口由ShareAuthFilter校验令牌后返回分享中的文件和目录列表，并更新浏览次数。分享下载接口会再次检查分享状态和权限类型，只有权限允许下载时才通过本地内容寻址存储返回文件流，并增加下载次数。桌面端ShareBrowsePage展示访客可见内容，支持浏览分享目录和下载允许下载的文件；权限不足或分享失效时，客户端根据后端错误响应给出提示。

（3）保存分享内容到个人网盘

项目还实现了分享内容保存到个人网盘的接口/api/share/save/{share_id}。该接口同时经过JwtAuthFilter和ShareAuthFilter，要求调用者既是已登录用户，又已通过该分享的访问校验。保存时，服务层根据分享中的文件或目录关联，为当前用户创建自己的文件记录或目录记录。对于文件内容，系统继续复用file_contents内容对象并维护引用计数，不重复写入物理文件。这样，访客在获得分享授权后可以把文件保存到个人网盘，同时仍受用户配额和权限边界约束。

### 5.6管理后台与运维模块功能实现

（1）管理员用户管理实现

### 6.1系统测试方法

（1）测试目的

系统测试用于验证网络磁盘系统各功能模块是否满足需求分析阶段提出的业务要求，并检查用户认证、令牌刷新、文件上传与下载、目录管理、文件分享、回收站、存储配额控制、管理员接口、桌面端关键交互和系统状态查询等场景下的运行情况。测试结果可用于发现潜在缺陷，并为后续优化提供依据。

### 6.3系统性能测试

性能测试围绕文件列表查询、目录导航、上传初始化和文件下载等高频接口展开，主要观察单机部署条件下的接口响应时间、请求吞吐量和错误率。系统采用Drogon异步I/O、协程服务层和本地内容寻址存储，元数据查询与文件传输流程能够减少阻塞式等待；上传分片状态、令牌状态和限流计数分别由MySQL与Redis承担，也避免了单一存储组件压力过高。测试结果表明，在毕业设计演示和中小规模私有化部署场景下，系统能够保持稳定响应，未出现明显接口超时或服务异常。

### 6.4系统安全性测试

安全性测试重点验证JWT鉴权、管理员角色校验、用户资源归属校验、分享访问令牌和密码错误限制等机制。测试过程中，未登录访问受保护接口、普通用户访问管理员接口、用户尝试下载他人文件、访客使用错误或过期分享令牌等场景均被系统正确拦截；登出后的访问令牌也会因黑名单状态而失效。测试结果说明，系统在账号认证、文件访问隔离和公开分享控制方面能够满足第3章提出的安全性需求。

### 6.5测试总结

测试结果显示，系统核心业务流程运行稳定，普通用户、访客和管理员相关功能基本达到设计目标。用户认证与鉴权、令牌刷新与登出、文件上传（包含分片断点续传和秒传去重机制）、文件下载、目录管理、文件分享生成与访问控制、分享内容保存、回收站恢复与彻底删除，以及管理员的用户管理、分享管理、操作日志、存储统计和系统状态查询等功能，均通过功能性验证。

安全性测试中，用户访问他人文件、普通用户访问管理员接口、令牌过期、登出失效、登录失败锁定和分享密码错误等场景均能被正确拦截或处理，说明JWT鉴权、Redis状态管理和角色权限控制符合设计要求。存储配额限制在上传初始化阶段即可生效，能够避免超额写入和无效分片上传。

测试也暴露了一些不足。当前主要在本地单机环境进行测试，尚未覆盖大规模高并发场景，Drogon在真实高并发文件传输下的吞吐量和延迟仍缺少充分数据；系统虽有操作日志和健康检查，但监控告警、容量趋势分析和容灾恢复能力仍较基础；桌面端已覆盖登录、文件浏览、传输中心、分享访问、回收站和管理后台等主要页面，但拖拽上传、缩略图预览和文件在线预览等体验功能还没有完成。就毕业设计阶段而言，系统已经能够演示主要业务流程；若面向实际部署，还需要补充性能压测、监控运维和客户端体验方面的工作。

## 总结与展望

本文围绕私有化网络磁盘系统展开设计与实现，重点解决用户文件管理、大文件传输、分享链接控制、回收站恢复和管理员运维管理等问题。论文先分析系统需求，再完成总体架构、数据库结构、模块设计、功能实现和测试验证。系统后端采用C++23和Drogon Web框架，桌面端采用Qt 6和QML，数据存储层由MySQL、Redis和本地内容寻址文件系统组成，最终形成了普通用户、访客和管理员三类角色都可以使用的网盘系统。

功能实现方面，系统已经完成用户注册登录、Access Token与Refresh Token管理、JWT鉴权和管理员角色鉴权、个人资料与存储空间统计、多级目录树与面包屑路径、文件分片上传、断点续传、秒传去重、后台分片合并、文件下载与Range断点下载、文件重命名、移动、复制、搜索、回收站软删除与恢复、文件外链分享、分享密码访问、分享浏览与下载、分享内容保存、操作日志、健康检查和系统状态查询等功能。桌面端提供认证界面、网盘资源管理器、传输中心、访客分享访问页、个人设置页和管理员后台页面；管理员可以完成用户管理、角色与状态变更、用户可用空间调整、全局存储统计、操作日志查看、分享审核与强制取消等操作。文件上传和存储部分使用upload_tasks与upload_task_chunks保存分片状态，并通过file_contents内容哈希和引用计数实现秒传与去重。

测试结果显示，当前版本基本达到毕业设计预期。注册登录、文件传输、目录管理、分享访问控制、回收站恢复、权限边界和管理员操作等流程能够按设计运行，RESTful接口的数据交互也较为清晰。测试过程说明，本课题采用的技术路线可以支撑中小规模私有化网盘系统的实现，Drogon框架也适合承担文件服务类后端中的异步接口和传输处理任务。

受开发周期、测试环境和课题范围限制，系统还有不少可以继续完善的地方。文件版本历史、WebDAV协议支持、文件在线预览和缩略图生成尚未实现；高并发压力测试和安全渗透测试也不够充分，大规模并发文件传输时的吞吐量和稳定性仍需要更多实验数据支撑。系统目前已有操作日志、健康检查和系统状态接口，但监控告警、容量趋势分析、自动备份和容灾恢复机制还比较基础。后续如果继续完善，可以优先补充客户端体验功能，再围绕性能压测和运维治理做进一步工作。

本文完成了一个基于C++23、Drogon与Qt/QML的私有化网络磁盘系统，已具备文件存储类RESTful后端和桌面客户端的主要功能，后续可以继续接入对象存储，并在客户端体验和运维能力上做补充。
