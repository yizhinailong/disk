# 基于Drogon的网络磁盘系统的设计与实现

## 摘　要

学习、办公和项目开发会产生大量文档、图片、代码包和临时资料，文件分散后查找、备份和跨设备访问都不方便。公有云网盘虽然易用，但数据托管、容量、带宽和平台规则都受第三方限制。针对个人服务器和小型团队的数据自主管理需求，本文设计并实现了一套基于Drogon的私有化网络磁盘系统。

系统采用后端服务与桌面客户端分离的结构。后端使用C++23和Drogon处理接口、文件传输、认证鉴权和后台管理；桌面端使用Qt 6和QML编写界面，并通过RESTful API访问后端。MySQL保存用户、文件元数据、目录、上传任务、分享、回收站和操作日志等长期数据，Redis保存令牌、登录失败计数、分享访问状态和限流计数等短期状态，真实文件按内容哈希写入本地目录。系统面向普通用户、访客和管理员，完成了账号认证、文件管理、分片上传、断点续传、秒传、Range下载、外链分享、回收站和后台管理等功能。

运行和测试结果表明，系统已完成主要业务流程。普通用户可以在桌面端整理文件、处理传输任务并创建分享，管理员可以查看用户、分享、日志和系统状态。注册登录、文件传输、目录管理、分享访问和权限控制等测试结果与设计要求基本一致，Drogon协程和非阻塞I/O能够支撑系统正常运行。

关键词：网络磁盘；文件管理；Drogon；C++23；RESTful API

## ABSTRACT

Digital materials generated in study, work, and project collaboration are often scattered across devices, making management and cross-device access inconvenient. Public cloud drives are easy to use, but data hosting, capacity, bandwidth, and service rules depend on third-party platforms. To improve data controllability for personal servers and small teams, this thesis designs and implements a private network disk system based on Drogon.

The system separates the backend service from the desktop client. The backend uses C++23 and Drogon for APIs, file transfer, authentication, authorization, and management. The Qt 6/QML desktop client communicates with the backend through RESTful APIs. MySQL stores persistent data such as users, file metadata, directories, upload tasks, shares, trash records, and operation logs, while Redis stores tokens, login failure counters, share access states, and rate-limiting counters. File entities are stored locally by content hash. For regular users, visitors, and administrators, the system implements authentication, file management, chunked and resumable upload, instant deduplication, Range download, sharing, trash handling, and backend management.

Operation and test results show that the system has completed its main workflows. Regular users can manage files, transfer tasks, and shares, while administrators can view users, shares, logs, and system status. Registration, login, file transfer, directory management, share access, and permission control meet the design requirements, and Drogon's coroutine and non-blocking I/O mechanisms support normal operation.

KEYWORDS: Network Disk; File Management; Drogon; C++23; RESTful API

## 前　言

学习、办公和日常生活会产生大量数字资料，课程文档、项目代码、图片和视频都需要集中保存和访问。网络磁盘把文件存储与网络访问结合起来，比单纯依赖本地硬盘更方便，也适合团队共享。不过，公有云网盘存在数据托管、容量、带宽和平台规则限制。对希望掌握数据和部署环境的个人用户或小型团队来说，私有化网络磁盘仍有必要。

网络磁盘常用操作包括上传、下载、目录整理、搜索和分享。大文件传输容易受网络波动影响，因此需要断点续传；分享链接如果缺少有效期、访问密码和权限控制，也会带来安全和管理负担。

管理员日常维护也需要统一入口。账号数量、存储占用、数据库连接、Redis状态和磁盘空间如果分散查看，排查问题会比较费时。因此，本文在实现普通用户文件管理的同时，也加入后台管理、操作日志和系统状态查询。

后端采用C++23和Drogon，主要考虑上传、下载对磁盘和网络I/O依赖较重。Drogon底层通过epoll（macOS/FreeBSD下为kqueue）处理网络事件，并支持协程化请求，用于这类等待时间较长的接口较合适。系统用MySQL保存元数据，Redis保存令牌和限流等短时状态，文件实体放在本地内容寻址目录中。

本文按照需求分析、系统设计、数据库设计、功能实现和测试验证的顺序展开。课题面向中小型私有化文件服务场景，验证Drogon、MySQL和Redis组合完成网络磁盘业务流程的可行性。

## 第1章 绪论

### 1.1研究背景

近几年，个人数字内容增长较快，在线存储也更常见。云存储让文件不再固定在某台设备中，联网后即可访问资料，方便了个人整理和团队协作。但公有云盘仍有局限：文件托管在第三方服务器上，隐私数据和商业资料保护存在不确定性；免费套餐常限制容量和速度，高级功能还需持续付费；服务商调整策略或停止服务时，用户也难以掌握主动权。对有合规要求的机构和团队来说，数据通常需要留在自有基础设施内。

私有化自建网盘因此有现实需求。文件实体和元数据保存在自有服务器上，数据位置、访问策略、存储空间和带宽都可自行配置。不过，功能完整、运行稳定且部署负担较低的网盘系统并不容易实现。本文选择C++和Drogon Web框架实现该系统，主要验证这一路线在文件服务场景中的适用性。

### 1.2研究意义

本课题面向私有化网络磁盘场景，设计并实现一个文件服务系统。系统把文件管理、目录组织、大文件上传、文件分享和管理员后台整合到同一套后端服务中，并使用C++与Drogon承担文件传输和接口处理任务，是一个可部署、可运行、可测试的工程样例。

从使用对象看，系统主要面向个人开发者、高校师生和中小团队。文件上传、目录整理、检索和分享集中在同一客户端界面中，存储配额和已用空间也直接展示。管理员端提供账号管理、存储统计和系统状态入口，可减少日常维护对数据库客户端、Redis命令行和系统磁盘工具的依赖。

从工程实践角度看，本课题把C++系统编程、异步网络I/O、Web框架、关系型数据库、缓存状态和RESTful接口放到同一项目中使用。实现时需要处理认证、文件传输、目录结构、权限边界和桌面客户端交互之间的配合，尤其要保证上传取消、文件删除、分享失效等场景下的数据状态一致。

### 1.3国内外研究现状

云存储和网络磁盘并不是新的研究方向，相关理论和工程实践已经比较丰富。但是，当研究范围缩小到“基于C++ Web框架的私有化网络磁盘系统”时，可以直接借鉴的完整案例相对较少。

国外云存储起步较早，分布式文件系统、对象存储和数据去重已有较多成熟方案。GFS、Amazon S3和OpenStack Swift主要面向数据中心级水平扩展，直接用于单机私有化部署会显得较重。Nextcloud和ownCloud功能较完整，但对服务器配置和运行性能有一定要求；SeaweedFS、MinIO等项目更偏向对象存储基础设施。

国内公有云网盘发展较快，百度网盘、阿里云盘等产品推动了文件秒传、内容去重和传输加速等方向。在教学和毕业设计项目中，自建网盘常采用Spring Boot、Django或Flask配合数据库和本地文件系统实现，基本功能能够满足使用需要，但高并发文件传输和资源占用控制仍有优化空间。采用C++ Web框架完成完整网盘业务流程的公开案例相对较少。

已有研究和系统实践可以为云存储架构和私有网盘开发提供参考，但在中小规模、私有化部署和C++后端这几个条件同时存在时，仍需要结合具体工程进行验证。本文不以替代成熟云存储系统为目标，而是尝试给出一种面向单机或小团队环境的网络磁盘实现路径。

### 1.4本文的组织结构

本文围绕私有化网络磁盘系统展开，重点包括文件存储访问、大文件传输、目录树管理、分享控制和后台运维。课题目标是完成一个普通用户和管理员均可使用的网盘平台，并验证其部署、演示和维护可行性。

用户侧接口包括账号认证、个人资料、文件和目录管理、分片上传、断点续传、秒传、Range下载、外链分享和回收站处理等功能。管理员侧偏向系统维护，包括用户管理、存储统计、分享管理、系统概览和状态查询。

对于文件上传和下载等I/O等待较多的请求，系统采用Drogon异步非阻塞I/O和C++协程模型进行处理。上传任务和分片状态写入数据库，客户端断线后只需要补传缺失分片；文件内容哈希和引用计数用于实现秒传与去重，避免相同内容重复落盘。Redis承担令牌、限流和登录失败次数等短时状态，从而减少高频状态变化对MySQL的压力。

系统安全设计主要围绕几个边界处理。普通用户只能访问自己名下的文件和目录；管理员接口除了校验登录状态，还要检查用户角色；公开分享访问不直接复用用户JWT，而是通过分享短码、可选密码、短期分享令牌和有效期共同限制访问范围。用户密码使用Argon2id算法进行哈希存储，登录失败计数和短时锁定机制则用于降低暴力破解带来的风险。

后端按照认证、用户、文件、目录、分享、回收站、运维统计和操作日志等模块进行拆分。控制器主要负责请求解析和响应转换，核心业务判断集中在服务层完成；存储层通过IFileStorage隔离本地文件系统。后续如果继续接入对象存储、文件版本历史、WebDAV接口或缩略图预览，也可以在现有模块基础上继续扩展。

## 第2章 相关技术分析

### 2.1 Drogon框架与C++23协程

Drogon是面向HTTP服务的C++ Web框架，底层基于epoll（macOS/FreeBSD下为kqueue）处理非阻塞I/O。文件上传和下载以磁盘读写、网络等待为主，阻塞模型容易长时间占用线程。本系统采用C++23，并结合HttpController、HttpCoroFilter和drogon::Task组织控制器、过滤器和服务层逻辑；业务返回值采用Result<T>表达成功或失败状态。

### 2.2 MySQL数据库

MySQL是常用的关系型数据库，稳定性和资料都比较成熟，适合保存中小规模业务系统中的长期数据。本系统把用户账号、文件内容哈希、文件元数据、目录树、上传任务、上传分片、回收站记录、分享记录、分享文件关联和操作日志放在MySQL中。文件列表、目录树遍历、秒传查重、配额统计和分享访问等查询频率较高，因此表结构中设置了联合索引、全文索引和唯一约束。

### 2.3 Redis缓存与状态管理

Redis是内存型键值数据库，适合保存生命周期较短、访问频率较高的系统状态。本系统将Refresh Token、Access Token黑名单、登录失败计数、分享访问令牌、密码尝试次数和接口限流计数保存到Redis中。该设计可以把易过期、变化频繁的状态从MySQL中分离出来，使鉴权、限流和安全控制逻辑更加清晰。

### 2.4 JWT身份鉴权机制

JWT（JSON Web Token）用于在各方之间传递身份认证信息。本系统登录成功后签发Access Token与Refresh Token，普通业务请求通过Authorization请求头携带访问令牌，令牌刷新和登出依赖Redis中的刷新令牌与黑名单状态；公开分享访问使用独立分享令牌，并通过X-Share-Token请求头传递。

### 2.5 CMake构建工具与安全基础库

CMake是跨平台构建工具，也是Drogon项目中比较常用的构建方式。本系统在后端工程中使用CMakeLists.txt、CMakePresets.json和vcpkg manifest管理编译依赖、构建预设和第三方库，使Linux与Windows环境下的编译、测试和部署步骤保持一致。密码处理方面，系统使用libsodium提供的Argon2id算法保存用户密码，避免把明文密码或弱哈希结果直接写入数据库。

### 2.6 Qt框架与QML

Qt是常用的跨平台C++应用程序开发框架。本系统桌面客户端基于Qt 6实现，使用Qt Network访问后端RESTful API，处理分片上传、断点下载和JSON解析。界面层采用QML和Qt Quick Controls 2编写文件列表、目录导航、传输进度、分享管理和后台页面；C++侧保存网络请求与业务状态，两者通过属性绑定和信号槽连接。

## 第3章 需求分析

### 3.1系统需求概述

在建设私有化网络磁盘系统之前，需要从技术条件、经济成本和使用流程三个方面分析系统建设的可行性。结合课题目标和已选技术栈来看，本系统具备落地实现的基础条件。

技术方面，C++23、Drogon、MySQL和Redis可以覆盖本课题主要需求。Drogon提供HTTP路由、过滤器、控制器、协程任务、异步数据库访问和配置管理；MySQL保存用户、文件、目录、分享和日志等结构化数据；Redis保存令牌、限流和登录失败计数等短期状态。JWT鉴权、Argon2id密码哈希以及CMake/vcpkg构建体系也都有成熟库可用。

经济可行性方面，本系统所用软件和运行环境都有开源免费版本，包括Drogon、MySQL社区版、Redis、CMake、GCC/Clang和常见Linux工具。系统硬件要求不高，普通个人计算机或低配云服务器即可完成编译、部署和演示。课题成本主要集中在开发、调试和测试时间上。

使用流程方面，系统面向普通用户和管理员，并为未登录访客保留受限分享访问入口。后端接口围绕账号认证、文件上传下载、目录管理、分享、回收站、日志和运维统计展开，桌面客户端通过RESTful API接入。权限校验、错误响应和业务状态由后端统一处理。

### 3.2系统功能需求分析

私有化网络磁盘系统的需求主要来自普通用户和管理员两个方面。普通用户关注文件是否能够稳定上传、是否便于整理、是否可以在需要时进行分享；管理员则更加关注账号、存储资源和系统运行状态是否可控。围绕这两类角色，系统需求可以分为功能需求和非功能需求两个部分。

#### 3.2.1账号与用户模块需求分析

账号与用户模块主要负责身份识别和登录状态维护。普通用户可以注册、登录、刷新令牌、登出，也可以查询或修改个人资料、修改密码、查看存储空间。注册时，系统检查用户名和邮箱是否已被占用；登录时，除校验密码外，还要判断账号状态和失败次数。认证通过后，后端签发Access Token与Refresh Token，后续业务接口依赖令牌完成鉴权和续期。用户中心展示已用空间、预占用空间、剩余配额、文件数和目录数，方便用户了解存储使用情况。

管理员侧账号功能更偏向平台维护。系统需要支持用户列表查询、关键字与状态筛选、用户详情查看、存储使用量查询、可用空间调整、账号禁用或启用、角色变更和软删除。由于管理员操作会直接影响平台账号状态和权限边界，因此所有管理员操作都必须先经过普通JWT鉴权，再经过管理员角色鉴权。

#### 3.2.2文件与目录模块需求分析

文件模块覆盖上传、访问、整理和删除等主要环节。系统需要支持文件与目录混合分页展示、按名称搜索、详情查询、重命名、批量移动、批量复制和软删除等操作。下载方面，除普通完整下载外，还需要支持HTTP Range断点下载，使客户端在网络不稳定时可以继续已有进度。

上传功能是文件模块中状态变化最多的部分。系统需要把上传过程拆分为初始化上传、上传分片、完成合并和取消上传四个阶段，并通过上传任务和分片记录保存进度，从而支持断点续传。当服务器中已经存在相同内容文件时，系统应根据内容哈希完成秒传，不再重复接收和保存物理文件。目录模块则需要支持多级目录创建、目录树查询和面包屑路径查询，同时保证同一用户在同一父目录下不能创建同名目录。

#### 3.2.3分享、回收站与管理模块需求分析

分享模块需要支持用户为文件或目录生成外链分享，并能够设置有效期、访问密码和查看或下载权限。未登录访客访问分享时，系统应先校验分享短码、分享状态、有效期和访问密码，校验成功后再签发短期分享访问令牌；访客浏览分享内容或下载分享文件时，需要通过独立的分享令牌完成鉴权，避免公开访问流程与登录用户JWT混用。

回收站模块主要面向误删除后的恢复需求。用户删除文件或目录时，系统不应立即清除物理内容，而是先把项目放入回收站，并保存原路径、原所属目录、项目类型、内容引用和恢复所需数据。用户可以查看回收站列表，也可以执行批量恢复、彻底删除或清空回收站。管理员与运维模块则需要提供全局存储统计、分享记录查看、违规分享强制取消、系统概览、数据库状态、Redis状态和磁盘空间状态查询等功能。

#### 3.2.4系统用例分析

本系统主要涉及普通用户和管理员两个账号角色，并包含未登录访客访问分享的公开场景。普通用户通过用户端完成注册登录、文件上传与下载、目录管理、文件分享等操作；访客通过分享短码、访问密码和分享令牌浏览或下载授权内容；管理员通过后台完成用户管理、存储统计查看和系统参数配置等操作。

普通用户核心用例包括账号认证、个人资料维护、存储空间查看、文件上传下载、目录管理、搜索、重命名、移动复制、回收站处理、分享创建与访问，以及保存分享内容到个人网盘；管理员核心用例包括用户列表与详情查看、账号状态和角色调整、空间设置、软删除用户、全局存储统计、分享管理、操作日志、系统概览和系统状态查看。

### 3.3系统非功能需求分析

#### 3.3.1系统性能需求分析

系统需要在单机私有化部署环境下稳定运行，并利用Drogon异步I/O提高文件传输效率。文件列表、目录导航和配额查询应快速返回；上传和下载应采用流式处理控制内存峰值。上传任务和分片状态需要持久化保存，以支持网络中断后的补传。

#### 3.3.2系统安全性与可维护性需求分析

系统需要对不同用户的文件资源严格隔离，普通用户只能访问自己名下的文件和目录，不能通过接口越权访问或下载他人文件；管理员接口需要单独鉴权，普通用户令牌无法访问管理员功能。文件分享链接需要使用随机短码、可选访问密码、有效期和短期分享访问令牌共同控制公开访问范围。用户密码必须经过安全哈希后存储，不得以明文形式保存在数据库中。

可维护性方面，后端按认证、用户、文件、目录、分享、回收站、管理员、日志和系统状态等模块划分。控制器负责请求解析和响应转换，业务判断放在服务层；数据库字段含义和约束尽量保持清楚，便于后续维护和Schema调整。

#### 3.3.3数据字典

本系统核心数据对象包括用户信息、文件内容、文件元数据、目录信息、上传任务、上传分片、回收站记录、分享记录、分享文件关联和操作日志。

用户信息（users）保存账号凭据、个人资料、登录安全状态和存储配额信息，是登录鉴权、文件归属判断和存储限额控制的依据。字段包括用户ID、用户名、邮箱、密码哈希、昵称、头像、存储配额、已用存储、预占用存储、账号状态、角色、登录失败次数、锁定时间、最后登录信息和创建更新时间。

文件内容（file_contents）保存物理文件索引，秒传去重和内容寻址存储都依赖该表。字段包括内容ID、MD5哈希、SHA256哈希、文件大小、存储路径、MIME类型、引用计数和创建时间。多个用户文件可指向同一内容对象，避免相同文件重复落盘。

文件元数据（files）保存用户视角下的文件描述，不直接保存二进制内容。字段包括文件ID、用户ID、内容ID、文件夹ID、文件名、扩展名、大小、MIME类型、路径、收藏标记、下载次数、最后访问时间和创建更新时间。文件列表、详情和权限判断都会读取该表。

目录信息（folders）维护用户目录树，用于目录导航和文件路径组织。字段包括目录ID、用户ID、父目录ID（根目录以0表示）、目录名称、完整路径、目录深度、子项数量、创建时间和更新时间。系统通过父目录ID形成父子关系。

上传任务（upload_tasks）用于大文件分片上传和断点续传，记录任务状态、目标文件夹、文件名、大小、MD5、分片数量、预占用字节、临时路径、过期时间和失败原因等信息。上传分片（upload_task_chunks）以任务ID和分片索引作为联合主键，用来标记已上传分片。

回收站记录（trash）保存被软删除文件或目录的恢复信息，字段包括记录ID、用户ID、项目类型、原项目ID、名称、大小、内容ID、原文件夹、原路径、数据备份、删除时间和过期时间。系统可据此恢复误删项目；彻底删除时再减少引用计数并释放物理存储。

分享记录（shares）保存外链分享信息，包括分享ID、短码、分享者、访问密码哈希、权限、访问次数、下载次数、状态和过期时间。分享文件关联（share_files）记录分享包含的文件或目录。拆成两张表后，一个分享可以关联多个项目，也便于后续扩展目录浏览。

操作日志（operation_logs）记录上传、下载、删除、分享等关键动作，保存用户、操作类型、目标对象、IP地址、客户端信息和创建时间。出现异常下载、误删文件或分享访问问题时，管理员可以据此确认对象、用户和时间。

这些数据对象基本覆盖了系统运行所需的业务信息，后续数据库设计和服务层逻辑也围绕它们展开。

## 第4章 系统设计

### 4.1系统架构设计

系统采用后端服务与桌面客户端分离的结构进行设计。后端通过RESTful HTTP接口提供认证、文件、目录、分享、回收站、日志和管理等能力，桌面端使用Qt/QML编写普通用户、访客和管理员界面，并通过统一网络层调用后端接口。该结构可以降低界面层和服务层之间的耦合程度，也便于后端接口脱离客户端进行单独测试。

后端内部可以划分为客户端接入层、过滤器层、控制器层、服务层和数据存储层。客户端负责发起HTTP请求；过滤器负责处理JWT鉴权、管理员鉴权、分享令牌鉴权和接口限流；控制器负责解析请求并组织响应；服务层负责认证、用户、文件、目录、分享、回收站、管理员、日志、健康检查和系统信息等业务处理；数据存储层由MySQL、Redis和本地文件系统组成，分别保存结构化业务数据、短生命周期状态和物理文件对象。

### 4.3系统功能设计

#### 4.3.1用户认证模块设计

用户认证模块负责注册、登录、令牌刷新、登出和接口鉴权。注册时，后端校验用户名和邮箱唯一性，使用libsodium的Argon2id生成密码哈希，并写入默认配额。登录时，服务层检查账号状态、锁定时间和密码哈希；认证通过后签发Access Token与Refresh Token，并把刷新令牌写入Redis。

JWT过滤器连接认证模块和业务控制器。登录接口携带访问令牌后，过滤器验证签名、过期时间和黑名单状态，再把用户ID、用户名和角色写入请求上下文。管理员接口还需经过管理员鉴权过滤器。Refresh Token保存在Redis中并在刷新时轮换；用户登出时删除刷新令牌，并把当前访问令牌加入黑名单。

#### 4.3.2文件与目录模块设计

（1）文件管理模块

文件管理模块承担普通用户最常使用的文件操作功能，包括列表、搜索、上传、下载、重命名、移动、复制和删除。后端由FileController暴露/api/file/* 系列接口，控制器负责请求解析和响应转换，具体业务判断由FileService完成。

文件列表接口会根据用户ID、目录ID、类型筛选、排序字段和分页参数查询files与folders表，然后把当前目录下的文件和文件夹整理成统一列表项返回。搜索功能主要依赖文件名和目录名索引，支持按关键词、类型和目录范围检索。文件详情接口除返回元数据外，还会返回面包屑路径，客户端据此构建导航视图。

文件变更操作需要处理名称、路径和内容引用边界。重命名检查名称长度、非法字符、保留名称和同目录冲突；移动目录不能移到自身或子目录下；复制文件复用file_contents内容对象并增加引用计数。普通删除写入trash表并从正常列表移除，彻底删除时才减少引用计数并清理物理文件。

（2）目录管理模块

目录管理模块维护用户的多级目录结构。folders表保存目录名称、父目录ID、完整路径、深度和子项数量，根目录统一用parent_id = 0表示。创建目录时，后端先确认父目录属于当前用户，再通过(user_id, parent_id, name)唯一约束避免同级重名。

目录树接口按父子关系返回当前用户的目录层级，面包屑接口返回从根目录到指定目录的路径。为避免异常数据造成循环引用，服务层构建目录树时限制最大深度，生成面包屑时检查重复节点。目录删除不直接丢弃数据，而是进入回收站流程，保留恢复所需的原始路径和项目数据。

（3）文件上传模块

文件上传采用统一分片流程，默认分片大小为5MB，包括初始化、上传分片、完成合并和取消上传四个阶段。初始化请求携带文件名、大小、目标目录和MD5，后端先检查配额，再按MD5查询file_contents表。若已存在相同内容对象，服务端直接创建files记录并增加引用计数，上传在初始化阶段完成，即秒传。

若服务器没有对应内容，系统创建upload_tasks记录并预占用空间。客户端按索引上传分片，后端写入临时目录，并在upload_task_chunks表记录进度。断点续传时，初始化接口返回已上传分片，客户端只补传缺失部分。全部分片完成后，AssemblyWorkerPool控制合并并发，后端合并临时分片、校验哈希，写入file_contents和files表，并释放预占用空间。

#### 4.3.3分享模块设计

文件分享模块用于把用户自己的文件或目录生成外链，供其他人访问。创建分享时，后端在shares表中写入分享短码、分享者ID、可选访问密码哈希、权限类型、有效期和状态，并在share_files表中保存被分享文件或目录的关联关系。分享权限分为查看和下载两类，分享状态则包括有效、取消和过期。

公开访问分享时，访客通过分享短码和可选密码调用访问接口。后端校验分享状态、有效期和密码，校验通过后签发短期分享令牌。后续浏览或下载时，访客在X-Share-Token请求头中携带该令牌，由分享鉴权过滤器校验。系统记录浏览和下载次数，并用Redis限制密码尝试次数。

（1）回收站模块

回收站模块用于降低用户误删除带来的数据丢失风险。普通删除不会立即物理删除文件，而是把项目类型、原项目ID、原路径、项目名称、内容ID和完整数据备份写入trash表。用户可以分页查看回收站项目，也可以批量恢复、彻底删除或清空回收站。恢复时，如果原目录不存在，则恢复到根目录；如果名称冲突，服务层生成新的名称，避免覆盖现有文件。定时清理任务负责删除过期回收站记录和过期上传任务，防止临时数据长期堆积。

#### 4.3.4管理员与运维模块设计

（1）用户管理模块

管理员用户管理模块通过/api/admin/users系列接口维护账号。管理员可以查看和筛选用户、查看详情和存储使用情况，也可以修改状态、调整角色、设置空间或软删除用户。所有管理员接口都先经过JWT鉴权，再经过管理员角色鉴权。

（2）存储统计与分享管理模块

存储统计模块聚合users、files、file_contents、folders等表，计算全平台用户数、文件数、内容对象数、存储占用和各用户使用情况。由于系统采用内容寻址和引用计数机制，用户视角下的逻辑文件大小与物理内容占用并不总是一致，因此统计时需要分别处理。

分享管理模块用于支持管理员查看全平台分享列表、查看单个分享详情并强制取消违规分享，主要面向公开链接滥用、误分享和过期分享治理等场景。

（3）系统状态与日志模块

系统状态模块用于部署检查和日常维护，页面展示服务运行时间、版本、数据库连接、Redis连接和磁盘空间等指标。操作日志分页保存上传、下载、删除、分享等动作，管理员排查异常请求或处理用户反馈时，可以先查看这些记录。

## 第5章 系统实现

本章结合项目代码说明系统实现。后端按控制器、过滤器、服务层、数据模型和存储抽象组织，控制器负责路由和响应转换，服务层处理业务规则、数据库事务和Redis状态。桌面端用AuthShell、OwnerShell、VisitorShell和AdminShell区分登录、普通用户、访客分享和管理员场景。

### 5.1用户与认证模块功能实现

（1）注册与登录实现

账号注册和登录接口由AuthController提供，业务判断由AuthService完成。注册时，后端接收用户名、邮箱和密码，由DTO检查格式，再查询users表确认用户名和邮箱未被占用。校验通过后，服务层使用Argon2id生成密码哈希，并写入默认资料、配额、状态和角色等字段。

登录接口支持用户名或邮箱。服务层读取账号状态、锁定时间和密码哈希后依次判断，账号禁用、锁定或密码错误时返回相应结果；认证成功时重置失败计数，签发Access Token与Refresh Token，并返回用户信息。客户端保存会话后，按角色切换到普通用户或管理员界面。

（2）令牌生命周期与鉴权过滤

令牌逻辑集中在TokenService中。Access Token采用JWT格式，携带用户ID、用户名、角色和过期时间；普通业务接口通过JwtAuthFilter校验Authorization请求头。Refresh Token保存在Redis中，用于续期访问令牌。刷新成功后旧令牌被替换，新令牌返回客户端。用户登出时，系统删除Redis中的刷新令牌，并把当前访问令牌加入黑名单。

不同访问边界使用不同过滤器。管理员接口在JWT校验后还要经过AdminAuthFilter，只有管理员角色可以访问/api/admin/* 路由；公开分享的浏览和下载接口使用ShareAuthFilter校验X-Share-Token，避免访客流程与登录用户JWT混在一起。桌面端网络层由RequestFactory按请求类型附加用户令牌、分享令牌或两者组合，请求来源也更容易区分。

（3）个人资料、密码与存储空间实现

用户中心由UserController和UserService实现，包括资料查询、资料更新、密码修改和空间查看。资料更新接口只修改请求中传入的字段；密码修改接口要求提交当前密码，校验通过后重新生成Argon2id哈希并更新users.password_hash。

存储空间接口读取users表中的storage_quota、storage_used和storage_reserved字段，并结合文件数、目录数返回已用空间、预占用空间、剩余配额和资源数量。桌面端SettingsPage和ProfileManager负责加载这些数据；用户修改资料或密码后，页面根据接口结果给出提示。

### 5.2文件传输模块功能实现

（1）分片上传初始化与秒传判断

文件上传由FileController提供初始化、上传分片、完成上传和取消上传接口，主要路径包括/api/file/upload/init、/api/file/upload/chunk和/api/file/upload/complete等。控制器绑定路由、HTTP方法和过滤器，上传接口接入JWT鉴权和限流过滤器。各处理函数返回drogon::Task<drogon::HttpResponsePtr>，并用co_await等待服务层逻辑。

客户端选择文件后，TransferManager会提交文件名、文件大小、目标目录和文件MD5。初始化阶段先检查用户配额，如果当前已用空间加上预占用空间已经超过配额上限，服务端直接返回空间不足，客户端也就不再继续上传分片。

初始化阶段还会按文件哈希查询file_contents表。若已有相同内容对象，服务层直接创建files元数据、增加引用计数，并返回秒传结果。若内容不存在，则创建upload_tasks记录，写入任务ID、目标目录、文件信息、分片信息、临时路径、预占用字节数和过期时间，并返回已上传分片列表。

（2）分片写入、断点续传与后台合并

分片上传接口按照任务ID和分片索引接收二进制内容。Drogon把请求体封装在HttpRequest对象中，控制器可以直接读取request->body()取得application/octet-stream数据，不需要再进行JSON封装。服务层随后检查任务归属和任务状态，确认无误后把分片写入临时目录，并在upload_task_chunks表中记录对应索引。

大文件拆成固定分片后，单次请求只处理一部分数据，服务端内存峰值更容易控制。客户端恢复上传时再次调用初始化接口，拿到已上传分片索引后，只补传缺失分片。断点续传由上传任务表和分片记录表共同支撑。

全部分片上传完成后，客户端调用完成接口。后端使用AssemblyWorkerPool限制合并并发，按索引读取临时文件，生成完整文件后计算MD5和SHA256并与初始化哈希比对。校验通过后，本地IFileStorage把文件移入内容寻址目录，服务层写入file_contents和files表，释放预占用空间并更新已用空间。取消上传或任务过期时，临时分片删除，任务状态和预占用空间回滚。

（3）文件下载与Range断点下载

文件下载流程分为下载信息查询和文件流返回两个步骤。前一步向客户端返回文件名、大小和MIME类型等信息；后一步先检查文件归属，确认当前用户具有访问权限后，再由IFileStorage定位内容寻址文件，并交给DownloadResponder生成HTTP响应。

大文件下载时，不能把完整文件一次性加载到内存中。下载接口使用Drogon的HttpResponse::newStreamResponse实现流式返回，回调函数按固定块大小读取文件，再写入响应缓冲区。这样处理后，内存占用能够保持在相对稳定的范围内，服务端在发送文件的同时也可以继续处理其他连接。

请求头包含Range字段时，后端解析字节范围，只返回对应内容，并设置206 Partial Content、Content-Range、Accept-Ranges和Content-Length等响应头。范围超过文件大小时返回416。普通下载、断点续传和非法Range响应共用流式构造逻辑；桌面端由TransferManager和DownloadTaskModel管理下载进度、状态和失败原因。

（4）传输中心实现

传输中心由TransferCenterPage实现，并与文件列表页面分开。上传任务记录文件名、目标目录、已上传字节数、总字节数、状态和错误信息；下载任务记录本地路径、进度、暂停状态和完成状态。这样处理以后，用户在上传或下载时间较长时，仍然可以继续浏览文件、切换目录或处理其他操作，不必一直停留在文件列表页面等待任务结束。

### 5.3文件与目录管理模块功能实现

（1）文件列表与资源管理器实现

普通用户的大部分文件操作从DriveBrowserPage进入。OwnerShell加载后，页面划分为“我的网盘”“分享”和“回收站”；“我的网盘”由DriveMyFilesView承载文件列表，工具栏和右键菜单提供刷新、上传、下载、新建文件夹、重命名、移动、复制、分享和删除等入口。后端由FileService查询files和folders，并整理成统一列表项返回。

DriveManager负责保存当前目录ID、列表模型、排序方式、选择状态和加载状态。根目录使用ID 0表示；用户切换目录时，页面不需要重建，只更新目录ID和列表数据。请求失败或列表为空时，界面显示对应提示并允许重新加载。后端查询始终带有用户ID权限边界，普通用户即使构造其他目录ID，也无法越权读取他人文件。

（2）目录树与面包屑导航实现

目录相关接口由FolderController和FolderService负责，包括创建目录、目录树查询、面包屑路径查询和目录重命名。创建目录时，服务层先确认父目录属于当前用户，再检查同级是否重名。校验通过后写入folders表，计算完整路径和目录深度，并更新父目录子项数量。

目录树依据folders.parent_id组织。构建时，服务层限制最大深度并检测异常循环，避免错误数据导致递归无法结束。面包屑路径从当前目录逐级回溯到根目录。桌面端左侧由FolderTreePanel显示目录树，顶部由BreadcrumbBar显示当前位置；用户点击节点后，目录树、面包屑和文件列表同步刷新。

图5-6为目录树和面包屑导航界面。目录树来自folders表中的父子关系，面包屑来自当前目录的父级回溯结果。用户点击目录树节点或面包屑节点后，文件列表切换到新的目录。

（3）重命名、移动、复制和搜索实现

重命名操作分别更新files或folders中的名称和路径。服务层在写入前检查名称长度、非法字符、保留名称和同级重名。移动接口支持批量文件和目录；移动目录时需要额外判断目标目录，不能把目录移动到自身或其子目录下，否则会破坏目录树结构。复制文件时只新增逻辑文件记录并增加file_contents.ref_count，不重复复制物理内容。

搜索接口按关键词、项目类型和目录范围返回分页结果。桌面端保存关键词和排序方式，用户输入后由DriveManager请求后端并刷新列表。批量移动、复制、删除和分享时，客户端提交多个项目ID，后端逐项处理并返回结果，界面再显示成功状态或失败原因。

### 5.4回收站模块功能实现

回收站由TrashController和TrashService负责。普通删除并不立即释放存储空间，而是把项目类型、原项目ID、项目名称、原目录、原路径、大小、内容引用和必要的JSON备份写入trash表，再从正常文件或目录列表中移除。桌面端DriveTrashView读取这些记录，用户可以多选后进行恢复、彻底删除，也可以清空当前账号的回收站。

图5-8 回收站管理功能截图

![图5-8 回收站管理功能截图](assets/回收站管理功能截图.png)

图5-8为回收站界面。列表中保留已删除项目的名称、路径、大小和删除时间，操作区提供恢复、彻底删除和清空入口。

恢复时，服务层先确认回收站记录属于当前用户。能够回到原父目录的项目优先恢复到原位置；原目录已经不存在时，则恢复到根目录；若目标目录中存在同名项目，服务层自动生成name (n).ext或name (n)形式的新名称，避免覆盖已有数据。当前版本对文件夹恢复采取较保守的规则，只恢复文件夹记录本身，不递归恢复其子树。

彻底删除会影响物理内容。对于文件项目，服务层先减少file_contents.ref_count，引用计数归零后由IFileStorage删除本地内容寻址文件，并更新用户已用空间。清空回收站时批量执行这一过程。后台清理服务还会定期处理过期记录，避免临时分片和删除数据长期堆积。

### 5.5分享模块功能实现

（1）分享创建与所有者管理

分享功能由ShareController和ShareService负责。所有者侧接口包括创建分享、我的分享列表、详情、设置更新和取消分享。用户选择文件或目录后，可设置有效期、访问密码和权限。服务层生成分享短码后写入shares表，再把被分享项目写入share_files表；带密码的分享只保存Argon2id哈希。创建完成后，桌面端返回分享信息供用户复制。

图5-9为创建分享对话框。用户在该页面确认被分享项目、有效期、访问密码和权限类型；后端生成分享短码并写入shares、share_files两张表，带密码的分享只保存密码哈希。

“分享”视图由DriveSharedView展示当前用户创建过的分享记录，列表包含分享码、状态、有效期、浏览次数和下载次数等字段。用户可以查看详情、复制链接、修改权限或有效期，也可以批量取消分享。取消时，服务层把分享状态改为取消，并使对应公开访问失效；访客再次打开原链接时，会收到链接无效提示。

（2）访客访问、浏览与下载实现

访客通过分享短码进入VisitorShell，ShareVerifyPage显示访问校验界面。公开访问接口查询shares表，检查分享状态、有效期和密码；带密码的分享还会在Redis中记录尝试次数并限流。校验通过后，后端签发短期Share Token，后续访客请求均携带X-Share-Token。

浏览分享内容时，ShareAuthFilter先校验令牌，接口再返回分享中的文件和目录列表，并更新浏览次数。下载接口还需要再次检查分享状态和权限，只有允许下载时才读取本地内容寻址文件并返回文件流，同时增加下载次数。桌面端ShareBrowsePage负责显示访客可见内容；权限不足、链接过期或令牌失效时，页面按照后端错误结果提示用户。

（3）保存分享内容到个人网盘

保存分享内容使用/api/share/save/{share_id}接口，同时经过JwtAuthFilter和ShareAuthFilter。调用者需登录账号并通过分享访问校验。保存时，服务层按share_files关联关系为当前用户创建文件或目录记录；文件内容复用file_contents对象，只增加引用计数，不再写入新的物理文件。

### 5.6管理后台与运维模块功能实现

（1）管理员用户管理实现

管理员接口集中在AdminController和AdminService中。所有/api/admin/* 路由都需要先经过JWT鉴权，再由AdminAuthFilter确认管理员角色。管理员登录后进入AdminShell和AdminPage，用户、分享和系统状态被放在不同标签页中。用户管理接口支持分页、关键词、账号状态和角色筛选，返回用户ID、用户名、邮箱、昵称、存储使用量、账号状态和角色等信息。

管理员可以禁用或启用普通用户、调整角色、设置空间，也可以软删除用户。服务层会保护管理员自身和系统中最后一个管理员，防止误禁用或降级。状态和角色变更后，服务层写入操作日志；桌面端UserTab和AdminManager负责加载列表、提交操作并显示结果。

### 6.3系统性能测试

性能测试围绕文件列表查询、目录导航、上传初始化和文件下载等高频接口展开，主要观察单机部署下的响应时间、吞吐量和错误率。后端使用Drogon异步I/O和协程服务层，本地文件按内容寻址保存；上传分片状态写入MySQL，令牌状态和限流计数交给Redis处理。从测试结果看，在毕业设计演示和中小规模私有化部署场景下，系统接口响应较稳定，未出现明显超时或服务异常。

### 6.4系统安全性测试

安全性测试重点验证JWT鉴权、管理员角色校验、用户资源归属校验、分享访问令牌和密码错误限制等机制。未登录访问受保护接口、普通用户访问管理员接口、用户下载他人文件、访客使用错误或过期分享令牌等场景均被单独测试。测试结果显示，上述请求能够被系统拦截或返回对应错误；登出后的访问令牌也会因为黑名单状态而失效。就当前设计范围而言，系统在账号认证、文件访问隔离和公开分享控制方面可以满足第3章提出的安全性需求。

### 6.5测试总结

功能测试完成后，系统主线业务基本能够稳定运行。普通用户、访客和管理员三类角色的核心流程均已通过验证，包括认证鉴权、文件传输、目录管理、分享访问、回收站处理，以及管理员用户管理、分享管理、操作日志、存储统计和系统状态查询。

安全性测试单独验证了用户访问他人文件、普通用户访问管理员接口、令牌过期、登出后继续请求、登录失败锁定、分享密码错误和分享令牌失效等场景。结果显示，这些请求能够被系统拦截或按预期返回错误。存储配额限制也能在上传初始化阶段生效，避免客户端继续上传无效分片。

当前测试仍以毕业设计演示环境为主，主要在本地单机条件下验证，尚未进行充分的大规模并发压测。操作日志和健康检查已经具备，但监控告警、容量趋势分析和容灾恢复仍较基础。桌面端覆盖主要页面，但拖拽上传、缩略图预览和在线预览尚未完成。若面向实际部署，后续应优先补充性能压测和运维监控。

## 总结与展望

本文完成了一套面向私有化部署的网络磁盘系统。论文从需求分析入手，说明总体架构、数据库结构、模块设计、功能实现和测试过程。系统后端采用C++23和Drogon Web框架，桌面端采用Qt 6和QML，数据层由MySQL、Redis和本地内容寻址文件系统组成。系统区分普通用户、访客和管理员三类角色，覆盖文件存储、传输、分享和后台运维等流程。

在功能实现方面，系统完成了注册登录、令牌管理、JWT鉴权、管理员鉴权、个人资料与空间统计、目录树、面包屑、分片上传、断点续传、秒传、后台合并、Range下载、文件整理、回收站、外链分享、操作日志、健康检查和系统状态查询等功能。桌面端实现了认证界面、网盘资源管理器、传输中心、访客分享页、个人设置页和管理员后台。上传与存储部分通过upload_tasks、upload_task_chunks和file_contents完成分片状态、秒传与去重管理。

测试结果表明，系统基本达到毕业设计阶段的预期目标。注册登录、文件传输、目录管理、分享访问控制、回收站恢复、权限边界和管理员操作等流程都能够按照设计运行，RESTful接口的数据交互也较为清晰。通过本次系统实现可以看出，C++23、Drogon、MySQL、Redis和Qt/QML能够组合形成一套可运行的中小规模私有化网络磁盘系统。

当前系统仍有不足。文件版本历史、WebDAV、在线预览和缩略图尚未完成；高并发压力测试和安全测试还不充分，大规模文件传输下的吞吐量、延迟和稳定性缺少更多数据。系统已有操作日志、健康检查和状态接口，但监控告警、容量趋势分析、自动备份和容灾恢复仍较基础。后续可优先完善客户端体验和压测数据，再考虑对象存储接入及运维能力建设。
