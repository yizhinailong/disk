# 基于 Drogon 的网络磁盘系统的设计与实现

## 摘　要

近年来，互联网应用和个人数字内容快速增长，用户对在线文件存储、管理与共享的需求不断增加。个人用户和中小型团队都希望文件能够随时访问、在多端同步，并尽量保存在可控的私有环境中。现有公有云网盘虽然使用方便，但常见问题也很突出，例如数据隐私受制于第三方平台、上传下载带宽受限、服务策略变化难以预判等；自建网盘方案则容易在性能和易用性之间失衡。因此，设计并实现一个高性能、便于私有化部署、可自主运维的网络磁盘系统，具有明确的应用价值。

本文按照软件工程流程完成系统设计与实现。系统定位为面向私有化部署的高性能网盘系统，后端采用 C++23 和 Drogon Web 框架，利用其基于 epoll 的非阻塞异步 I/O 与 C++ 协程处理文件传输和业务接口；客户端采用 Qt 6 与 QML 构建桌面端界面，通过 RESTful API 与后端交互。数据层使用 MySQL 保存用户信息、文件元数据、内容索引、目录结构、上传任务、分享记录和回收站等核心数据，引入 Redis 管理刷新令牌、令牌黑名单、登录失败计数、分享访问状态和限流计数等短时状态；文件实体采用内容寻址方式存放在服务器本地文件系统中，由后端统一处理路径映射、引用计数和访问权限。系统面向普通用户、访客与管理员三类使用场景：普通用户可完成注册、登录、令牌刷新与登出，查看个人资料和存储空间，进行文件与目录的列表、搜索、重命名、移动、复制、软删除，使用支持断点续传和秒传的大文件分片上传、文件下载、外链分享、分享管理和回收站管理等功能；访客可通过分享密码和分享令牌浏览或下载授权内容；管理员可通过管理界面维护用户账号状态与角色，查看全局存储统计、操作日志和系统状态，审核或强制取消分享。

系统目前能够覆盖私有化网络磁盘的主要业务需求，用户可以通过桌面端较方便地完成在线文件管理、文件传输与文件共享，管理员也可以在后台界面完成用户、分享、日志和系统状态管理；后端借助 Drogon 在高并发 HTTP 处理和异步数据库访问方面的能力保持较好的响应效率。本文完成了一个可运行的私有化网盘系统，也为使用 C++ 技术栈构建文件服务类 Web 后端及配套桌面客户端提供了工程实践参考。

关键词：网络磁盘；文件管理；Drogon；C++23；RESTful API

## ABSTRACT

In recent years, with the continuous development of internet technologies and the profound transformation of personal digital lifestyles, the demand for online file storage, management, and sharing has been growing rapidly. Both individual users and small-to-medium-sized teams face practical needs for accessing files anytime and anywhere, synchronizing across multiple devices, and securely storing data on private infrastructure. However, mainstream public cloud storage products often suffer from problems such as insufficient data privacy protection, restricted upload and download bandwidth, and dependence on the stability of third-party infrastructure, while self-hosted network disk solutions frequently struggle to achieve a satisfactory balance between performance and ease of use. Accordingly, designing and implementing a high-performance, easily deployable, and fully self-manageable private network disk system carries considerable practical application value and research significance.

This thesis conducts system design and implementation work in accordance with the fundamental processes of software engineering. The system is positioned as a high-performance private network disk system. The backend is built upon the C++23 standard and the Drogon high-performance web framework, leveraging its epoll-based non-blocking asynchronous I/O and C++ coroutine capabilities to handle file transfers and business API processing. The desktop client is implemented with Qt 6 and QML and interacts with the backend through RESTful APIs. MySQL is selected for persistent storage of core data such as user information, file metadata, content indexes, directory structures, upload tasks, share records, and trash records. Redis is introduced for managing short-lived states including refresh tokens, token blacklists, login failure counters, share access states, and rate-limiting counters. File entities are stored on the server's local filesystem using content-addressed storage, with the backend uniformly managing path mapping, reference counting, and access control. The system covers regular-user, visitor, and administrator scenarios: regular users can perform account registration, login, token refreshing and logout, profile and storage querying, file and folder listing, searching, renaming, moving, copying, and soft deletion, resumable chunked upload with instant deduplication, file downloading, external sharing, share management, and trash management; visitors can browse or download authorized shared content through share passwords and share tokens; administrators can manage user account status and roles, view global storage statistics, inspect operation logs and system status, review and forcefully cancel shares, and perform other administrative functions through protected management interfaces.

The system currently satisfies the core business requirements of a private network disk to a considerable degree. On one hand, it makes online file management, file transfer, and file sharing more convenient and efficient for users through the desktop client. On the other hand, it fully exploits the advantages of the Drogon framework in high-concurrency HTTP processing and asynchronous database access at the performance level. The research presented in this thesis not only completes the development of a private network disk system with practical application value, but also provides a concrete engineering practice reference for building high-performance web services and supporting desktop clients based on the C++ technology stack.

KEYWORDS: Network Disk; File Management; Drogon; C++23; RESTful API

## 前　言

当前，工作和生活中的数字资料越来越多。学习中的文档与笔记、工作中的代码和项目文件，以及图片、视频等多媒体资料，都需要一个可靠、便于访问的存储入口。网络磁盘（网盘）把文件存储和互联网访问结合在一起，已经成为日常数据管理的重要工具。与此同时，公有云盘产品也存在隐私风险、带宽限速、免费空间有限和平台依赖较强等问题，这使得私有化、自主可控的网盘方案具有现实需求。

从用户使用角度看，网盘的价值主要体现在上传、下载和分享三个环节。用户希望通过统一的 Web 入口上传并整理文件，在需要时快速检索目标文件；对于大文件，还希望系统支持断点续传，避免网络抖动后从头开始上传。文件分享同样是高频场景，用户需要通过外链把文件分发给他人，并控制分享链接的有效期和访问权限。传统文件传输工具或即时通信软件虽然也能完成部分操作，但管理分散、过程繁琐，难以提供统一的文件视图。

从运维管理角度看，网盘系统不能只关注前台功能，还需要配套的后台管理能力。管理员需要掌握存储使用情况，查询和管理用户账号，设置存储配额与访问规则，并在系统状态异常时及时处理。如果这些管理操作分散在不同工具中，运维成本会增加，系统可靠性和规范性也会受到影响。因此，系统设计需要同时考虑用户端体验和管理端效率。

在技术选型上，本文采用 C++23 作为后端开发语言，使用 Drogon 作为 HTTP 服务框架，主要考虑性能和工程表达能力。Drogon 基于 epoll（在 macOS/FreeBSD 下为 kqueue）实现非阻塞 I/O，协程化请求处理模型适合文件传输这类 I/O 密集型场景。与脚本语言或传统阻塞式 Web 框架相比，C++ 后端在内存占用、请求吞吐量和资源控制方面更有优势，适合部署在资源有限的私有服务器上。系统同时使用 MySQL 保存关系型元数据，使用 Redis 处理短时状态和限流计数，并以本地文件系统保存内容寻址的文件实体，形成了依赖较少、便于单机部署的后端技术栈。

基于上述背景，本文围绕私有化网络磁盘系统的设计与实现展开研究，按照软件工程思路，对需求分析、总体结构、数据库设计、详细设计、实现过程和测试结果进行说明。本课题既用于验证 Drogon、MySQL 等技术在中小型文件服务系统中的适用性，也用于完成一次从需求抽象到工程实现的完整实践。相关设计和实现可为私有化存储平台以及 C++ 高性能 Web 服务开发提供参考。

## 第1章 绪论

### 1.1 研究背景

近年来，随着移动互联网的普及和个人数字内容的快速增长，用户对在线存储服务的需求持续上升。云存储技术的出现，使文件的存储与访问不再受限于特定设备或物理位置，极大地方便了个人和团队的日常数据管理工作。然而，现有的公有云网盘产品在带来便利的同时，也逐渐暴露出诸多不足：数据存储在第三方服务器上，用户的隐私和商业机密难以得到充分保护；免费套餐的存储容量和传输速度受到严格限制，高级功能往往需要持续付费订阅；一旦服务商调整政策、停止运营或发生安全事故，用户数据便面临不可控风险。部分机构或企业出于合规需要，明确要求数据必须保存在自主可控的基础设施之上，也无法使用公有云网盘服务。

因此，私有化自建网盘的需求逐渐增加。与公有云网盘相比，私有化网盘把文件实体和元数据保存在用户自己的服务器上，数据主权和隐私保护更容易落实；存储空间和访问带宽也可以按需配置，不必受第三方平台策略限制，更适合有特定要求的个人开发者、高校师生和中小型团队使用。不过，要构建一个功能完整、性能稳定且便于部署的私有化网盘并不简单。传统脚本语言或解释型语言的 Web 框架在高并发文件传输场景下，可能出现吞吐量不足和 CPU 利用率偏高的问题。为解决上述问题，本文采用 C++ 语言配合 Drogon Web 框架，设计并实现一个适合私有化部署的网络磁盘系统，为私有化存储平台的技术实现提供可验证的参考方案。

### 1.2 研究意义

本课题面向私有化网络磁盘的实际业务场景，设计并实现一个功能较完整的网盘服务系统。系统把用户文件管理、目录组织、大文件上传、文件分享和管理员后台等业务统一纳入后端服务，并利用 C++ 与 Drogon 的高性能 I/O 处理能力，为私有化文件存储平台提供可验证的工程方案。

从实践层面看，本系统可为有私有化部署需求的个人开发者、高校师生和中小团队提供一套可自主运维的文件存储与管理服务，减少数据托管在第三方平台带来的隐私风险和策略依赖。用户可以在统一界面内完成文件上传、整理、查找和分享，系统会同步跟踪存储配额，使资源使用情况更清楚。管理员则可通过后台完成用户管理、存储统计和系统配置，降低日常运维复杂度。

从学习层面看，本课题综合使用了 C++ 系统编程、异步网络 I/O、Web 框架、关系型数据库设计、缓存状态管理和 RESTful API 架构等知识，覆盖需求分析、系统设计、功能实现和测试验证等环节。通过该系统的实现，能够加深对 Drogon 框架工作机制、MySQL 数据库设计原则和 RESTful 接口规范的理解，也能积累 C++ 工程项目中模块划分、接口设计和异常处理的经验。

### 1.3 国内外研究现状

云存储与网络磁盘相关技术已经有较多研究和工程实践，但面向高性能 C++ 框架的私有化网盘实现仍然不多，公开资料也相对有限。

在国外，云存储领域的学术研究起步较早，分布式文件系统、对象存储架构和数据去重技术等方向已有大量成熟论文与工程案例。Google 文件系统（GFS）、Amazon S3 以及 OpenStack Swift 等系统在架构层面为大规模云存储提供了经典范式，但这些系统的设计目标是面向数据中心级别的水平扩展，对于资源受限的单机私有化部署而言过于复杂，部署和维护成本极高。在开源网盘领域，Nextcloud 和 ownCloud 是比较具有代表性的 PHP 实现，功能丰富但对服务器配置要求较高，性能也受限于 PHP 的运行模型。SeaweedFS 和 MinIO 则是基于 Go 语言实现的对象存储系统，在性能和部署便捷性上有明显进步，但 API 面向对象存储协议设计，并不直接提供网盘形态的用户交互界面。

在国内，随着百度网盘、阿里云盘等公有云网盘产品的快速发展，相关技术研究也日益增多，重点集中在文件秒传、内容去重、传输加速和版权保护等方向。自建私有网盘的研究与实践则主要集中在基于 Java Spring Boot、Python Django/Flask 框架的 Web 应用开发上，面向教学或毕业设计目的的实现案例中，大多采用关系型数据库配合本地文件系统的存储方式，功能覆盖基本够用，但在高并发性能和资源占用方面仍有提升空间。基于 C++ Web 框架（尤其是 Drogon）构建文件存储服务的研究与工程实践目前较少见，与本课题相关的开源项目也处于起步阶段，尚未形成成熟的设计范式和参考实现。

现有研究和实践已经为云存储架构设计、私有网盘开发提供了基础，但 C++ 高性能框架在网盘场景中的工程化应用仍有探索空间。本文结合 Drogon 的异步高并发特性和私有化部署需求，给出一个可参考的设计与实现方案。

### 1.4 本文的组织结构

本文围绕私有化网络磁盘系统的设计与实现展开，结合文件存储访问、大文件传输、目录树管理、分享链接控制和后台运维管理等需求，说明系统的需求分析、总体架构、数据库设计、模块设计与实现以及测试验证。课题目标是构建一个同时面向普通用户和管理员的网络磁盘服务平台，覆盖文件存储生命周期中的主要业务，并验证其部署可行性和可用性。

在功能设计上，系统主要面向普通用户文件管理和管理员运维管理两类需求。用户侧接口包括账号注册、登录、令牌刷新与登出，个人资料与存储空间统计，文件和目录的分页列表、搜索、详情、重命名、移动、复制、软删除，目录树与面包屑路径查询，文件上传（含断点续传、秒传去重和后台合并的分片上传机制）、文件下载（含 Range 断点下载）、文件外链分享、分享密码校验、分享内容浏览与下载，以及回收站列表、批量恢复、彻底删除和清空等功能。管理员侧接口包括用户账号查询、状态切换、角色变更、软删除、用户文件与存储查看、全局存储统计、分享列表与强制取消、系统概览和系统状态查询等功能。

在性能设计上，系统依托 Drogon 的异步非阻塞 I/O 和 C++ 协程模型，提升文件上传、下载等 I/O 密集型场景下的请求处理能力。上传任务和分片状态持久化后，客户端可以继续上传缺失分片；文件内容哈希和引用计数用于实现秒传与去重，减少相同内容的重复写入；Redis 保存短时状态、限流计数和登录失败次数，用于降低数据库热路径压力并提高安全控制效率。

在安全性设计上，系统通过登录认证、Access Token、Refresh Token 轮换和 JWT 令牌鉴权区分不同角色的访问边界。普通用户只能访问自己名下的文件和目录，管理员接口另设角色鉴权，非管理员账号不能调用后台接口。用户密码使用 Argon2id 哈希后存储，登录失败计数和短时锁定机制用于降低暴力破解风险。文件分享通过分享短码、可选访问密码、短期分享访问令牌和有效期共同限制公开访问范围，失效或取消后的分享链接不再允许访问。

在可扩展性设计上，系统按低耦合方式划分认证、用户、文件、目录、分享、回收站、运维统计和操作日志等模块。控制器负责解析请求和转换响应，核心业务集中在服务层。存储层通过 `IFileStorage` 抽象隔离本地文件系统实现，后续可在尽量少改动业务接口的情况下扩展对象存储、文件版本历史、WebDAV 接口和缩略图预览等功能。

## 第2章 相关技术分析

### 2.1 Drogon 框架与 C++23 协程

Drogon 是一个高性能 HTTP Web 应用框架，其底层网络库基于 epoll（在 macOS/FreeBSD 下为 kqueue）实现非阻塞 I/O，采用异步请求处理模型，能够以较少的线程资源支撑高并发的 HTTP 请求处理，非常适合文件传输这类 I/O 密集型服务。本系统在项目实现中采用 C++23 标准，结合 Drogon 的 `HttpController`、`HttpCoroFilter` 和 `drogon::Task` 协程接口组织控制器、过滤器和服务层逻辑，并使用 `std::expected` 风格的 `Result<T>` 统一表达业务成功或失败，减少异常控制流对业务代码的侵入。

### 2.2 MySQL 数据库

MySQL 是一种广泛使用的关系型数据库管理系统，具有稳定性高、社区资料丰富、查询性能良好等特点，适合作为中小规模业务系统的持久化数据存储后端。本系统通过 MySQL 保存用户账号信息、文件内容哈希、文件元数据、目录树结构、上传任务、上传分片、回收站记录、分享记录、分享文件关联和操作日志等核心数据，并通过联合索引、全文索引和唯一约束支撑文件列表查询、目录树遍历、秒传查重、配额统计和分享访问等高频操作。

### 2.3 Redis 缓存与状态管理

Redis 是一种高性能内存键值数据库，适合保存短生命周期状态和计数器。本系统使用 Redis 保存 Refresh Token、Access Token 黑名单、登录失败计数、分享访问令牌、密码尝试次数和接口限流计数等数据，从而将高频、短时、易过期的状态从 MySQL 中剥离出来，提高鉴权、限流和安全控制逻辑的执行效率。

### 2.4 JWT 身份鉴权机制

JWT（JSON Web Token）是一种基于 JSON 格式的开放标准（RFC 7519），用于在各方之间以紧凑、自包含的方式安全地传递身份认证信息。本系统在用户登录成功后签发 Access Token 与 Refresh Token，普通业务请求通过 `Authorization: Bearer <token>` 携带访问令牌，令牌刷新和登出依赖 Redis 中保存的刷新令牌与黑名单状态实现轮换和失效控制；公开分享访问则使用独立的分享令牌并通过 `X-Share-Token` 请求头传递，避免将用户 JWT 暴露给未登录访客。

### 2.5 CMake 构建工具与安全基础库

CMake 是一种跨平台的构建系统生成工具，被 Drogon 生态所推荐使用。本系统通过 CMakeLists.txt、CMakePresets.json 和 vcpkg manifest 管理后端项目的编译依赖、构建预设和第三方库，简化了 Linux 与 Windows 环境下的编译、测试和部署流程。密码哈希方面，系统使用 libsodium 提供的 Argon2id 算法保存用户密码，避免明文密码或弱哈希方案带来的安全风险。

### 2.6 Qt 框架与 QML

Qt 是一个跨平台的 C++ 应用程序开发框架，提供了丰富的 GUI 组件、网络通信、文件处理和国际化等功能模块，广泛用于桌面端、嵌入式和移动端应用开发。本系统的桌面客户端基于 Qt 6 构建，使用 Qt Network 模块实现与后端 RESTful API 的 HTTP 通信，支持文件分片上传、断点下载和 JSON 数据解析；界面层采用 QML（Qt Modeling Language）声明式语言编写，配合 Qt Quick Controls 2 提供现代风格的用户界面组件，实现了文件列表展示、目录导航、上传进度、分享管理和后台管理等功能页面。通过 QML 与 C++ 后端的属性绑定和信号槽机制，客户端能够在保持流畅交互体验的同时，与后端服务保持清晰的职责分离。

## 第3章 需求分析

### 3.1 系统需求概述

在私有化网络磁盘系统建设前，需要先评估系统是否具备开发和应用基础。本文从技术可行性、经济可行性和操作可行性三个方面进行分析。结合课题目标和所选技术栈的成熟度，系统具备实施条件。

从技术可行性看，本系统选用 C++23、Drogon、MySQL 和 Redis 作为核心技术基础，这些技术已有较多工业界和开源社区实践，资料和社区支持较充分。Drogon 提供 HTTP 路由、过滤器、控制器、协程任务、异步数据库访问和配置文件管理等功能，能够覆盖后端开发的主要需求；MySQL 适合保存用户、文件、目录、分享和日志等结构化数据；Redis 适合处理令牌、限流、登录失败计数等短生命周期状态。C++23 提供的协程、`std::expected`、`std::filesystem` 等能力，也降低了异步流程、错误返回和文件路径操作的编码复杂度。JWT 鉴权、Argon2id 密码哈希和 CMake/vcpkg 构建体系在 Web 服务开发中较成熟，相关 C++ 库便于集成。因此，本课题所涉及的技术处于可用、稳定状态，技术风险较低。

从经济可行性看，本系统依赖的软件工具和运行环境均可使用开源免费版本，包括 Drogon、MySQL 社区版、CMake、GCC/Clang 以及常用 Linux 系统工具，开发成本较低。系统对硬件要求不高，在普通个人计算机或低配云服务器上即可编译和运行。对于毕业设计课题而言，所需软硬件资源可以在个人环境中准备，经济层面不存在明显障碍。

从操作可行性看，系统面向普通用户和管理员两类主要账号角色设计，并为未登录访客提供受限分享访问流程。后端接口围绕账号认证、个人资料、文件上传下载、目录管理、分享、回收站、日志和运维统计等操作展开，接口路径清晰，参数和响应格式统一。桌面客户端通过 RESTful API 接入后端，管理员可通过受保护的管理接口完成用户、分享、存储和系统状态管理。权限校验、错误响应和业务状态由后端统一封装，后续二次开发按接口规范调用即可，操作复杂度可控。

### 3.2 系统功能需求分析

私有化网络磁盘系统的需求主要来自两类角色：普通用户需要在线存储、管理和共享文件，管理员需要统一管理平台用户、存储资源和系统参数。结合实际业务场景，系统需求可分为功能需求和非功能需求两部分。

#### 3.2.1 账号与用户模块需求分析

账号与用户模块需要为普通用户提供注册、登录、令牌刷新、登出、个人资料查询与更新、密码修改和存储空间查看等基础能力。系统应在注册阶段校验用户名和邮箱唯一性，在登录阶段校验账号状态、密码正确性和失败次数，并在认证成功后签发 Access Token 与 Refresh Token，以支持后续业务接口鉴权和登录态续期。用户中心还需要展示已用空间、预占用空间、剩余配额、文件数和目录数，使用户能够清晰了解个人存储资源使用情况。

管理员侧需要在账号维度提供用户列表查询、关键字与状态筛选、用户详情查看、用户存储使用量查询、可用空间调整、账号禁用或启用、角色变更和软删除等功能。所有管理员操作均应建立在普通 JWT 鉴权和管理员角色鉴权之上，防止普通用户越权访问后台运维接口。

#### 3.2.2 文件与目录模块需求分析

文件模块需要覆盖文件从上传、访问、组织到删除的完整生命周期。系统应支持文件和目录的混合分页列表展示、按名称搜索、文件详情查询、文件重命名、批量移动、批量复制和软删除；对于文件下载，需要支持普通完整下载和 HTTP Range 断点下载，以便客户端在网络不稳定场景下恢复下载进度。

上传功能是文件模块的核心需求。系统需要支持初始化上传、上传分片、完成合并和取消上传四个阶段，并通过上传任务与分片状态记录实现断点续传；当服务器已经存在相同内容文件时，应能够基于内容哈希完成秒传，避免重复上传和重复存储。目录模块需要支持多级目录创建、目录树查询和面包屑路径查询，并保证同一用户同一父目录下的目录名称不重复。

#### 3.2.3 分享、回收站与管理模块需求分析

分享模块需要支持用户为文件或目录生成外链分享，并能够设置有效期、访问密码和查看或下载权限。未登录访客访问分享时，系统应先校验分享短码、分享状态、有效期和访问密码，校验成功后再签发短期分享访问令牌；访客浏览分享内容或下载分享文件时，需要通过独立的分享令牌完成鉴权，避免公开访问流程与登录用户 JWT 混用。

回收站模块需要支持误删除恢复场景。用户删除文件或目录时，系统应先将项目移动到回收站，保留原路径、原所属目录、项目类型、内容引用和恢复所需数据；用户可以查看回收站列表，执行批量恢复、彻底删除或清空回收站。管理员与运维模块则需要提供全局存储统计、分享记录查看、违规分享强制取消、系统概览、数据库状态、Redis 状态和磁盘空间状态查询等能力。

#### 3.2.4 系统用例分析

本系统主要涉及普通用户和管理员两个账号角色，并包含未登录访客访问分享的公开场景。普通用户通过用户端完成注册登录、文件上传与下载、目录管理、文件分享等操作；访客通过分享短码、访问密码和分享令牌浏览或下载授权内容；管理员通过后台完成用户管理、存储统计查看和系统参数配置等操作。

### 3.3 系统非功能需求分析

#### 3.3.1 系统性能需求分析

系统需要能够在单机私有化部署环境下稳定运行，利用 Drogon 框架的异步 I/O 能力提升文件传输吞吐量。对于文件列表、目录导航、存储配额查询等元数据请求，后端应在较短时间内完成响应；对于文件上传和下载操作，系统应利用流式处理机制避免将大文件全量加载入内存，减少内存峰值占用。上传任务和分片状态需要具备持久化能力，以便在客户端网络中断后继续上传缺失分片。

在可维护性方面，后端代码需要按认证、用户、文件、目录、分享、回收站、管理员、日志和系统状态等功能模块清晰划分。控制器只负责解析请求和转换响应，核心业务集中在服务层实现；数据库表结构应做到字段含义清晰、约束合理，方便后期维护和 Schema 演进。

#### 3.3.3 数据字典

本系统涉及的核心数据对象主要包括用户信息、文件内容、文件元数据、目录信息、上传任务、上传分片、回收站记录、分享记录、分享文件关联和操作日志等，以下分别对主要数据对象的字段组成和含义进行说明。

用户信息（users）是整个系统的基础数据对象，主要用于保存用户的账号凭据、个人资料、登录安全状态和存储配额信息，是登录鉴权、文件归属判断和存储限额控制的核心依据。其主要字段包括用户主键 ID、用户名、邮箱、哈希后的密码、昵称、头像、存储配额、已用存储、上传预占用存储、账号状态、角色类型、登录失败次数、锁定截止时间、最后登录时间、最后登录 IP、创建时间和更新时间。

文件内容（file_contents）用于保存物理文件内容的索引信息，是秒传去重和内容寻址存储的基础。其主要字段包括内容主键 ID、MD5 哈希、SHA256 哈希、文件大小、实际存储路径、MIME 类型、引用计数和创建时间。多个用户文件记录可以引用同一个内容对象，从而避免相同内容被重复存储。

文件元数据（files）是文件管理功能的核心数据对象，用于保存每一个用户可见文件的描述性信息，而不直接存储文件二进制内容。其主要字段包括文件主键 ID、所属用户 ID、关联的内容 ID、所属文件夹 ID、文件名、扩展名、文件大小、MIME 类型、完整路径、收藏标记、下载次数、最后访问时间、创建时间和更新时间。

目录信息（folders）用于维护用户的目录树结构，是目录导航和文件路径组织的基础数据表。其主要字段包括目录主键 ID、所属用户 ID、父目录 ID（根目录以 0 表示）、目录名称、完整路径、目录深度、子项数量、创建时间和更新时间。通过父目录 ID 字段形成的递归引用关系，可以构建出任意层级深度的目录树结构。

上传任务（upload_tasks）用于支持大文件分片上传和断点续传机制，保存每个进行中、已完成、已取消或已过期上传任务的总体状态。其主要字段包括上传任务 ID、用户 ID、目标文件夹 ID、文件名、文件大小、文件 MD5、分片大小、总分片数、预占用字节数、临时存储路径、任务状态、过期时间、完成时间、失败原因、创建时间和更新时间。上传分片（upload_task_chunks）则以任务 ID 和分片索引作为联合主键，记录每个分片是否已经上传成功。

回收站记录（trash）用于保存软删除文件或目录的恢复信息。其主要字段包括回收站记录 ID、用户 ID、项目类型、原项目 ID、项目名称、项目大小、关联内容 ID、原所属文件夹 ID、原完整路径、项目完整数据备份、删除时间和过期时间。通过回收站表，系统可以在彻底删除之前恢复误删项目，也可以在过期清理时减少内容引用计数并释放物理存储。

分享记录（shares）用于保存用户发起的分享操作的基础信息，是外链分享功能的数据基础。其主要字段包括分享 ID、分享短码、分享者用户 ID、访问密码哈希、权限类型、访问次数、下载次数、分享状态、过期时间、创建时间和更新时间。分享文件关联（share_files）用于描述某个分享包含的文件或目录，主要字段包括关联记录 ID、分享 ID、项目类型、项目 ID 和创建时间。该设计使一个分享可以关联一个或多个文件或目录，并支持后续扩展分享目录浏览能力。

操作日志（operation_logs）用于记录用户上传、下载、删除、分享等关键操作，主要字段包括日志 ID、用户 ID、操作类型、目标类型、目标 ID、目标名称、操作详情、IP 地址、客户端信息和创建时间。操作日志为问题排查、安全审计和运维统计提供基础数据。

上述核心数据对象明确了主要字段结构和含义，后续数据库设计、接口定义和业务逻辑实现均以此为基础。

## 第4章 系统设计

### 4.1 系统架构设计

本系统采用 RESTful 后端服务与桌面客户端分离的架构，将客户端展示与后端业务能力解耦。后端通过标准化 HTTP 接口暴露认证、文件、目录、分享、回收站、日志和管理能力；桌面端基于 Qt/QML 实现普通用户、访客和管理员界面，并通过统一网络层调用后端接口。这样可以保持接口契约清晰，便于后期维护、测试和功能扩展。

系统整体由客户端接入层、过滤器层、控制器层、服务层和数据存储层组成。客户端接入层通过 RESTful HTTP 请求调用系统能力；过滤器层基于 Drogon 全局过滤器完成 JWT 鉴权、管理员鉴权、分享令牌鉴权和接口限流；控制器层负责解析请求并返回统一响应；服务层划分为认证、用户、文件、目录、分享、回收站、管理员、日志、健康检查和系统信息等模块，集中处理业务逻辑；数据存储层由 MySQL、Redis 和本地文件系统组成，其中 MySQL 保存结构化业务数据，Redis 保存刷新令牌、黑名单、登录失败计数、分享访问状态和限流计数，本地文件系统按内容哈希保存物理文件对象。

### 4.2 系统模块设计

系统按角色划分为普通用户端和管理员端两大模块，并包含访客分享访问页面。普通用户端包含账号管理、用户中心、文件管理、目录管理、分享管理、回收站管理和存储空间查看七个子模块。账号管理包括注册、登录、刷新令牌和登出；文件管理支持分片上传（初始化、上传分片、完成合并、取消上传）、秒传去重、下载、重命名、移动、复制、删除和搜索；目录管理提供创建目录、目录树和面包屑路径查询；分享管理覆盖生成分享链接、访问密码、有效期、查看/下载权限、我的分享、取消分享、浏览和下载分享文件以及保存分享内容；回收站管理包括回收站列表、批量恢复和彻底删除/清空。管理员端包含用户管理、存储统计、分享管理、操作日志和系统状态等子模块。用户管理支持查看用户列表、搜索用户、查看用户详情、禁用或启用账号、修改角色、调整用户可用空间和软删除用户；存储统计提供全平台统计和各用户占用排行；分享管理支持查看分享列表、分享详情和强制取消分享；系统状态包括系统概览以及数据库、Redis 和磁盘的运行状态。图4-1 和图4-2 分别展示普通用户端和管理员端的功能结构。

### 4.3 系统功能设计

#### 4.3.1 用户认证模块设计

用户认证模块是整个系统的安全基础，主要负责用户注册、登录、令牌刷新、登出和接口鉴权。用户注册时，后端校验用户名和邮箱唯一性，使用 libsodium 的 Argon2id 算法生成密码哈希，并在 `users` 表中写入默认存储配额。用户登录时，后端校验账号状态、锁定时间和密码哈希；登录成功后签发 Access Token 与 Refresh Token，并将刷新令牌写入 Redis。登录失败时系统会累计失败次数，达到阈值后短时锁定账号，从而降低暴力破解风险。

JWT 过滤器是认证模块与各业务控制器之间的桥梁。需要登录的接口统一通过 `Authorization: Bearer <access_token>` 携带访问令牌，过滤器负责验证签名、过期时间和黑名单状态，并将用户 ID、用户名和角色等上下文写入请求对象。管理员接口在 JWT 校验之后还会经过管理员鉴权过滤器，只有角色为管理员的账号才能继续访问。Refresh Token 采用 Redis 存储和轮换机制，登出时会使访问令牌进入黑名单并删除刷新令牌，实现较完整的登录态生命周期管理。

#### 4.3.2 文件与目录模块设计

**（1）文件管理模块**

文件管理模块是普通用户最核心的业务模块，围绕文件列表、搜索、上传、下载、重命名、移动、复制和删除等操作展开设计。后端通过 `FileController` 暴露 `/api/file/*` 系列接口，控制器仅负责解析请求和转换响应，具体业务由 `FileService` 完成。

在文件列表展示方面，系统根据当前用户 ID、目录 ID、类型筛选、排序字段和分页参数，从 `files` 与 `folders` 表中查询当前目录下的文件和文件夹，并以统一 DTO 返回给客户端。搜索功能通过文件名和目录名索引支持按关键词、类型和目录范围检索。文件详情接口会返回文件或目录元数据及面包屑路径，便于客户端构建导航视图。

在文件变更方面，重命名会校验名称长度、非法字符、保留名称以及同目录冲突；移动和复制支持批量操作，其中复制文件时不会重复写入物理文件，而是复用 `file_contents` 中的内容对象并增加引用计数。删除操作采用回收站机制：普通删除会将文件或目录的恢复信息写入 `trash` 表，并从正常文件或目录列表中移除；彻底删除时才会减少内容引用计数，引用计数归零后再清理物理文件。

**（2）目录管理模块**

目录管理模块负责维护用户的多级目录树结构。系统通过 `folders` 表保存目录名称、父目录 ID、完整路径、深度和子项数量，其中根目录以 `parent_id = 0` 表示。创建目录时，后端校验目标父目录是否属于当前用户，并通过 `(user_id, parent_id, name)` 唯一约束保证同级目录名称不重复。

目录树接口通过递归查询返回当前用户的目录层级结构，面包屑接口返回从根目录到指定目录的路径链路。为了避免异常数据导致无限递归，服务层会限制目录树深度并在面包屑构建过程中检测循环引用。目录删除不直接丢弃数据，而是进入回收站流程，保留恢复所需的原始路径和项目数据。

![图4-4 创建目录流程图](assets/创建目录流程图.png)

**（3）文件上传模块**

文件上传模块是整个系统中技术实现复杂度最高的部分。当前系统采用统一的分片上传流程，默认分片大小为 5MB，并支持初始化上传、上传分片、完成合并和取消上传四个阶段。上传初始化请求会携带文件名、文件大小、目标目录、文件 MD5 等信息，后端首先进行配额预检查，并根据 MD5 查询 `file_contents` 表。如果相同内容已经存在，系统无需再次上传物理文件，只需要创建新的 `files` 记录并增加内容引用计数，即可完成秒传。

如果文件内容不存在，系统会创建 `upload_tasks` 记录并预占用用户存储空间。客户端随后按分片索引上传数据，后端将分片写入临时目录，并在 `upload_task_chunks` 表中记录已上传分片。断点续传的关键在于初始化接口会返回已上传分片列表，客户端恢复上传时只需补传缺失分片。所有分片完成后，后端通过 `AssemblyWorkerPool` 控制并发合并，将临时分片按顺序合并为完整文件，计算并校验内容哈希，随后写入 `file_contents` 和 `files` 表，释放预占用空间并将上传任务标记为完成。

#### 4.3.3 分享模块设计

文件分享模块允许用户将自己的文件或目录通过外链方式分享给他人。创建分享时，后端在 `shares` 表中写入分享短码、分享者 ID、可选访问密码哈希、权限类型、有效期和状态，并在 `share_files` 表中写入被分享的文件或目录关联。分享权限支持查看和下载两类，分享状态支持有效、取消和过期。

公开访问分享时，访客首先通过分享短码和可选密码调用访问接口。后端校验分享是否存在、是否过期、是否取消以及密码是否正确；校验通过后签发短期分享访问令牌。后续浏览分享目录或下载分享文件时，访客需要在 `X-Share-Token` 请求头中携带该令牌，由分享鉴权过滤器完成校验。系统会分别记录浏览次数和下载次数，并使用 Redis 对分享密码尝试进行限流，避免暴力猜测分享密码。

**（1）回收站模块**

回收站模块用于降低误删除风险。普通删除操作不会立即物理删除文件，而是将项目类型、原项目 ID、原路径、项目名称、内容 ID 和完整数据备份写入 `trash` 表。用户可以分页查看回收站项目，也可以批量恢复、彻底删除或清空回收站。恢复时，如果原目录不存在，系统会回退到根目录；如果名称发生冲突，系统会自动生成新的名称以避免覆盖现有文件。系统还通过定时清理任务删除过期回收站记录和过期上传任务，保证长期运行时临时数据不会无限累积。

#### 4.3.4 管理员与运维模块设计

**（1）用户管理模块**

管理员用户管理模块通过 `/api/admin/users` 系列接口提供平台账号维护能力。管理员可以查看用户列表、按条件筛选用户、查看用户详情和存储使用情况，也可以修改用户状态、修改角色、调整用户可用空间或软删除用户。用户状态在数据库中以数值表示，包括禁用、正常和锁定；角色也以数值表示，包括普通用户和管理员。所有管理员接口都需要同时通过 JWT 鉴权和管理员角色鉴权。

**（2）存储统计与分享管理模块**

存储统计模块通过聚合 `users`、`files`、`file_contents`、`folders` 等表，统计全平台用户数、文件数、内容对象数、存储占用和各用户使用情况。由于系统采用内容寻址和引用计数，逻辑文件大小与物理内容占用并不总是完全一致，因此统计时需要区分用户视角的文件大小和物理内容对象的实际存储。

分享管理模块允许管理员查看全平台分享列表、查看单个分享详情并强制取消违规分享。该功能主要用于处理公开链接滥用、误分享和过期分享治理等场景，能够与分享状态、访问次数和下载次数统计结合，为平台安全运维提供依据。

**（3）系统状态与日志模块**

系统状态模块用于查看服务运行时间、版本信息、数据库连接状态、Redis 连接状态和磁盘空间等指标；健康检查接口可公开访问，用于部署环境中的存活检测。操作日志模块记录用户上传、下载、删除、分享等关键操作，并支持分页查询。通过系统状态和操作日志，管理员可以更及时地定位异常请求、追踪重要操作并评估系统运行情况。

#### 4.4.1 数据库概念结构设计

根据系统需求分析阶段对各核心数据对象的梳理，系统主要涉及用户（Users）、文件内容（FileContents）、文件元数据（Files）、目录（Folders）、上传任务（UploadTasks）、上传分片（UploadTaskChunks）、回收站（Trash）、分享（Shares）、分享文件关联（ShareFiles）和操作日志（OperationLogs）等实体，以及实体之间的若干关联关系。

## 第5章 系统实现

本章结合当前项目实现，从后端 RESTful 服务和 Qt/QML 桌面客户端两个层面说明系统主要功能。后端代码按照控制器、过滤器、服务层、数据模型和存储抽象划分，控制器负责路由绑定和请求响应转换，服务层负责业务规则、数据库事务和 Redis 状态维护；桌面端通过 `AuthShell`、`OwnerShell`、`VisitorShell` 和 `AdminShell` 区分认证、普通用户、访客分享和管理员场景，并通过各类 Manager 与后端接口交互。

### 5.1 用户与认证模块功能实现

（1）注册与登录实现

账号注册和登录由 `AuthController` 暴露 HTTP 接口，并由 `AuthService` 完成业务处理。注册时，系统接收用户名、邮箱和密码等字段，先通过 DTO 进行格式校验，再检查 `users` 表中用户名和邮箱是否已经存在。校验通过后，服务层调用 libsodium 的 Argon2id 算法生成密码哈希，并写入用户默认昵称、头像、存储配额、账号状态和角色等基础字段。桌面端对应 `RegisterPage` 页面，注册成功后可返回登录页继续认证。

登录接口支持用户名或邮箱登录。服务层会读取用户账号状态、锁定截止时间和密码哈希，若账号被禁用或处于锁定期则直接拒绝登录；若密码校验失败，则累计失败次数，并在达到阈值后设置短时锁定状态；若认证成功，则重置失败计数，签发 Access Token 与 Refresh Token，并返回用户 ID、用户名、昵称、角色等会话信息。桌面端 `LoginPage` 通过 `AuthService` 发起登录请求，`SessionStore` 保存登录态，`ShellController` 根据用户角色进入普通用户界面或管理员界面。

（2）令牌生命周期与鉴权过滤

令牌相关逻辑集中在 `TokenService` 中实现。Access Token 采用 JWT 形式携带用户 ID、用户名、角色和过期时间等声明，普通业务接口统一通过 `JwtAuthFilter` 校验 `Authorization: Bearer <token>` 请求头。Refresh Token 存储在 Redis 中，用于刷新访问令牌；刷新成功后，旧刷新令牌被替换，新的 Access Token 与 Refresh Token 返回客户端。登出接口会删除 Redis 中的刷新令牌，并将当前访问令牌加入黑名单，使其在过期前也无法继续访问受保护接口。

系统还为不同访问边界提供独立过滤器。管理员接口在 JWT 校验之后继续经过 `AdminAuthFilter`，只有角色为管理员的账号才能访问 `/api/admin/*` 路由；公开分享浏览和下载接口使用 `ShareAuthFilter` 校验 `X-Share-Token`，避免访客访问流程与登录用户 JWT 混用。桌面端网络层通过 `RequestFactory` 根据请求类型自动附加用户令牌、分享令牌或两者组合，从客户端侧保证接口调用的认证上下文清晰。

（3）个人资料、密码与存储空间实现

用户中心功能由 `UserController` 和 `UserService` 实现，包含个人资料查询、资料更新、密码修改和存储空间查看。资料更新接口支持修改昵称和头像 URL，服务层只更新请求中明确传入的字段，并同步更新时间。密码修改接口要求用户提交当前密码，校验通过后重新生成 Argon2id 哈希并更新 `users.password_hash`，避免客户端或数据库保存明文密码。

存储空间接口聚合 `users` 表中的 `storage_quota`、`storage_used` 和 `storage_reserved` 字段，并结合文件与目录统计返回已用空间、预占用空间、剩余配额、文件数和目录数。桌面端 `SettingsPage` 与 `ProfileManager` 负责展示用户资料和存储占用情况，用户修改资料或密码后会通过提示信息反馈操作结果。

### 5.2 文件传输模块功能实现

（1）分片上传初始化与秒传判断

文件上传由 `FileController` 提供初始化、上传分片、完成上传和取消上传四类接口，对应路径包括 `/api/file/upload/init`、`/api/file/upload/chunk`、`/api/file/upload/complete` 和取消上传接口。客户端选择文件后，`TransferManager` 首先提交文件名、文件大小、目标目录和文件 MD5。`FileService` 根据当前用户的已用空间和预占用空间进行配额检查，若上传后超过配额上限，则直接返回空间不足错误，避免无效分片写入。

初始化阶段还会根据文件哈希查询 `file_contents` 表。如果系统已经存在相同内容对象，服务层不再要求客户端上传分片，而是直接创建新的 `files` 元数据记录，增加内容对象引用计数，并返回秒传结果。若内容不存在，则创建 `upload_tasks` 记录，写入任务 ID、目标目录、文件名、文件大小、分片大小、总分片数、临时路径、预占用字节数和过期时间，同时查询 `upload_task_chunks` 表返回已上传分片列表，为断点续传提供依据。

（2）分片写入、断点续传与后台合并

分片上传接口按任务 ID 和分片索引接收二进制数据。服务层先校验上传任务是否属于当前用户、是否仍处于进行中状态，再将分片写入任务临时目录，并在 `upload_task_chunks` 表中记录该分片已完成。客户端恢复上传时重新调用初始化接口即可获得已上传分片索引，只补传缺失部分，从而实现断点续传。

全部分片上传完成后，客户端调用完成上传接口。后端通过 `AssemblyWorkerPool` 控制同一上传任务的合并并发，避免同一任务被重复合并；合并过程按分片顺序读取临时文件，生成完整文件后计算 MD5 和 SHA256，并与初始化阶段提交的哈希进行校验。校验通过后，系统通过 `IFileStorage` 的本地实现将文件移动到内容寻址存储路径，写入 `file_contents` 和 `files` 表，释放预占用空间并更新用户已用空间。若用户取消上传或任务过期，系统会删除临时分片、更新任务状态并释放预占用空间；`CleanupService` 和定时任务负责清理过期上传任务。

（3）文件下载与 Range 断点下载

文件下载接口分为下载信息查询和实际文件流下载。客户端下载前可先获取文件名、大小、MIME 类型等元数据，再调用下载接口获取文件内容。服务层会校验文件归属，确认当前用户只能下载自己名下的文件；校验通过后，通过 `IFileStorage` 定位内容寻址文件，并由下载响应逻辑返回 HTTP 文件流。

当请求头包含 `Range` 字段时，后端解析起止字节位置，只返回指定区间的文件内容，并设置 `206 Partial Content`、`Content-Range` 和 `Content-Length` 等响应信息。桌面端下载任务由 `TransferManager` 和 `DownloadTaskModel` 管理，传输中心页面展示下载进度、状态、失败原因，并支持取消、重试以及基于 Range 的暂停后继续下载。

（4）传输中心实现

桌面端单独实现了 `TransferCenterPage`，用于集中展示上传和下载任务。上传任务模型记录文件名、目标目录、已上传字节数、总字节数、状态和错误信息；下载任务模型记录保存路径、下载进度、暂停状态和完成状态。用户可以在传输中心查看正在进行和已经完成的任务，也可以执行取消、重试、暂停、继续和清理已完成任务等操作。该页面把文件传输从文件列表页面中拆分出来，便于用户在长时间上传或下载过程中继续浏览目录和管理文件。

### 5.3 文件与目录管理模块功能实现

（1）文件列表与资源管理器实现

普通用户的主要工作区由桌面端 `DriveBrowserPage` 承载，并通过 `OwnerShell` 进入。页面包含“我的网盘”“分享”和“回收站”等视图，其中“我的网盘”视图通过 `DriveMyFilesView` 展示文件与目录列表，工具栏和右键菜单提供刷新、上传、下载、新建文件夹、重命名、移动、复制、分享和删除等入口。后端列表接口由 `FileService` 同时查询 `files` 和 `folders` 表，根据用户 ID、目录 ID、分页参数和排序字段返回统一列表项，列表项包含 ID、名称、类型、大小、更新时间、MIME 类型和下载次数等信息。

桌面端通过 `DriveManager` 持有当前目录 ID、列表模型、排序方式、选择状态和加载状态。目录 ID 为 0 时表示根目录，切换目录时页面不会重建，只更新当前目录和列表模型；当请求失败或数据为空时，页面会展示对应状态提示，并允许用户重新加载。所有后端查询都带有用户 ID 权限边界，普通用户无法通过构造请求查看他人文件或目录。

（2）目录树与面包屑导航实现

目录管理由 `FolderController` 和 `FolderService` 实现，主要包括创建目录、目录树查询、面包屑路径查询和目录重命名。创建目录时，服务层先校验父目录是否属于当前用户，再检查同一父目录下是否已有同名目录；校验通过后写入 `folders` 表，并计算目录完整路径、深度和父目录子项数量。

目录树接口基于 `folders` 表中的 `parent_id` 关系返回树形结构，服务层在构建过程中限制最大深度并检测异常循环，避免坏数据造成无限递归。面包屑接口从当前目录逐级回溯父目录，生成从根目录到当前目录的路径链路。桌面端使用 `FolderTreePanel` 展示目录选择树，使用 `BreadcrumbBar` 展示当前位置；用户点击目录树节点或面包屑节点后，文件列表、目录树和面包屑会同步刷新。

（3）重命名、移动、复制和搜索实现

文件和目录重命名会分别更新 `files` 或 `folders` 表中的名称和路径字段，服务层会校验名称长度、非法字符、保留名称和同级重名情况。移动接口支持文件和目录批量移动，移动目录时会阻止将目录移动到自身或子目录下，避免破坏目录树结构；复制接口支持文件和目录批量复制，其中复制文件时只新增逻辑文件记录并增加 `file_contents.ref_count`，不会重复写入物理文件内容。

搜索接口支持按关键词、类型和目录范围检索文件或目录，并返回分页结果。桌面端工具栏维护搜索关键词和排序方式，用户输入关键词后由 `DriveManager` 调用后端搜索接口并刷新列表；在多选状态下，批量移动、复制、删除和分享等操作会把多个项目 ID 一次性提交给后端，后端返回每个项目的处理结果，便于客户端展示成功或失败原因。

### 5.4 回收站模块功能实现

回收站功能由 `TrashController` 和 `TrashService` 实现，后端提供回收站列表、批量恢复、批量彻底删除和清空回收站接口。普通删除不会立即释放存储空间，而是把项目类型、原项目 ID、项目名称、原目录、原路径、大小、内容引用和必要的 JSON 备份写入 `trash` 表，并从正常文件或目录列表中移除。桌面端 `DriveTrashView` 负责展示回收站记录，用户可以多选项目执行恢复或彻底删除，也可以一次性清空回收站。

恢复操作会校验回收站记录是否属于当前用户，并优先恢复到原父目录；如果原父目录已经不存在，则恢复到根目录；如果目标目录中存在同名文件或目录，服务层会自动生成 `name (n).ext` 或 `name (n)` 形式的新名称，避免覆盖现有数据。当前实现中，文件夹恢复只恢复文件夹记录本身，不递归恢复文件夹子树，这一点与服务层 V1 规则保持一致。

彻底删除会永久移除回收站记录，并根据文件内容引用计数决定是否删除物理文件。对于文件项目，服务层减少 `file_contents.ref_count`，当引用计数归零时再通过 `IFileStorage` 删除本地内容寻址文件，并更新用户已用空间；对于清空回收站操作，系统会批量处理当前用户所有回收站记录并汇总释放空间。后台清理服务还会定期处理过期回收站记录，防止长期运行后临时和删除数据无限累积。

### 5.5 分享模块功能实现

（1）分享创建与所有者管理

分享功能由 `ShareController` 和 `ShareService` 实现，所有者侧接口包括创建分享、查询我的分享列表、查看分享详情、更新分享设置和取消分享。用户在文件管理页面选择文件或目录后，可以设置有效期、访问密码和权限类型。服务层生成随机分享短码，将分享主体写入 `shares` 表，将被分享的文件或目录写入 `share_files` 表；如果设置了访问密码，系统保存 Argon2id 哈希而不是明文密码。创建成功后，桌面端显示分享短码、分享链接、过期时间和权限信息，方便用户复制分发。

“分享”视图由 `DriveSharedView` 展示当前用户创建的分享记录，列表中包含分享码、分享状态、有效期、浏览次数和下载次数等信息。用户可以查看分享详情、复制链接、修改权限或有效期，也可以批量取消分享。取消分享时，服务层将分享状态更新为取消，并使相关公开访问状态失效，之后访客再次访问该分享会收到链接无效提示。

（2）访客访问、浏览与下载实现

访客访问分享时，首先通过分享短码进入 `VisitorShell`，桌面端 `ShareVerifyPage` 负责展示密码输入和访问校验。后端公开访问接口会查询 `shares` 表，检查分享是否存在、是否过期、是否已取消以及密码是否正确；对设置密码的分享，Redis 会记录密码尝试次数并进行限流，降低暴力猜测风险。校验通过后，系统签发短期 Share Token，访客后续请求通过 `X-Share-Token` 请求头访问。

分享浏览接口由 `ShareAuthFilter` 校验令牌后返回分享中的文件和目录列表，并更新浏览次数；分享下载接口会再次检查分享状态和权限类型，只有权限允许下载时才通过本地内容寻址存储返回文件流并增加下载次数。桌面端 `ShareBrowsePage` 展示访客可见内容，支持浏览分享目录、下载允许下载的文件，并在权限不足或分享失效时给出提示。

（3）保存分享内容到个人网盘

当前项目还实现了分享内容保存到个人网盘的接口 `/api/share/save/{share_id}`。该接口同时经过 `JwtAuthFilter` 和 `ShareAuthFilter`，要求调用者既是已登录用户，又已经通过该分享的访问校验。保存时，服务层依据分享中的文件或目录关联创建当前用户自己的文件记录或目录记录；对于文件内容，系统继续复用 `file_contents` 内容对象并维护引用计数，不重复写入物理文件。该功能使访客在获得分享授权后，可以把有价值的文件保存到自己的网盘空间中，同时仍受用户配额和权限边界约束。

### 5.6 管理后台与运维模块功能实现

（1）管理员用户管理实现

管理员功能由 `AdminController` 和 `AdminService` 实现，所有 `/api/admin/*` 接口都需要先通过 JWT 鉴权，再通过管理员角色鉴权。管理员登录后，桌面端根据角色进入 `AdminShell` 和 `AdminPage`，页面通过标签页组织用户、分享和系统功能。用户管理接口支持分页查询、关键词搜索、状态筛选和角色筛选，返回用户 ID、用户名、邮箱、昵称、存储使用量、账号状态和角色等字段。

管理员可以修改普通用户状态、调整用户角色、设置用户可用空间和软删除用户。服务层对关键操作设置保护规则，例如禁止管理员禁用或降级自己，防止系统中最后一个管理员被降级或禁用，并在执行状态变更、角色变更等操作时写入操作日志。桌面端 `UserTab` 和 `AdminManager` 负责展示用户列表、提交管理操作并显示成功或失败提示。

（2）分享管理、存储统计与系统状态实现

管理员分享管理接口支持查看全平台分享列表、查看单个分享详情和强制取消分享。分享详情包含分享码、分享者、被分享项目、有效期、浏览次数、下载次数和状态等信息，管理员可据此处理违规分享或失效链接。存储统计接口聚合用户、文件、目录和内容对象数据，区分逻辑文件大小与物理内容对象占用，为后台展示用户数量、文件数量、内容对象数量和整体存储使用情况提供数据来源。

系统状态接口返回服务运行时间、版本信息、数据库连接状态、Redis 连接状态和磁盘空间等指标。桌面端 `SystemTab` 汇总展示概览统计、全局存储统计和组件状态，使管理员能够在一个页面中了解系统当前运行情况。对于部署环境，公开健康检查接口 `/api/health` 可用于存活检测；登录用户也可以通过 `/api/system/info` 查看系统版本、Drogon 版本、构建时间、连接统计和存储统计等信息。

（3）操作日志与后台清理实现

操作日志由 `OperationLogController` 和 `OperationLogService` 实现，后端在登录、登出、上传、下载、删除、恢复、重命名、移动、复制、创建分享、取消分享和管理员操作等关键路径写入 `operation_logs` 表。日志记录包含用户 ID、操作类型、目标类型、目标 ID、目标名称、JSON 详情、IP 地址、客户端信息和创建时间。桌面端管理界面通过操作日志标签页分页展示日志内容，便于问题追踪和安全审计。

后台清理能力由 `CleanupService` 和定时任务实现，主要处理过期上传任务和过期回收站记录。清理上传任务时，系统会释放预占用空间、删除临时分片并更新任务状态；清理回收站记录时，系统按照彻底删除规则减少引用计数并释放物理存储。通过这些后台任务，系统能够在无人值守情况下维持上传临时目录、回收站数据和用户存储统计的一致性。

### 6.5 测试总结

测试结果显示，系统核心业务流程运行稳定，普通用户、访客和管理员相关功能基本达到设计目标。用户认证与鉴权、令牌刷新与登出、文件上传（包含分片断点续传和秒传去重机制）、文件下载、目录管理、文件分享生成与访问控制、分享内容保存、回收站恢复与彻底删除，以及管理员的用户管理、分享管理、操作日志、存储统计和系统状态查询等功能，均通过功能性验证。

安全性测试中，用户访问他人文件、普通用户访问管理员接口、令牌过期、登出失效、登录失败锁定和分享密码错误等场景均能被正确拦截或处理，说明 JWT 鉴权、Redis 状态管理和角色权限控制符合设计要求。存储配额限制在上传初始化阶段即可生效，能够避免超额写入和无效分片上传。

测试过程也暴露出一些不足。当前测试主要在本地单机环境下进行，缺少大规模高并发压力测试，Drogon 在实际高并发文件传输场景下的吞吐量和延迟表现尚未用充分数据量化；系统虽然已有操作日志和健康检查，但监控告警、容量趋势分析和容灾恢复能力仍较基础；桌面端已经覆盖登录、文件浏览、传输中心、分享访问、回收站和管理后台等主要页面，但拖拽上传、缩略图预览和文件在线预览等体验能力还需要后续补充。综合来看，系统能够满足毕业设计阶段的实现目标，主要功能流程具有可演示性和基础实用性；若用于生产环境，还需要继续完善性能压测、监控运维和客户端体验。

## 总结与展望

本文围绕私有化网络磁盘系统的设计与实现展开，结合用户文件管理、大文件传输可靠性、分享链接控制、回收站恢复和管理员运维管理等需求，完成了需求分析、总体架构设计、数据库设计、模块设计与实现以及系统测试。系统定位为高性能私有化网盘系统，后端以 C++23 和 Drogon Web 框架为核心，桌面端以 Qt 6 和 QML 为主要技术，数据存储层由 MySQL、Redis 和本地内容寻址文件系统组成，基本实现了面向普通用户、访客和管理员的完整业务支撑能力。

在功能实现方面，系统完成了用户注册登录、Access Token 与 Refresh Token 生命周期管理、JWT 鉴权和管理员角色鉴权、个人资料与存储空间统计、多级目录树与面包屑路径、文件分片上传、断点续传、秒传去重、后台分片合并、文件下载与 Range 断点下载、文件重命名、移动、复制、搜索、回收站软删除与恢复、文件外链分享、分享密码访问、分享浏览与下载、分享内容保存、操作日志、健康检查和系统状态查询等功能。桌面端实现了认证界面、网盘资源管理器、传输中心、访客分享访问页、个人设置页和管理员后台页面；管理员侧实现了用户管理、角色与状态变更、用户可用空间调整、全局存储统计、操作日志查看、分享审核与强制取消等运维能力。文件上传和存储部分通过 `upload_tasks` 与 `upload_task_chunks` 持久化分片状态，通过 `file_contents` 内容哈希和引用计数实现秒传与去重，体现了网盘核心场景下的工程化处理思路。

从测试结果看，当前版本基本达到毕业设计预期目标。系统主要功能流程能够稳定运行，RESTful 接口的数据交互逻辑清晰，文件存储、目录管理、分享访问控制、回收站恢复、权限边界和管理员操作等关键业务场景下的行为符合设计预期。测试结果验证了所采用技术路线和系统架构的可行性，也说明 Drogon 框架适用于文件服务类后端系统。就毕业设计要求而言，本系统具有较好的完整性、可演示性和基础实用价值。

受开发周期、测试环境和课题范围限制，系统仍有不足。文件版本历史、WebDAV 协议支持、文件在线预览和缩略图生成尚未实现；高并发压力测试和安全渗透测试开展不够充分，大规模并发文件传输场景下的吞吐量和稳定性还需要更多数据验证；操作日志、健康检查和系统状态接口已经具备，但监控告警、容量趋势分析、自动备份和容灾恢复机制仍需完善。当前系统已完成核心后端能力和主要桌面端交互，若要达到长期生产环境使用标准，还需要继续补充客户端体验、性能压测和运维治理能力。

综上，本文完成了一个基于 C++23、Drogon 与 Qt/QML 的私有化网络磁盘系统，为构建文件存储类 RESTful 后端服务和桌面客户端提供了较完整的工程实践样例，也为后续扩展对象存储、客户端体验优化和运维能力完善奠定了基础。
