# Disk 桌面客户端 - 测试计划

## 1. 测试概述

**视觉样式：使用 Qt Quick Controls 平台默认样式；不在文档中引入 AppTheme/Colors 等自定义样式模块。**


### 1.1 测试目标

本测试计划旨在确保 Qt/QML 桌面客户端的功能正确性、稳定性和用户体验。测试覆盖以下方面：

1. **C++ 业务逻辑测试**：验证 API 客户端、服务层、ViewModel 的业务逻辑正确性
2. **QML UI 测试**：验证界面显示、交互和视觉反馈
3. **API 集成测试**：验证与后端服务的通信正确性
4. **性能测试**：验证响应速度和资源占用
5. **兼容性测试**：验证跨平台兼容性

**核心原则**：测试分离匹配架构分离。
- C++ 单元测试覆盖所有业务逻辑（服务、ViewModel、API 客户端）
- QML UI 测试仅覆盖界面呈现和交互
- QML/JavaScript 不包含业务逻辑，因此不需要业务逻辑测试

void ApiClientTest::test_getRequest_buildsCorrectUrl() {
    MockApiClient client;
    client.setBaseUrl("http://localhost:8080");
    
    QSignalSpy spy(&client, &MockApiClient::requestSent);
    client.get("/api/file/list", QUrlQuery("page=1"));
    
    QCOMPARE(spy.count(), 1);

void ApiClientTest::test_expiredToken_autoRefresh() {
    MockApiClient client;
    MockTokenStore tokenStore;
    tokenStore.setAccessToken("expired_token", QDateTime::currentDateTime().addSecs(-1));
    tokenStore.setRefreshToken("valid_refresh_token", QDateTime::currentDateTime().addDays(5));
    
    client.setTokenProvider([&]() { return tokenStore.accessToken(); });
    
    // 模拟返回 TokenExpired 错误
    client.setMockResponse("/api/file/list", QJsonDocument::fromJson(R"({
        "code": 40108,
        "message": "令牌已过期"
    })"));
    
    // 模拟刷新成功
    client.setMockResponse("/api/auth/refresh", QJsonDocument::fromJson(R"({
        "code": 0,
        "data": {
            "access_token": "new_access_token",
            "expires_in": 7200
        }
    })"));
    
    auto future = client.get("/api/file/list");
    future.waitForFinished();
    
    // 验证 Token 被刷新
    QCOMPARE(tokenStore.accessToken(), QString("new_access_token"));
}

class IntegrationTest : public QObject {

        // 8. 删除文件

        QVERIFY(deleteResult.has_value());

    }

## 4. QML UI 测试策略

**本节覆盖 QML 层的 UI 测试。QML 测试使用 Qt Quick Test 框架，测试范围仅限于：UI 组件渲染、用户交互、视觉反馈。**

**重要原则**：
- QML 测试不包含业务逻辑测试（业务逻辑在 C++ 单元测试中覆盖）
- QML 测试验证 UI 组件正确绑定到 ViewModel 属性
- QML 测试验证用户交互（点击、输入、滚动）正确触发 ViewModel 方法
- QML 测试验证视觉状态（加载、错误、空状态）正确显示

### 4.3 QML 测试注意事项

1. **使用 Mock ViewModel**：QML 测试应使用 Mock ViewModel，不依赖真实服务
2. **不测试业务逻辑**：业务逻辑在 C++ 单元测试中覆盖，QML 测试只验证 UI 行为
3. **测试异步操作**：使用 `tryCompare` 和 `waitForRendering` 处理异步更新
4. **隔离测试**：每个测试用例应独立，不依赖其他测试的状态

### 9.2 CI/CD 集成

```yaml
# .github/workflows/test.yml
name: Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-22.04, windows-2022, macos-13]
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Install Qt
        uses: jurplel/install-qt-action@v3
        with:
          version: '6.5.0'
          
      - name: Configure
        run: cmake -B build -DCMAKE_BUILD_TYPE=Debug
        
      - name: Build
        run: cmake --build build
        
      - name: Run Unit Tests
        run: ctest --test-dir build --output-on-failure
        
      - name: Upload Test Results
        if: always()
        uses: actions/upload-artifact@v3
        with:
          name: test-results-${{ matrix.os }}
          path: build/test-results/
```
