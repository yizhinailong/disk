# Disk 桌面客户端 - 架构设计

## 1. 设计概述

**视觉样式：使用 Qt Quick Controls 内置 Fusion 样式，以获得跨平台一致的视觉效果并支持 `background` / `contentItem` 自定义。不在文档中引入 AppTheme/Colors 等自定义样式模块。**

> 注：Windows/macOS 原生样式不支持控件自定义，设置 background 或 contentItem 会产生运行时警告。


### 1.1 设计目标

本文档定义 Qt/QML 桌面客户端的架构设计，主要目标包括：

1. **清晰的分层架构** - 表现层、业务层、数据层职责分明
2. **MVVM 模式** - QML View + C++ ViewModel，数据绑定驱动 UI
3. **可维护性** - 依赖注入，便于模块替换与调试
4. **可扩展性** - 模块化设计，功能可插拔
5. **跨平台兼容** - 抽象平台相关代码

### 1.2 架构原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 每个类只负责一个功能 |
| **依赖倒置** | 高层模块不依赖低层模块，都依赖抽象 |
| **接口隔离** | 使用小而专注的接口 |
| **开闭原则** | 对扩展开放，对修改关闭 |

#### 3.3.3 Qt MVVM 模式

Qt MVVM 模式将应用分为三层：ViewModel（视图模型）、View（视图）和 Model（模型）。核心原则是 **QML/JavaScript 只负责 UI 展示，所有业务逻辑都在 C++ 层处理**。

**架构原则：**

| 层级 | 职责 | 技术实现 |
|------|------|----------|
| ViewModel (C++) | 业务逻辑、状态管理、数据绑定 | QObject + Q_PROPERTY + Q_INVOKABLE |
| View (QML) | UI 渲染、用户交互 | QML 组件、属性绑定 |
| Model (C++) | 数据模型、API 调用 | QAbstractListModel、数据结构 |

**LoginViewModel 示例（C++ 层 - 处理所有业务逻辑）：**

```cpp
// viewmodels/LoginViewModel.h

#include "storage/TokenStore.h"

    Q_PROPERTY(QString password READ password WRITE setPassword NOTIFY passwordChanged)
    Q_PROPERTY(bool loading READ loading NOTIFY loadingChanged)
    Q_PROPERTY(QString errorMessage READ errorMessage NOTIFY errorChanged)

public:
    explicit LoginViewModel(
        services::AuthService* authService,
        storage::TokenStore* tokenStore,
        QObject* parent = nullptr

    // 属性访问器
    QString username() const;
    void setUsername(const QString& value);
    
    QString password() const;
    void setPassword(const QString& value);
    
    bool loading() const;
    QString errorMessage() const;

    // QML 可调用的方法
    Q_INVOKABLE void login();
    Q_INVOKABLE void navigateToRegister();
    Q_INVOKABLE void clearError();

signals:
    void loginSuccess();
    void usernameChanged();
    void passwordChanged();
    void loadingChanged();
    void errorChanged();

private:
    void handleLoginResult(const api::ApiResult<api::LoginResponse>& result);

    storage::TokenStore* m_tokenStore;
    QString m_username;

**对应的 QML 视图（展示层 - 仅处理 UI 渲染）：**

```qml
// views/LoginView.qml
import QtQuick 2.15
import QtQuick.Controls 2.15
import QtQuick.Layouts 1.15
import disk.viewmodels 1.0

ColumnLayout {
    id: root
    
    // 由 C++ 层注入的 ViewModel
    required property LoginViewModel viewModel
    
    spacing: 16

        id: usernameField
        placeholderText: qsTr("用户名")
        text: viewModel.username
        onTextChanged: viewModel.username = text
        Layout.fillWidth: true
    }

    TextField {
        id: passwordField
        placeholderText: qsTr("密码")
        echoMode: TextInput.Password
        text: viewModel.password
        onTextChanged: viewModel.password = text
        Layout.fillWidth: true
    }

    Label {
        text: viewModel.errorMessage
        visible: viewModel.errorMessage !== ""
        color: "red"
        Layout.fillWidth: true
    }

    Button {
        text: qsTr("登录")
        enabled: !viewModel.loading
        onClicked: viewModel.login()  // 仅委托给 C++
        Layout.fillWidth: true
    }

    BusyIndicator {
        running: viewModel.loading
        visible: viewModel.loading
        Layout.alignment: Qt.AlignHCenter
    }

    Connections {
        target: viewModel
        function onLoginSuccess() {
            // 导航到主页面
            stackView.push("MainView.qml")
        }
    }
}
```

**关键设计原则：**

1. **Q_PROPERTY** - 暴露给 QML 的属性，支持双向绑定
2. **Q_INVOKABLE** - 暴露给 QML 调用的方法
3. **信号 (Signals)** - ViewModel 状态变化时通知 QML 更新
4. **Connections** - QML 监听 ViewModel 信号
5. **业务逻辑隔离** - 所有验证、API 调用都在 C++ ViewModel 中

## 6. 并发与异步

### 6.1 网络请求异步处理

```cpp
// 使用 QFuture + QCoro
QFuture<ApiResult<FileInfo>> FileService::getFileInfo(quint64 fileId) {
    return QtConcurrent::run([this, fileId]() {
        QEventLoop loop;
        ApiResult<FileInfo> result;
        
        auto reply = m_client->get(QString("/api/file/%1").arg(fileId));
        
        connect(reply, &QNetworkReply::finished, &loop, [&]() {
            auto response = ApiResponse::parse(reply->readAll());
            if (response && response->isSuccess()) {
                result = FileInfo::fromJson(response->data);
            } else {
                result = std::unexpected(response.error());
            }
            loop.quit();
        });
        
        loop.exec();
        return result;
    });
}
```

// 哈希计算在后台线程
QFuture<QString> HashCalculator::calculateMd5(const QString& filePath) {
    return QtConcurrent::run([filePath]() {
        QCryptographicHash hash(QCryptographicHash::Md5);
        QFile file(filePath);
        
        if (file.open(QIODevice::ReadOnly)) {
            constexpr qint64 chunkSize = 8192;
            while (!file.atEnd()) {
                hash.addData(file.read(chunkSize));
            }
        }
        
        return hash.result().toHex();
    });
}

### 7.2 错误传播

```cpp
// 使用 std::expected 进行错误传播
template<typename T>
using Result = std::expected<T, ErrorInfo>;

// 服务层返回 Result
auto FileService::getFileList(quint64 folderId) -> QFuture<Result<FileListResponse>>;

// ViewModel 处理错误
void FileListViewModel::loadFiles(quint64 folderId) {
    m_loading = true;
    emit loadingChanged();
    
    auto future = m_service->getFileList(folderId);
    
    QtFuture::connect(future, &decltype(future)::finished, this, [=]() {
        m_loading = false;
        emit loadingChanged();
        
        auto result = future.result();
        if (result) {
            m_model->setFiles(result->items);
            m_errorMessage.clear();
        } else {
            m_errorMessage = result.error().message();
            emit errorChanged();
        }
    });
}
