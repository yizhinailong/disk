# 桌面客户端 — 状态模型与导航模型

## 1. 文档说明

### 1.1 文档目的

本文档定义桌面客户端的导航规则、页面状态机、选择模型、transient feedback 模型，以及 `VIEW-` / `PAGE-` / `STATE-` / `FLOW-` ID 体系的详细编号规则。本文档的核心目标是解决旧文档（`04-navigation-and-ui-state.md`）与当前实现之间的导航冲突，冻结新的导航与状态契约，为 DOC-04（组件与实现映射）和 DOC-05（验证计划）提供行为层面的唯一规范基线。

### 1.2 权威来源

| 来源 | 路径 | 用途 |
|------|------|------|
| 文档治理基线 | `docs/desktop/00-桌面客户端系统概述与文档治理.md` | 权威层级、ID 前缀定义、资源管理器模型 |

### 1.3 冻结不变量

1. 文件夹钻取使用 **同页切换当前 folder context**（修改 `currentFolderId`），不是 `StackView push` 新 `DriveBrowserPage`。此行为已被 quick test 验证。
2. 文件相关 Sidebar 视图切换是 **view mode switch**，在 `PAGE-DRIVE` 内部切换数据源，不替换 StackView 页面。
3. 传输中心、设置是独立页面，通过 `stackView.replace()` 替换。登录/访客流仍是独立 Shell。
4. 选择模型在此文档中完整定义，包括当前单选实现和未来的 Ctrl/Shift/框选/右键选择语义。
5. Visitor Shell 是独立流程，不与 Owner Shell 混写，不共享导航栈。
6. 页面状态机采用统一的 `STATE-` 标识体系，所有状态迁移在此文档中冻结。
7. Transient feedback（toast/dialog/progress/skeleton）各自的触发场景、职责边界和优先级在此文档中冻结。

### 1.4 与旧文档的冲突修正

旧文档 `04-navigation-and-ui-state.md` §2.1.2 记录的"文件夹钻入: 在 DriveBrowserPage 内点击文件夹，StackView push 新的页面（新 parent_id）"与当前实现不符。当前 `DriveBrowserPage.qml` 的 `navigateToFolder()` 函数（行 436-443）仅修改 `currentFolderId` 属性并调用 `refreshCurrentFolder()`，不触发任何 StackView 操作。Quick test `tst_drive_browser_navigation.qml`（行 82-131）验证了这一行为：调用 `navigateToFolder("42")` 后 `currentFolderId` 变为 `"42"`，同时触发 `loadFolderTree`、`listFiles`、`loadBreadcrumb` 三路加载，页面实例不变。

本文档以此已验证行为为准。旧文档的 `StackView push` 描述作为历史错误归档，不再参与导航规范。

## 2. ID 编号规则

### 2.1 VIEW- 前缀（文件视图模式）

文件视图模式标识资源管理器上下文（`PAGE-DRIVE`）内的数据视角。前缀由 DOC-01 §3.2 定义，此处补充编号约束。

| ID | 名称 | 数据源 | 文件夹钻取 |
|----|------|--------|-----------|
| `VIEW-MYFILES` | 我的文件 | `GET /api/file/list`（按 parent_id） | 支持（同页切换） |
| `VIEW-SHARED` | 已共享 | `GET /api/share` | 不适用 |
| `VIEW-TRASH` | 回收站 | `GET /api/trash` | 不支持 |

> **编号规则**：`VIEW-` 后接大写英文短名，使用 `UPPER_SNAKE_CASE`。新增视图模式必须在此表中注册并标注状态标签。

### 2.2 PAGE- 前缀（独立页面）

页面标识在 StackView 中独立存在的完整内容区域。

| ID | 名称 | Shell 归属 | StackView 行为 |
|----|------|-----------|----------------|
| `PAGE-SPLASH` | 启动画面 | 认证前 | 初始页，检查本地令牌后切换 |
| `PAGE-LOGIN` | 登录/注册 | 认证前 | 独立页，登录成功后进入 Owner Shell |
| `PAGE-DRIVE` | 资源管理器主页 | Owner Shell | StackView 初始项，承载三个 VIEW- 模式 |
| `PAGE-TRANSFER` | 传输中心 | Owner Shell | `stackView.replace()` 替换 |
| `PAGE-SETTINGS` | 设置/个人信息 | Owner Shell | `stackView.replace()` 替换 |
| `PAGE-SHARE-VERIFY` | 分享验证 | Visitor Shell | Visitor Shell 独立流程 |
| `PAGE-SHARE-BROWSE` | 分享内容浏览 | Visitor Shell | Visitor Shell 独立流程 |
| `PAGE-ADMIN-USERS` | 用户管理 | Admin Shell | AdminShell StackView 页面，默认首页 |
| `PAGE-ADMIN-SHARES` | 分享管理 | Admin Shell | AdminShell StackView 页面 |
| `PAGE-ADMIN-SYSTEM` | 系统监控 | Admin Shell | AdminShell StackView 页面 |

> **编号规则**：`PAGE-` 后接大写英文短名，使用 `UPPER_SNAKE_CASE`。新增页面必须在此表中注册。

### 2.3 STATE- 前缀（页面/会话状态）

| ID | 含义 | 适用范围 |
|----|------|---------|
| `STATE-LOADING` | 数据加载中 | 所有可加载数据的页面 |
| `STATE-EMPTY` | 数据加载成功但结果为空 | 列表类页面 |
| `STATE-CONTENT` | 数据加载成功且有内容 | 列表类页面 |
| `STATE-ERROR` | 数据加载失败 | 所有可加载数据的页面 |
| `STATE-BATCH-RESULT` | 批量操作完成（可能部分成功） | 支持批量操作的页面 |
| `STATE-AUTHENTICATING` | 登录请求已发送 | `PAGE-LOGIN` |
| `STATE-REFRESHING` | Access Token 刷新中 | Owner Session |
| `STATE-REAUTH-REQUIRED` | 需要重新认证 | Owner/Visitor Session |
| `STATE-LOGOUT-PENDING` | 登出清理中 | Owner Session |
| `STATE-VERIFYING` | 分享验证请求已发送 | Visitor Session |
| `STATE-UNVERIFIED` | 分享未验证（等待密码输入） | Visitor Session |

> **编号规则**：`STATE-` 后接大写英文短名。页面级状态和会话级状态都使用此前缀，适用范围列区分两者。

### 2.4 FLOW- 前缀（用户流程/导航流）

| ID | 流程名称 | 起点 | 终点 | 涉及页面/状态 |
|----|---------|------|------|-------------|
| `FLOW-LOGIN` | 所有者登录 | `PAGE-SPLASH` | `PAGE-DRIVE`（`VIEW-MYFILES`） | `PAGE-SPLASH` → `PAGE-LOGIN` → Owner Shell |
| `FLOW-UPLOAD` | 文件上传 | `PAGE-DRIVE` 工具栏 | `PAGE-TRANSFER`（任务追踪） | `PAGE-DRIVE` → 文件选择 Dialog → `PAGE-TRANSFER` |
| `FLOW-DOWNLOAD` | 文件下载 | `PAGE-DRIVE` 工具栏 | `PAGE-TRANSFER`（任务追踪） | `PAGE-DRIVE` → 保存 Dialog → `PAGE-TRANSFER` |
| `FLOW-VISITOR-ACCESS` | 访客访问分享 | 外部链接唤起 | `PAGE-SHARE-BROWSE` | `PAGE-SHARE-VERIFY` → `PAGE-SHARE-BROWSE` |
| `FLOW-FOLDER-NAVIGATE` | 文件夹钻取 | `PAGE-DRIVE`（`VIEW-MYFILES`） | 同页面内新 folder context | 不离开 `PAGE-DRIVE` |
| `FLOW-VIEW-SWITCH` | 视图模式切换 | Sidebar 文件类入口 | 同页面内新数据源 | 不离开 `PAGE-DRIVE` |
| `FLOW-PAGE-SWITCH` | 独立页面替换 | Sidebar 独立页面入口 | 目标独立页面 | `stackView.replace()` |
| `FLOW-LOGOUT` | 所有者登出 | Sidebar 登出按钮 | `PAGE-LOGIN` | Owner Session 清理 → `PAGE-LOGIN` |
| `FLOW-ADMIN-LOGIN` | 管理员登录路由 | `PAGE-SPLASH` | `PAGE-ADMIN-USERS`（AdminShell 首页） | `PAGE-SPLASH` → `PAGE-LOGIN` → `AuthService.Login` → `OwnerSessionManager.DecodeRoleFromJwt` → `role==1` → `ShellController.navigateToAdmin` → AdminShell |

> **编号规则**：`FLOW-` 后接大写英文短名，使用 `UPPER_SNAKE_CASE`。每个流程必须定义起点、终点和涉及的页面/状态。

## 3. 导航模型

### 3.1 导航层次

桌面客户端的导航分为三个互不混淆的层次：

| 层次 | 行为 | StackView 操作 | 状态影响 | 示例 |
|------|------|---------------|---------|------|
| **文件夹钻取**（`FLOW-FOLDER-NAVIGATE`） | 在同一 `PAGE-DRIVE` 内切换 `currentFolderId` | 无。不触发 StackView 操作 | 清空选中项；触发 tree + list + breadcrumb 三路加载；pageState → `STATE-LOADING` | 点击面包屑节点、点击 Open 按钮、点击目录树节点、点击 Up 按钮 |
| **视图模式切换**（`FLOW-VIEW-SWITCH`） | 在 `PAGE-DRIVE` 内切换数据源 | 无。不触发 StackView 操作 | 清空选中项；切换数据绑定；Header 标题/副标题联动 | 点击 Sidebar 的"我的文件""已共享""回收站"入口 |
| **独立页面替换**（`FLOW-PAGE-SWITCH`） | 用新页面替换 StackView 栈顶 | `stackView.replace()` | 整个页面内容替换；Header 标题/副标题更新 | 点击 Sidebar 的"传输中心""设置"入口 |

### 3.2 Owner Shell 导航规则

#### 3.2.1 启动与首页

| 规则 | 说明 | 状态 |
|------|------|------|
| 应用启动 | 进入 `PAGE-SPLASH`，检查本地是否存在有效令牌 | `[已实现]` OwnerShell 为默认启动 Shell |
| 有有效令牌 | 恢复 Owner Session，进入 `PAGE-DRIVE`（默认 `VIEW-MYFILES`） | `[已实现]` 当前直接进入 OwnerShell |
| 无有效令牌 | 进入 `PAGE-LOGIN` | `[已实现]` |
| Owner Shell 首页 | `StackView` 初始项为 `PAGE-DRIVE` | `[已实现]` `OwnerShell.qml` 行 591 |

#### 3.2.2 Sidebar 导航

| 导航目标 | 行为 | StackView 操作 | 状态 |
|----------|------|---------------|------|
| VIEW-MYFILES（我的文件） | 在 `PAGE-DRIVE` 内激活我的文件视图模式 | 无。若当前不是 `PAGE-DRIVE` 则 `stackView.replace()` 回到 `PAGE-DRIVE` | `[已实现]` `activateViewMode("myfiles")` + `refreshCurrentFolder()` |
| VIEW-SHARED（已共享） | 在 `PAGE-DRIVE` 内激活已共享视图模式 | 无 | `[已实现]` `activateViewMode("shared")` + `refreshSharedList()` |
| VIEW-TRASH（回收站） | 在 `PAGE-DRIVE` 内激活回收站视图模式 | 无 | `[已实现]` `activateViewMode("trash")` + `refreshTrashList()` |
| PAGE-TRANSFER（传输中心） | 替换 StackView 栈顶为传输中心页面 | `stackView.replace()` | `[已实现]` |
| PAGE-SETTINGS（设置） | 替换 StackView 栈顶为设置页面 | `stackView.replace()` | `[已实现]` |

#### 3.2.3 文件夹钻取（FLOW-FOLDER-NAVIGATE）

文件夹钻取是 `PAGE-DRIVE` 在 `VIEW-MYFILES` 模式下的核心导航行为。它始终在同一页面实例内完成，不创建新页面。

| 触发方式 | 行为 | 状态 |
|----------|------|------|
| 点击列表行内 "Open" 按钮 | 调用 `navigateToFolder(folderId)`，修改 `currentFolderId`，触发三路刷新 | `[已实现]` |
| 点击面包屑节点 | 调用 `navigateToFolder(folderId)`，导航到对应目录 | `[已实现]` |
| 点击目录树节点 | 调用 `navigateToFolder(folderId)`，同步面包屑和文件列表 | `[已实现]` |
| 点击 Up 按钮 | 导航到面包屑倒数第二项（上级目录），根目录时 disabled | `[已实现]` |
| 双击文件夹行 | 等同于点击 Open 按钮 | `[规划]` 当前仅 `onClicked`，无双击处理 |

**钻取时的状态变更序列**：

```
1. 清空选中项（selectedItemId / selectedItemKind / selectedItemName → ""）
2. 设置 pageState → "loading"（STATE-LOADING）
3. 修改 currentFolderId → 目标 folder ID
4. 并行触发三路加载：loadFolderTree() + listFiles(folderId) + loadBreadcrumb(folderId)
5. 等待响应：
   - listFiles 成功 + total > 0 → pageState → "content"（STATE-CONTENT）
   - listFiles 成功 + total == 0 → pageState → "empty"（STATE-EMPTY）
   - listFiles 失败 → pageState → "error"（STATE-ERROR）
```

> **关键约束**：快速连续调用 `navigateToFolder()` 时，最终状态由最后一次调用决定。Quick test `test_rapid_navigation_final_state_wins` 验证了这一行为：连续调用 `navigateToFolder("10")` → `navigateToFolder("20")` → `navigateToFolder("30")` 后，`currentFolderId` 为 `"30"`，且最后一次 `listFiles` 调用的参数也是 `"30"`。

#### 3.2.4 视图模式切换（FLOW-VIEW-SWITCH）

视图模式切换在 `PAGE-DRIVE` 内部进行，不替换 StackView 页面。切换仅改变数据源绑定和 Header 展示。

| 切换行为 | 说明 | 状态 |
|----------|------|------|
| 切换数据源 | 根据目标 VIEW- 模式调用不同的 API 或 API 参数 | `[规划]` |
| 清空选中项 | 切换视图模式时清空 `selectedItemId` 等选择属性 | `[规划]` |
| 清空面包屑 | 仅 VIEW-MYFILES 有面包屑；切换到其他视图模式时隐藏面包屑 | `[规划]` |
| Header 标题联动 | Shell 层 Header 的页面标题随视图模式更新 | `[规划]` |
| 隐藏目录树面板 | 切换到非 VIEW-MYFILES 的视图模式时收起目录树 Popup | `[规划]` |
| pageState → STATE-LOADING | 切换视图模式后触发新数据加载 | `[规划]` |

#### 3.2.5 独立页面替换（FLOW-PAGE-SWITCH）

独立页面替换通过 `stackView.replace()` 将 StackView 栈顶页面替换为目标页面。替换后 StackView 栈深度始终为 1，不累积历史页面。

| 替换行为 | 说明 | 状态 |
|----------|------|------|
| PAGE-DRIVE → PAGE-TRANSFER | 点击 Sidebar "Transfers"，`stackView.replace(transferCenterPageComponent)` | `[已实现]` |
| PAGE-DRIVE → PAGE-SETTINGS | 点击 Sidebar "Settings"，`stackView.replace(settingsPageComponent)` | `[已实现]` |
| PAGE-TRANSFER → PAGE-DRIVE | 点击 Sidebar "Files"，`stackView.replace(driveBrowserPageComponent)` | `[已实现]` |
| Header 标题更新 | 替换页面后 `currentPageTitle` / `currentPageSubtitle` 随 `activeDestination` 更新 | `[已实现]` |
| Sidebar 高亮更新 | `activeDestination` 随页面切换更新，Sidebar 按钮高亮状态同步 | `[已实现]` |

### 3.3 Visitor Shell 导航规则

Visitor Shell 是完全独立的导航流，不进入 Owner Shell 的 StackView，不包含 Sidebar。

#### 3.3.1 导航流程（FLOW-VISITOR-ACCESS）

```
外部链接（share_id）→ PAGE-SHARE-VERIFY → PAGE-SHARE-BROWSE
```

| 步骤 | 页面/状态 | 说明 | 状态 |
|------|----------|------|------|
| 1. 提取 share_id | `PAGE-SHARE-VERIFY` | 从分享链接中提取 share_id | `[已实现]` ShareVerifyPage.qml 已实现，share_id 从 URL 参数解析 |
| 2. 判断密码保护 | `PAGE-SHARE-VERIFY` | 若无密码，自动跳过验证 | `[已实现]` ShareVerifyPage 根据 share_id 请求后端判断 |
| 3. 输入密码 | `PAGE-SHARE-VERIFY`（`STATE-VERIFYING`） | 提交密码到 `POST /api/share/access/{share_id}` | `[已实现]` ShareVerifyPage 调用 `sessionStore.visitor.StartVerify()` |
| 4. 验证成功 | `STATE-VERIFYING` → `STATE-CONTENT` | 获取 Share Token，进入 `PAGE-SHARE-BROWSE` | `[已实现]` VisitorShell 路由切换到 ShareBrowsePage |
| 5. 浏览分享 | `PAGE-SHARE-BROWSE`（`STATE-LOADING` → `STATE-CONTENT`） | 加载分享根级内容 | `[已实现]` ShareBrowsePage 调用 `shareManager.browseShare()` |
| 6. 文件夹钻取 | 同页内刷新列表 | 调用 `GET /api/share/browse/{share_id}` 加载子级 | `[已实现]` ShareBrowsePage 文件夹钻取已实现 |
| 7. 下载文件 | `PAGE-SHARE-BROWSE` | 仅当 `permission == download` 时可用 | `[已实现]` ShareBrowsePage 下载按钮已实现 |

#### 3.3.2 与 Owner Shell 的隔离规则

| 规则 | 说明 |
|------|------|
| 导航隔离 | Visitor Shell 不包含 Owner Sidebar，无法导航到传输中心、设置等所有者页面 |
| 认证域隔离 | 访客使用 Share Token（`X-Share-Token`），所有者使用 JWT（`Authorization: Bearer`），两套令牌不可混用 |
| 功能隔离 | 访客不支持上传、重命名、移动、复制、删除、创建文件夹、分享管理、回收站操作 |
| 生命周期隔离 | 所有者流和访客流不会同时处于活跃状态 |
| 下载权限降级 | 当 `permission == view` 时，访客可浏览但下载按钮禁用 |

### 3.4 Admin Shell 导航规则

Admin Shell 是管理员用户（`role === 1`）登录后的独立导航流，不进入 Owner Shell 的 StackView。

#### 3.4.1 导航流程（FLOW-ADMIN-LOGIN）

```
PAGE-SPLASH → PAGE-LOGIN → AuthService.Login
  → OwnerSessionManager.DecodeRoleFromJwt
  → role === 1 → ShellController.navigateToAdmin → AdminShell (PAGE-ADMIN-USERS)
  → role !== 1 → ShellController.navigateToOwner → OwnerShell (PAGE-DRIVE)
```

| 步骤 | 页面/状态 | 说明 | 状态 |
|------|----------|------|------|
| 1. 提交登录 | `PAGE-LOGIN`（`STATE-AUTHENTICATING`） | 调用 `AuthService.Login()` | `[规划]` |
| 2. 解码角色 | `OwnerSessionManager.DecodeRoleFromJwt()` | 从 JWT payload 提取 `role` 字段 | `[规划]` |
| 3. 路由判断 | `ShellController` | `role === 1` → AdminShell；`role !== 1` → OwnerShell | `[规划]` |
| 4. 进入 AdminShell | `PAGE-ADMIN-USERS` | AdminShell 默认首页，加载用户列表 | `[规划]` |

#### 3.4.2 AdminShell 内部导航

| 导航目标 | 行为 | StackView 操作 | 状态 |
|----------|------|---------------|------|
| PAGE-ADMIN-USERS（用户管理） | 替换 StackView 栈顶为用户管理页面 | `stackView.replace()` | `[规划]` |
| PAGE-ADMIN-SHARES（分享管理） | 替换 StackView 栈顶为分享管理页面 | `stackView.replace()` | `[规划]` |
| PAGE-ADMIN-SYSTEM（系统监控） | 替换 StackView 栈顶为系统监控页面 | `stackView.replace()` | `[规划]` |
| 登出 | 清理 Owner Session，切换 Shell 为 PAGE-LOGIN | Shell 替换 | `[规划]` |

#### 3.4.3 与 Owner Shell 的隔离规则

| 规则 | 说明 |
|------|------|
| 导航隔离 | AdminShell 不包含 Owner Sidebar，无文件浏览、传输中心、设置等所有者页面 |
| 功能隔离 | AdminShell 不包含文件管理功能（无文件列表、上传、下载、文件夹钻取） |
| 认证域共享 | AdminShell 使用与 OwnerShell 相同的 JWT（`Authorization: Bearer`） |
| 生命周期隔离 | AdminShell 与 OwnerShell 互斥，同一时刻只有一个活跃 |
| 降级隔离 | AdminShell 登出后回到 PAGE-LOGIN，不会进入 OwnerShell |

## 4. 页面状态模型

### 4.1 通用页面状态

每个页面拥有统一的状态机，用于控制内容区域的呈现。页面状态由数据加载结果和用户操作共同驱动。

| 状态 ID | 含义 | 触发条件 |
|---------|------|---------|
| `STATE-LOADING` | 正在加载初始数据 | 页面首次进入、用户触发刷新、视图模式切换、文件夹钻取 |
| `STATE-EMPTY` | 数据加载成功但结果为空 | 列表接口返回空结果 |
| `STATE-CONTENT` | 数据加载成功且有内容 | 列表接口返回非空结果 |
| `STATE-ERROR` | 数据加载失败 | 网络错误或后端返回错误码 |
| `STATE-BATCH-RESULT` | 批量操作完成（可能部分成功） | 批量操作接口返回 |

### 4.2 状态迁移图

```
STATE-LOADING ──成功且有数据──→ STATE-CONTENT
STATE-LOADING ──成功但无数据──→ STATE-EMPTY
STATE-LOADING ──失败──────────→ STATE-ERROR

STATE-CONTENT ──用户刷新──────→ STATE-LOADING
STATE-CONTENT ──批量操作──────→ STATE-BATCH-RESULT
STATE-CONTENT ──文件夹钻取───→ STATE-LOADING
STATE-CONTENT ──视图模式切换──→ STATE-LOADING

STATE-EMPTY ──用户刷新───────→ STATE-LOADING

STATE-ERROR ──用户重试───────→ STATE-LOADING

STATE-BATCH-RESULT ──用户确认──→ STATE-LOADING（刷新列表）
```

### 4.3 各页面/视图的状态详情

#### 4.3.1 PAGE-DRIVE（资源管理器主页）

PAGE-DRIVE 是唯一承载三个文件视图模式的页面。状态机在所有视图模式下共享，但不同视图模式的状态触发条件不同。

| 视图模式 | STATE-LOADING 触发 | STATE-EMPTY 含义 | STATE-CONTENT 含义 | STATE-ERROR 触发 | STATE-BATCH-RESULT 触发 | 状态 |
|----------|-------------------|-----------------|-------------------|-----------------|----------------------|------|
| VIEW-MYFILES | 文件夹钻取、刷新、首次加载 | 当前目录无文件/文件夹 | 展示文件列表 | listFiles 失败 | 批量删除/移动/复制 | `[已实现]`（STATE-LOADING/EMPTY/CONTENT/ERROR） |
| VIEW-SHARED | 视图模式切换、刷新 | 无分享记录 | 展示分享列表 | API 失败 | 批量取消分享 | `[规划]` |
| VIEW-TRASH | 视图模式切换、刷新 | 回收站为空 | 展示回收站列表 | API 失败 | 批量恢复/彻底删除 | `[规划]` |

**PAGE-DRIVE 各状态的 UI 表现**（当前 VIEW-MYFILES 实现）：

| 状态 | 内容区表现 | 状态摘要卡片 | 状态芯片 | 状态 |
|------|----------|------------|---------|------|

#### 4.3.2 PAGE-TRANSFER（传输中心）

## 5. 选择模型

### 5.1 选择模型概述

选择模型定义用户如何在文件列表中选择一个或多个项目。当前实现为单值选择模型，多选行为为规划中的扩展。

### 5.2 选择类型定义

#### 5.2.1 单击选择（Single Click）

| 行为 | 说明 | 状态 |
|------|------|------|
| 单击未选中项 | 设置 `selectedItemId` / `selectedItemKind` / `selectedItemName` 为该项目，高亮该行，取消其他行高亮 | `[已实现]` `onClicked: root.selectItem(model.id, model.kind, model.name)` |
| 单击已选中项 | 保持选中状态不变（不取消选中） | `[已实现]` |
| 单击空白区域 | 清空选中项（`selectedItemId` 等设为空字符串） | `[规划]` 当前 `ListView` 不处理空白区域点击 |

#### 5.2.2 Ctrl + 单击（Toggle Select）

| 行为 | 说明 | 状态 |
|------|------|------|
| Ctrl + 单击未选中项 | 将该项目追加到选中集合，不影响已选中项 | `[规划]` 当前选择模型为单值属性 |
| Ctrl + 单击已选中项 | 从选中集合中移除该项目，其他选中项不受影响 | `[规划]` |
| 无 Ctrl + 单击未选中项（多选已激活时） | 清空所有选中项，仅选中新项目（回到单选） | `[规划]` |

#### 5.2.3 Shift + 单击（Range Select）

| 行为 | 说明 | 状态 |
|------|------|------|
| Shift + 单击 | 选中从上次单击项（锚点）到当前项之间的所有连续项目（含两端） | `[规划]` 当前无锚点追踪机制 |
| 锚点定义 | 最近一次无修饰键单击的项目作为范围起点 | `[规划]` |
| Shift + 单击在已有多选时 | 重新计算范围，替换之前的 Shift 选择，保留之前的 Ctrl 选择 | `[规划]` |

#### 5.2.4 鼠标框选（Box / Lasso Select）

| 行为 | 说明 | 状态 |
|------|------|------|
| 在空白区域按住左键拖拽 | 绘制矩形选择框，框内项目全部选中 | `[规划]` 当前无框选实现 |
| 框选与 Ctrl 组合 | 框选结果追加到已选中集合 | `[规划]` |
| 框选释放 | 框选结果替代之前的非 Ctrl 选中项 | `[规划]` |

#### 5.2.5 右键选择（Right-Click Selection）

| 行为 | 说明 | 状态 |
|------|------|------|
| 右键未选中项 | 选中该项目，弹出上下文菜单 | `[规划]` 当前无右键菜单实现 |
| 右键已选中项 | 保持当前选中状态不变，弹出上下文菜单 | `[规划]` |
| 右键空白区域 | 清空选中项（如有多选），弹出空白区域上下文菜单 | `[规划]` |
| 右键属于多选中的一项 | 保持多选状态不变，弹出多选上下文菜单 | `[规划]` |

#### 5.2.6 全选（Ctrl + A）

| 行为 | 说明 | 状态 |
|------|------|------|
| Ctrl + A | 选中当前列表所有项目 | `[规划]` |

### 5.3 选择保持规则

选择状态在以下场景中被清除或保留：

| 场景 | 选择行为 | 状态 |
|------|---------|------|
| 文件夹钻取 | **清除**。`navigateToFolder()` 调用 `clearSelection()` | `[已实现]` quick test 验证 |
| 手动刷新 | **清除**。`refreshCurrentFolder()` 调用 `clearSelection()` | `[已实现]` |
| 视图模式切换 | **清除**。切换 VIEW- 时清空选中项 | `[规划]` |
| 独立页面替换 | **自然清除**。整个页面被替换，选中项随旧页面销毁 | `[已实现]` |
| mutation 操作成功 | **清除**。`finishMutationSuccess()` 关闭对话框并刷新列表 | `[已实现]` |
| mutation 操作失败 | **保留**。选中项不变，对话框显示错误信息 | `[已实现]` |
| 打开对话框 | **保留**。对话框是模态浮层，不改变底层选中项 | `[已实现]` |
| 关闭对话框（无操作） | **保留**。`onClosed` 仅在 `!mutationInFlight` 时重置 mutation 状态 | `[已实现]` |
| 目录树节点点击 | **清除**。等同于文件夹钻取 | `[已实现]` |
| 面包屑节点点击 | **清除**。等同于文件夹钻取 | `[已实现]` |

### 5.4 选择模型实现路径

当前选择模型使用三个独立属性：

```qml
property string selectedItemId: ""
property string selectedItemKind: ""
property string selectedItemName: ""
```

每次 `selectItem()` 调用覆盖这三个属性。多选需要引入集合类型的选择模型（如 `selectedIds: list<string>`），属于架构级变更。此变更不在本文档范围内，但选择语义在此冻结，以便实现时有明确的行为契约。

## 6. Transient Feedback 模型

Transient feedback 是不参与导航栈的临时 UI 反馈，用于向用户传达操作结果、进行中的状态或需要确认的决策。本文档定义四种 transient feedback 的职责边界。

### 6.1 四种 Transient Feedback 类型

#### 6.1.1 Dialog（模态对话框）

**职责**：需要用户确认或输入的操作，阻断页面其他交互。

| 属性 | 说明 |
|------|------|
| 模态性 | 模态。打开时阻断底层页面交互 |
| 关闭方式 | 用户主动操作（Cancel/Confirm 按钮）或操作完成后自动关闭 |
| 生命周期 | 短期。操作完成后立即关闭 |
| 触发场景 | 新建文件夹、重命名、删除确认、文件选择、移动/复制目标选择 |
| 实现方式 | Qt `Dialog` 组件，`closePolicy: Popup.NoAutoClose` |
| 内容 | 标题、描述文字、输入控件（如需要）、Cancel/Confirm 按钮、内联错误提示 |

**Dialog 内的操作反馈**：

| 场景 | Dialog 内表现 | 状态 |
|------|-------------|------|
| 操作进行中 | `mutationInFlight = true`，按钮文字变为 "创建中..." / "保存中..." / "删除中..."，输入框和按钮 disabled | `[已实现]` |
| 操作成功 | Dialog 自动关闭，页面刷新列表 | `[已实现]` |
| 操作失败 | Dialog 保持打开，显示内联红色错误文字，输入框保持焦点 | `[已实现]` |

#### 6.1.2 Toast（轻量通知）

**职责**：操作成功/失败的轻量提示，不阻断用户操作。

| 属性 | 说明 |
|------|------|
| 模态性 | 非模态。不阻断页面交互 |
| 关闭方式 | 自动消失（建议 3-5 秒），或用户手动关闭 |
| 生命周期 | 短暂。几秒后自动消失 |
| 触发场景 | 操作成功反馈、操作部分失败反馈、认证状态变更提示 |
| 实现方式 | 页面底部或右上角浮出的条状通知组件 |
| 优先级 | 低于 Dialog。当 Dialog 打开时，Toast 等待 Dialog 关闭后再显示（或排队显示） |

**Toast 场景定义**：

| 场景 | Toast 内容 | 状态 |
|------|-----------|------|
| 单项操作成功 | 如 "文件夹已创建"、"重命名成功" | `[已实现]` `showToast()` + `toastOverlay` + `toastDismissTimer`（3 秒自动消失） |
| 批量操作部分失败 | 如 "3/5 项已删除，2 项失败"，带展开详情按钮 | `[规划]` |
| 认证状态变更 | 如 "登录已过期，请重新登录" | `[规划]` |
| 下载/上传启动 | 如 "文件下载已开始" | `[规划]` |
| 配额不足警告 | 如 "存储空间不足，无法上传" | `[规划]` |

#### 6.1.3 Progress（进度指示）

**职责**：展示进行中的操作进度，包括确定性和非确定性进度。

| 进度类型 | 位置 | 展示内容 | 状态 |
|---------|------|---------|------|
| 上传任务进度 | `PAGE-TRANSFER` 中 | 文件名、进度百分比/进度条、速度、剩余时间、暂停/继续/取消按钮 | `[已实现]` |
| 下载任务进度 | `PAGE-TRANSFER` 中 | 文件名、进度百分比/进度条、速度、剩余时间、暂停/继续/取消按钮 | `[已实现]` |
| 存储空间进度 | Sidebar 存储统计卡片 | 已用/总量的 ProgressBar，百分比文字 | `[已实现]` |
| Dialog 内操作进行中 | Dialog 按钮区域 | 按钮文字变为 "创建中..." / "保存中..." / "删除中..."，输入和按钮 disabled | `[已实现]` |
| 页面级加载进度 | `PAGE-DRIVE` 状态摘要卡片 | 状态芯片显示 "正在刷新"，摘要文字显示 "正在刷新文件夹内容..." | `[已实现]` |

#### 6.1.4 Skeleton（骨架屏）

**职责**：初始加载时以灰色动画占位块模拟列表布局，提供视觉稳定性，避免内容区完全空白。

| 属性 | 说明 |
|------|------|
| 模态性 | 非模态。替代内容区的空白 loading 态 |
| 生命周期 | 从数据请求开始到数据返回为止 |
| 触发场景 | 首次加载文件夹、搜索加载中、视图模式切换时短暂加载 |
| 实现方式 | 灰色动画矩形模拟列表行的文件名、类型、大小、时间列 |

| 场景 | 展示方式 | 状态 |
|------|---------|------|
| 首次加载文件夹 | 灰色动画矩形模拟列表行（文件名、类型、大小、时间四列） | `[规划]` 当前 loading 态仅隐藏内容区，无骨架屏 |
| 搜索加载中 | 搜索结果区域骨架屏 | `[规划]` |
| 视图模式切换加载 | 主内容区短暂骨架屏（数据源切换时） | `[规划]` |

### 6.2 Transient Feedback 优先级

当多种 feedback 同时适用时，按以下优先级展示：

| 优先级 | 反馈类型 | 触发条件 | 说明 |
|--------|---------|---------|------|
| 1 | Dialog 内操作进行中指示 | `mutationInFlight === true` 且 Dialog 打开 | Dialog 打开时，其他反馈被 Dialog 遮挡 |
| 2 | Dialog | 用户触发需要确认/输入的操作 | 模态阻断，优先级最高 |
| 3 | 内容区 STATE-LOADING（PageStateView） | `pageState === "loading"` | 替代内容区，可叠加 Skeleton |
| 4 | Skeleton | 初始加载或视图模式切换时 | 叠加在 STATE-LOADING 之上，替代空白 |
| 5 | 状态芯片 "正在刷新" | 同 STATE-LOADING | 始终反映 pageState |
| 6 | Toast | 操作成功/失败反馈 | 非模态，不阻断交互 |
| 7 | Progress | 长时间操作（上传/下载） | 在 PAGE-TRANSFER 中展示 |

### 6.3 Transient Feedback 与页面状态的配合

| 页面状态 | 可同时展示的 Feedback | 说明 |
|---------|---------------------|------|
| `STATE-LOADING` | Skeleton、状态芯片 | Skeleton 替代空白内容区，芯片显示 "正在刷新" |
| `STATE-CONTENT` | Dialog、Toast、Progress | Dialog 用于操作确认，Toast 用于操作结果，Progress 用于传输任务 |
| `STATE-EMPTY` | Toast、Dialog | Toast 提示空状态原因，Dialog 用于创建内容（如新建文件夹） |
| `STATE-ERROR` | Toast、Dialog | Toast 提示错误摘要，Dialog 用于重试确认 |
| `STATE-BATCH-RESULT` | Dialog | Dialog 展示批量操作逐项结果 |

## 7. 路由守卫与错误联动

### 7.1 认证状态守卫

#### 7.1.1 Owner Session 路由守卫

| 守卫规则 | 检查条件 | 拦截动作 |
|----------|---------|---------|
| Session 活跃 | Owner Session 状态为 `Active` | 放行 |
| Session 刷新中 | Owner Session 状态为 `Refreshing` | 放行（等待刷新结果，不阻断导航） |
| Session 未认证 | Owner Session 状态为 `LoggedOut` / `ReauthRequired` | 重定向到 `PAGE-LOGIN` |
| Session 认证中 | Owner Session 状态为 `Authenticating` | 阻断导航，等待认证结果 |
| Session 登出中 | Owner Session 状态为 `LogoutPending` | 阻断导航，等待清理完成 |

#### 7.1.2 Visitor Session 路由守卫

| 守卫规则 | 检查条件 | 拦截动作 |
|----------|---------|---------|
| Session 活跃 | Visitor Session 状态为 `Active` | 放行到 `PAGE-SHARE-BROWSE` |
| Session 未验证 | Visitor Session 状态为 `Idle` / `Unverified` | 重定向到 `PAGE-SHARE-VERIFY` |
| Session 验证中 | Visitor Session 状态为 `Verifying` | 阻断导航，等待验证结果 |
| Token 过期 | Visitor Session 状态为 `ReverifyRequired` | 重定向到 `PAGE-SHARE-VERIFY` |
| 分享失效 | 收到分享不存在/过期错误码 | 关闭 Visitor Shell，提示分享已失效 |

### 7.2 认证错误与导航联动

#### 7.2.1 Owner 认证错误

| 错误场景 | 触发状态 | 导航动作 | 页面影响 |
|----------|---------|---------|---------|
| Access Token 过期 | Session → `Refreshing` | 不跳转 | 页面保持当前状态，等待刷新结果 |
| 刷新成功 | `Refreshing` → `Active` | 不跳转 | 自动重放失败请求，页面恢复 |
| 刷新失败 | `Refreshing` → `ReauthRequired` | 重定向到 `PAGE-LOGIN` | 清空所有页面栈 |
| 用户登出 | `Active` → `LogoutPending` → `LoggedOut` | 重定向到 `PAGE-LOGIN` | 清空所有页面栈 |
| 存储配额不足 | 保持 `Active` | 不跳转 | 当前页面展示配额不足提示，阻止继续上传 |

#### 7.2.2 Visitor 认证错误

| 错误场景 | 触发状态 | 导航动作 | 页面影响 |
|----------|---------|---------|---------|
| Share Token 过期 | `Active` → `ReverifyRequired` | 重定向到 `PAGE-SHARE-VERIFY` | 清空浏览页面 |
| Share Token 撤销 | `Active` → `ReverifyRequired` | 重定向到 `PAGE-SHARE-VERIFY` | 同上 |
| 密码错误 | `Unverified` → `Unverified` | 保持在 `PAGE-SHARE-VERIFY` | 清空密码输入框，展示错误提示 |
| 分享不存在/过期 | 任意 | 关闭 Visitor Shell | 提示分享已失效 |
| 下载权限不足 | 保持 `Active` | 不跳转 | 禁用下载按钮，浏览继续 |
