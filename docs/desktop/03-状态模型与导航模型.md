# 桌面客户端 - 状态模型与导航模型

## 1. 文档说明

### 1.1 文档目的

本文定义 Shell 路由、PAGE/VIEW 状态、选择集合和短时反馈之间的转换。DOC-01 决定对象属于 Shell、PAGE 还是 VIEW；DOC-02 决定它如何呈现；DOC-04 提供当前实现与可执行测试证据。

### 1.2 权威来源

- DOC-00 的会话、认证域和状态证据规则；
- DOC-01 的页面 taxonomy；
- DOC-02 的交互合同；
- `clients/desktop/src/app/ShellController.cpp`、`clients/desktop/qml/Main.qml` 与各 Shell/Page 当前实现；
- DOC-04 的测试证据索引。

### 1.3 冻结不变量

1. `currentShell` 决定活动顶层 Shell；`pageState` 不能替代 Shell 路由。
2. PAGE-DRIVE 的 VIEW 切换不 push Owner StackView 页面。
3. Owner 与 Visitor Session 可以并存，但请求认证域和页面状态不能串用。
4. 页面只有在真实数据/信号驱动下才可声明 loading/content/empty/error；单独声明属性不构成实现。
5. 当前多选状态是数组集合；修饰键和范围锚点在实现前保持规划。

## 2. ID 规则

### 2.1 VIEW

| ID | 定义 |
|---|---|
| VIEW-MYFILES | PAGE-DRIVE 内的我的文件模式 |
| VIEW-SHARED | PAGE-DRIVE 内的 Owner 已共享模式 |
| VIEW-TRASH | PAGE-DRIVE 内的回收站模式 |

### 2.2 PAGE

页面 ID 的完整定义见 DOC-01 §3.2。状态模型涉及的页面为 PAGE-SPLASH、PAGE-LOGIN、PAGE-REGISTER、PAGE-DRIVE、PAGE-TRANSFER、PAGE-SETTINGS、PAGE-SHARE-VERIFY、PAGE-SHARE-BROWSE、PAGE-ADMIN-USERS、PAGE-ADMIN-SHARES、PAGE-ADMIN-LOGS、PAGE-ADMIN-SYSTEM。

### 2.3 STATE

| ID | 通用语义 |
|---|---|
| STATE-IDLE | 尚未发起操作或任务静止 |
| STATE-LOADING | 正在获取当前内容；可选择隐藏或保留缓存内容 |
| STATE-CONTENT | 当前数据可呈现 |
| STATE-EMPTY | 请求成功但当前集合为空 |
| STATE-ERROR | 当前操作失败且需要展示/重试 |
| STATE-BUSY | 表单提交或 mutation 正在执行，相关控件禁用 |
| STATE-VERIFY | Visitor 需要输入或重新输入验证信息 |
| STATE-BATCH-RESULT | 批量操作结果列表 |

这些是语义 ID，不要求所有页面实现全部状态。各页面的实际支持范围见 §4。

### 2.4 FLOW

| ID | 定义 |
|---|---|
| FLOW-STARTUP | splash 后恢复/选择 Shell |
| FLOW-AUTH | 登录、注册与认证结果路由 |
| FLOW-FOLDER-NAVIGATE | PAGE-DRIVE 内文件夹钻取 |
| FLOW-VIEW-SWITCH | PAGE-DRIVE 内 VIEW 切换 |
| FLOW-PAGE-SWITCH | Owner 独立页面替换 |
| FLOW-VISITOR-ACCESS | 分享验证与浏览 |
| FLOW-ADMIN-LOGIN | 管理员角色进入 Admin Shell |

## 3. Shell 与导航模型

### 3.1 FLOW-STARTUP

```text
Application 初始化
  -> currentShell = splash, pageState = loading
  -> SessionStore 恢复 Owner 状态
      -> 未认证：login
      -> 普通用户：owner
      -> 管理员：admin
```

该流程为 `[已实现]`。证据包括 DOC-04 §3.1、§6.1 中 `InitDefaultsToSplash`、`UnauthenticatedNavigatesToLogin`、`AuthenticatedNavigatesToOwner` 和 `AdminUserNavigatesToAdminShell`。

### 3.2 FLOW-AUTH

Auth Shell 在同一个窗口中用 Loader 切换 PAGE-LOGIN/PAGE-REGISTER。提交时页面进入 STATE-BUSY，禁用输入、提交和模式切换；成功由 Owner 状态与角色驱动 Shell 路由，失败保留页面并显示内联错误。

该流程为 `[已实现]`，证据见 DOC-04 §3.1、§6.2。注册成功计时返回登录，切换页面时调用 `resetState()` 清理 busy/error。

### 3.3 Owner Shell

#### 3.3.1 默认页面

进入 Owner Shell 后默认显示 PAGE-DRIVE/VIEW-MYFILES。该行为为 `[已实现]`，由 OwnerShell Quick Test 验证；它不是应用初始化默认 Shell，初始化默认仍是 splash。

#### 3.3.2 FLOW-VIEW-SWITCH

```text
Sidebar 文件类别入口
  -> OwnerShell.showDriveViewMode(mode)
  -> 复用/恢复 DriveBrowserPage 主机
  -> DriveBrowserPage.activateViewMode(mode)
  -> 清选择 + 收起目录树 + 分发对应 Manager 刷新
  -> 只切换 DriveMyFilesView / DriveSharedView / DriveTrashView
```

该流程为 `[已实现]`，证据见 DOC-04 §6.3、§6.6。模式往返保留各子视图内容状态，但不保留跨模式选择。

#### 3.3.3 FLOW-PAGE-SWITCH

传输中心和设置通过 `showPage(...)` 替换 Owner StackView 内容；返回文件类别时恢复同一 DriveBrowser 主机。该流程为 `[已实现]`，证据见 DOC-04 §6.3。

#### 3.3.4 FLOW-FOLDER-NAVIGATE

```text
双击文件夹 / 树节点 / 面包屑 / 返回上级
  -> navigateToFolder(folderId)
  -> 清理选择和搜索
  -> 不保留旧目录内容作为新目录内容
  -> 并行触发树、面包屑、列表加载
  -> paginationLoaded / listLoadFailed
  -> content | empty | error
```

该流程为 `[已实现]`。连续、快速、未知目录和模型 reset 行为均有运行时 Quick Test，见 DOC-04 §6.6。

### 3.4 FLOW-VISITOR-ACCESS

```text
分享入口
  -> SessionStore.activateVisitor(shareId)
  -> VisitorShell / PAGE-SHARE-VERIFY
  -> verify(shareId, optional password)
      -> verifying/loading
      -> active/content -> PAGE-SHARE-BROWSE
      -> password error/unverified -> verify
      -> expired -> 关闭 Visitor；有有效 Owner 则回 Owner，否则回 Login
```

该流程为 `[已实现]`，证据见 DOC-04 §6.4。`ShareVerifyPage` 在 shareId 变化时发起空密码验证尝试；是否需要密码由响应决定，而不是预先假设。

进入 Visitor 不清除有效 Owner token。Visitor 下载只使用分享认证头；返回 Owner 时仍由 Owner 状态守卫决定是否允许。

### 3.5 FLOW-ADMIN-LOGIN

Owner 登录成功后，`ShellController` 根据角色进入 Admin 或 Owner。AdminShell 在四个持久化 Loader 之间切换：PAGE-ADMIN-USERS、PAGE-ADMIN-SHARES、PAGE-ADMIN-LOGS、PAGE-ADMIN-SYSTEM。

该流程为 `[已实现]`，证据见 DOC-04 §6.1、§6.5。角色变为普通用户或认证失效时清理 Owner 会话并返回登录；Admin 目的地不使用 Owner StackView。

## 4. 页面与视图状态

### 4.1 通用转换

```text
idle -> loading -> content
                 -> empty
                 -> error -> loading (retry)

content/empty -> loading (refresh)
content -> busy (mutation) -> content | error
content -> batch-result -> content
```

保留缓存刷新是 loading 的呈现策略，不是新的状态：只有当前范围不变且显式设置 preserve 标志时，旧内容可以在 loading 期间继续可见。

### 4.2 PAGE-DRIVE / VIEW-MYFILES

| 状态 | 触发/呈现 | 当前状态 | 证据 |
|---|---|---|---|
| STATE-LOADING | 首次加载、目录切换或刷新 | `[已实现]` | DOC-04 §4.1、§6.6 |
| STATE-CONTENT | 列表有项目 | `[已实现]` | DOC-04 §4.1、§6.6 |
| STATE-EMPTY | 列表成功且为空 | `[已实现]` | DOC-04 §4.1、§6.6 |
| STATE-ERROR | `listLoadFailed`，显示重试 | `[已实现]` | DOC-04 §4.1、§6.6 |
| 保留式刷新 | 同目录刷新时缓存内容保持可见 | `[已实现]` | DOC-04 §6.6 |

文件夹切换明确不保留旧目录内容。mutation 成功后保持当前文件夹并刷新；无 pending mutation 的成功信号不会错误刷新。

### 4.3 VIEW-SHARED

STATE-LOADING、STATE-CONTENT、STATE-EMPTY、STATE-ERROR 与 STATE-BATCH-RESULT 均为 `[已实现]`，由 ShareManager 信号驱动并在 `DriveSharedView` 内呈现。取消、复制和详情不会调用 DriveManager。Toolbar 访客入口已经接线但测试仍指向拆分前组件，保持 `[待验证]`；证据与缺口见 DOC-04 §4.6、§6.10。

### 4.4 VIEW-TRASH

STATE-LOADING、STATE-CONTENT、STATE-EMPTY、STATE-ERROR 与 STATE-BATCH-RESULT 均为 `[已实现]`，由 TrashManager 信号驱动并在 `DriveTrashView` 内呈现。恢复、永久删除和清空不会调用 DriveManager。证据见 DOC-04 §4.7、§6.11。

### 4.5 PAGE-TRANSFER

- `[已实现]` 上传与下载 Tab 的任务内容和空列表呈现；
- `[已实现]` 单任务进度、状态详情、失败和暂停/继续状态；
- `[已实现]` 清理完成/取消任务。

任务来自内存 Model，因此不虚构页面级远端 loading 状态。证据见 DOC-04 §4.8、§6.12。

分布式后端完成上传期间，`POST /api/file/upload/complete` 可能返回 HTTP 409 / `ResourceConflict` 并携带 `Retry-After`。该响应表示另一实例持有有效完成租约，不是终态失败：上传任务保持 `Completing`，按服务端等待时间自动重试；客户端没有收到 `Retry-After` 时使用有上限的指数退避。网络超时或响应丢失也重放同一 `upload_id` 的 complete，不重新初始化上传。后端返回已完成文件时转为 `Completed`，返回 `Cancelled`、`Expired` 或 `Failed` 终态时才转为对应终态并停止自动重试。

自动重试必须有总时限和取消入口；用户取消只停止客户端重试并调用取消 API，若后端已进入 `Finalizing` 且返回冲突，界面保持可恢复状态并继续查询/重放 complete，不能显示“取消成功”。该合同在客户端适配和测试完成前标记为 `[规划]`。

### 4.6 PAGE-SETTINGS

- `[已实现]` 页面内容骨架、服务端连接设置和密码修改反馈；
- `[待验证]` 个人资料读取/更新的完整 loading/content/error 渲染流程；
- `[规划]` 在补足真实信号和测试前，不声明 PAGE-SETTINGS 拥有通用 STATE-LOADING 或 STATE-ERROR 页面切换。

当前页面的 `pageState: "content"` 常量不能作为 loading/error 已实现证据。现有证据与缺口见 DOC-04 §4.9、§6.13。

### 4.7 PAGE-LOGIN / PAGE-REGISTER

| 状态 | 当前行为 | 状态 |
|---|---|---|
| STATE-IDLE | 表单可编辑 | `[已实现]` |
| STATE-BUSY | 输入、提交与模式切换禁用，按钮文字变化 | `[已实现]` |
| STATE-ERROR | 页面保留并显示字段/请求错误 | `[已实现]` |
| 注册成功 | 显示确认并计时返回登录 | `[已实现]` |

运行时证据见 DOC-04 §6.2。

### 4.8 Visitor 页面

| Visitor 状态 | pageState | 页面 | 当前状态 |
|---|---|---|---|
| Idle/Unverified | STATE-VERIFY | PAGE-SHARE-VERIFY | `[已实现]` |
| Verifying/ReverifyRequired | STATE-LOADING | 当前 Visitor Shell | `[已实现]` |
| Active | STATE-CONTENT | PAGE-SHARE-BROWSE | `[已实现]` |
| Password error | STATE-VERIFY | PAGE-SHARE-VERIFY + 内联错误 | `[已实现]` |
| Expired | 关闭 Visitor | Owner 或 Login | `[已实现]` |

证据见 DOC-04 §6.4。

### 4.9 Admin 页面

用户、分享和日志列表的 loading/content/empty/error 由 `AdminPage` 与 `AdminManager` 驱动；系统目的地呈现概览、存储、连接和系统信息。四个目的地及其请求/错误路径为 `[已实现]`，证据见 DOC-04 §4.11、§6.5。

## 5. 选择模型

### 5.1 当前选择状态

PAGE-DRIVE 使用并行数组保存项目 ID、类型和名称，同时派生第一个选中项以兼容单项 Dialog。以下能力为 `[已实现]`：

| 行为 | 状态转换 |
|---|---|
| 行单击 | `clearSelection()` 后写入当前项 |
| 复选框选中 | `toggleItemSelection()` 向集合添加项目 |
| 复选框取消 | 从集合删除对应索引 |
| 右键未选项 | 先变为唯一选择，再打开菜单 |
| 右键已选项 | 保留当前集合 |
| 右键空白区 | 保留当前集合，打开当前目录菜单 |
| 文件夹导航 | 清空选择 |
| VIEW 切换 | 清空选择 |

实现/测试证据见 DOC-04 §4.4、§6.7。

### 5.2 规划中的键盘/范围选择

以下能力统一为 `[规划]`：Ctrl+单击、Shift+单击范围、鼠标框选/套索、Ctrl+A 与完整方向键锚点模型。

完成这些能力需要新增：

- `anchorIndex` 与 `focusIndex` 的明确状态；
- 过滤、排序、分页和模式切换时的锚点处理；
- 与复选框、右键和批量命令一致的集合更新；
- Qt Quick Test 覆盖修饰键组合、范围边界和键盘焦点。

DOC-02 §4.4 只列用户交互；本节是规划状态模型的唯一规范定义。

## 6. Transient Feedback 模型

### 6.1 Dialog

Dialog 阻塞当前命令，适用于输入、目标选择、详情和破坏性确认。移动、复制、分享、文件详情和 Owner 分享详情均为 `[已实现]`，证据见 DOC-04 §4.2、§4.6。

### 6.2 Toast

Toast 不改变页面状态，只短时报告 mutation 结果。PAGE-DRIVE `driveToast` 与分享链接复制反馈为 `[已实现]`，证据见 DOC-04 §6.7、§6.10。

### 6.3 Progress

Progress 属于长任务状态，必须与任务 ID、已完成字节和状态详情绑定。PAGE-TRANSFER 的上传/下载进度为 `[已实现]`，证据见 DOC-04 §6.12。

### 6.4 Skeleton

Skeleton 是 `[规划]`，不改变 loading 状态本身。规划规范只在 DOC-02 §5.5 定义；当前 spinner、空态和保留缓存不是 Skeleton。

### 6.5 优先级

1. 需要用户决策或确认：Dialog；
2. 长任务持续状态：Progress；
3. 页面数据获取：PageStateView 的 loading/content/empty/error；
4. 轻量完成反馈：Toast；
5. Skeleton 仅在规划实现后作为 loading 的视觉策略。

## 7. 路由守卫与认证错误

### 7.1 Owner/Admin 守卫

- 未认证访问 Owner/Admin 重定向 PAGE-LOGIN；
- Owner Refreshing 期间允许保留 Owner Shell 并进入 loading；
- ReauthRequired 清理 Owner token 并回登录；
- 管理员角色进入 Admin，普通角色进入 Owner；
- Admin 角色降级触发退出。

以上为 `[已实现]`，证据见 DOC-04 §6.1。

### 7.2 Visitor 守卫

- Visitor 验证失败留在 Visitor Shell；
- 密码错误进入 STATE-VERIFY；
- 过期关闭 Visitor，并根据有效 Owner 状态返回 Owner 或 Login；
- Visitor 路由与令牌变化不污染 Owner 状态。

以上为 `[已实现]`，证据见 DOC-04 §6.4、§6.14。

## 8. 冲突修正记录

| 旧说法 | 当前结论 |
|---|---|
| 应用启动默认进入 Owner | 启动默认 splash，再根据会话路由 |
| 已共享/回收站是 Owner 独立页面 | 它们是 PAGE-DRIVE 内 VIEW，复用主机 |
| DriveBrowser 仍是全部 UI 的单体文件 | 主机负责编排，三个 VIEW 和多项组件已拆分 |
| 文件夹双击、搜索、排序、上下文菜单、多选尚未实现 | 这些具体行为已有实现与测试，见 DOC-04；修饰键多选仍规划 |
| grid 属性存在即网格已实现 | 当前只切换紧凑 ListView；真实二维网格仍规划 |
| 有页码参数即用户可见分页完成 | 当前无可见控件/触发/反馈，仍规划 |
| 进入 Visitor 必须注销 Owner | 活动 Shell 互斥，会话可并存且认证头隔离 |
| Settings 声明 pageState 即拥有完整状态机 | 当前常量 content 不能证明 loading/error，资料流程待验证 |
