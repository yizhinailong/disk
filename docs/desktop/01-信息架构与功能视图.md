# 桌面客户端 — 信息架构与功能视图

## 1. 文档说明

### 1.1 文档目的

本文档定义桌面客户端的完整信息架构（Information Architecture）与功能分区。目标是把 DOC-00 中定义的双产品流、资源管理器定位和范围边界拆解为可操作的功能视图、页面分类和 taxonomy，为 DOC-02（布局与交互）、DOC-03（状态与导航）和 DOC-04（组件与实现映射）提供唯一 IA 基线。

### 1.2 权威来源

| 来源 | 路径 | 用途 |
|------|------|------|
| 文档治理基线 | `docs/desktop/00-桌面客户端系统概述与文档治理.md` | 权威层级、状态标签、ID 前缀 |
| 后端 API 接口设计 | `docs/design/02-API接口设计.md` | 接口路由与响应结构 |
| 当前实现锚点 | `clients/desktop/qml/shells/OwnerShell.qml` | 所有者 Shell 顶层结构 |
| 当前实现锚点 | `clients/desktop/qml/pages/DriveBrowserPage.qml` | 文件浏览页面 |
| 当前实现锚点 | `clients/desktop/qml/components/FolderTreePanel.qml` | 目录树面板组件 |
| 当前实现锚点 | `clients/desktop/qml/components/BreadcrumbBar.qml` | 面包屑导航组件 |

### 1.3 冻结不变量

1. 文件相关主页是 **共享资源管理器上下文**，侧栏文件类入口是 view mode 切换，不是跳转到不同页面。
2. `FolderTreePanel` 和 `BreadcrumbBar` 是组件（`COMP-`），不是页面（`PAGE-`）。
3. `已共享`（Owner 视角查看自己发出的分享）与访客分享浏览（Visitor Shell）是两个不同概念，不得混写。
4. 收藏视图必须纳入 IA，不得遗漏。
5. 文件视图模式切换不离开资源管理器上下文，仅改变主内容区的数据源和呈现规则。
6. `传输中心` 和 `设置/个人信息` 是独立功能页，不是文件视图模式。

## 2. Shell 架构

桌面客户端在同一进程中运行两个互斥的 Shell。同一时刻只有一个 Shell 处于活跃状态。

### 2.1 Owner Shell（所有者 Shell）

Owner Shell 是已注册用户登录后的主界面容器。它使用 `ApplicationWindow` 作为顶层窗口，内部通过 `RowLayout` 分为左侧导航栏（Sidebar）和右侧内容区，右侧内容区使用 `StackView` 管理页面。

#### 2.1.1 结构

```
OwnerShell (ApplicationWindow)
├── Sidebar                          # 左侧导航栏（固定可见）
│   ├── 品牌区                       # Disk / Workspace
│   ├── 导航区
│   │   ├── 文件视图模式入口组
│   │   │   ├── 我的文件 (VIEW-MYFILES)
│   │   │   ├── 最近使用 (VIEW-RECENT)
│   │   │   ├── 已共享 (VIEW-SHARED)
│   │   │   ├── 回收站 (VIEW-TRASH)
│   │   │   └── 收藏 (VIEW-FAVORITES)
│   │   └── 独立页面入口组
│   │       └── 传输中心 (PAGE-TRANSFER)
│   ├── 存储统计卡片                 # 已用/配额 进度条
│   └── 会话区                       # 登出按钮
└── 内容区
    ├── Header                       # 页面标题 + 副标题 + 用户信息卡片
    └── StackView                    # 页面内容
        ├── 资源管理器页 (PAGE-DRIVE) # 默认首页，承载五个文件视图模式
        ├── 传输中心页 (PAGE-TRANSFER)
        └── 设置页 (PAGE-SETTINGS)   # 包含个人资料、密码修改、存储统计
```

#### 2.1.2 当前的实现差距

当前 `OwnerShell.qml` 的 Sidebar 已分为两组：**File Views**（文件视图模式入口组）和 **Independent Pages**（独立页面入口组）。File Views 组包含 My Files、Recent（禁用，"Soon" 标记）、Shares、Trash、Favorites（禁用，"Soon" 标记）五个入口。Shares 和 Trash 已通过 `showDriveViewMode()` 实现为 `DriveBrowserPage` 内部的视图模式切换（对应 `DriveSharedView` 和 `DriveTrashView` 嵌入式视图），不再作为独立页面。当前实现与目标 IA 的差距如下：

| 维度 | 当前实现 | 目标 IA |
|------|---------|---------|
| Sidebar 分组 | 已实现 File Views + Independent Pages 两组 `OwnerSidebarSection` | ✅ 已对齐 |
| My Files 入口 | 已实现，`showDriveViewMode("myfiles")` | ✅ 已对齐 |
| Shares 入口 | 已实现为视图模式 `DriveSharedView`（嵌入 `DriveBrowserPage`） | ✅ 已对齐 |
| Trash 入口 | 已实现为视图模式 `DriveTrashView`（嵌入 `DriveBrowserPage`） | ✅ 已对齐 |
| Recent 入口 | Sidebar 入口存在但禁用（`enabled: false`，"Soon" 标记），点击无响应 | 待启用，需实现 `DriveRecentView` |
| Favorites 入口 | Sidebar 入口存在但禁用（`enabled: false`，"Soon" 标记），点击无响应 | 待启用，需实现 `DriveFavoritesView` 及后端 API |
| Transfers | 独立页面，通过 `stackView.replace()` 切换 | 保持为独立页面 `PAGE-TRANSFER`（无变化） |
| Settings | 独立页面，通过 `stackView.replace()` 切换 | 保持为独立页面 `PAGE-SETTINGS`（无变化） |

以上差距显示核心 Sidebar 分组和视图模式切换机制已落地，Recent 和 Favorites 的 Sidebar 入口已预留（禁用状态），待实现对应视图组件和后端支持后启用。实现映射详见 DOC-04。

### 2.2 Visitor Shell（访客 Shell）

Visitor Shell 是通过分享链接进入的独立浏览/下载流，不依赖所有者登录，不共享 Owner Shell 的导航结构。Visitor Shell 运行在 **独立 Visitor Shell** 中，不进入 Owner Shell 的导航树。

#### 2.2.1 结构

```
VisitorShell
├── ShareVerifyPage                  # 密码验证（如有密码保护）
└── ShareBrowsePage                  # 分享内容浏览 + 文件下载
```

#### 2.2.2 与 Owner Shell 的隔离规则

| 规则 | 说明 |
|------|------|
| 导航隔离 | Visitor Shell 不包含 Owner Sidebar，无法导航到传输中心、设置等所有者页面 |
| 认证域隔离 | 访客使用 Share Token（`X-Share-Token`），所有者使用 JWT（`Authorization: Bearer`），两套令牌不可混用 |
| 功能隔离 | 访客不支持上传、重命名、移动、复制、删除、创建文件夹、分享管理、回收站操作 |
| 生命周期隔离 | 所有者流和访客流不会同时处于活跃状态 |
| 下载权限降级 | 当 `permission == view` 时，访客可浏览但下载按钮禁用 |

### 2.3 认证前页面

认证前的页面不属于任何 Shell，在全局导航层面独立存在。

| 页面 | ID | 说明 |
|------|-----|------|
| SplashPage | PAGE-SPLASH | 应用启动画面，检查本地令牌、决定进入 LoginPage 或 OwnerShell |
| LoginPage | PAGE-LOGIN | 注册/登录表单，对应 O-01、O-02 |

## 3. 文件视图模式

### 3.1 概念定义

文件视图模式（View Mode）是资源管理器上下文中的数据视角切换。五个文件视图模式共享同一个三栏布局框架（Header + Sidebar + 主内容区），仅数据源、筛选策略和可用操作不同。切换视图模式 **不离开资源管理器上下文**，不触发 StackView 页面替换，仅改变 `PAGE-DRIVE` 内部的数据绑定。

这一设计的核心约束来自 DOC-00 §3.1：文件相关侧栏入口共享同一个三栏布局框架，仅数据源和筛选/排序策略不同。

### 3.2 五个文件视图模式

#### 3.2.1 VIEW-MYFILES（我的文件）

| 属性 | 值 |
|------|-----|
| ID | `VIEW-MYFILES` |
| 中文名称 | 我的文件 |
| 数据源 | `GET /api/file/list`，按 `parent_id` 分页加载 |
| 默认排序 | 名称升序 |
| 文件夹钻取 | 支持。通过 `currentFolderId` 同页切换，不是 push 新页面 |
| 面包屑 | 支持。`GET /api/folder/{folder_id}/breadcrumb` |
| 目录树 | 支持。`GET /api/folder/tree`（Popup 弹出，非常驻） |
| 可用操作 | 上传、下载、新建文件夹、重命名、移动、复制、删除、搜索、创建分享 |
| 功能编号 | O-05, O-06, O-07, O-08, O-09, O-10, O-11, O-12, O-13, O-14, O-15, O-16, O-17 |
| 实现状态 | `[已实现]` 基础列表浏览、同页文件夹钻取、面包屑、重命名、删除、上传、下载、新建文件夹 |

## 4. 独立功能页

独立功能页不属于资源管理器上下文，在 Owner Shell 的 StackView 中作为独立页面存在。点击 Sidebar 的独立页面入口时，通过 `stackView.replace()` 替换当前页面内容。

### 4.1 PAGE-TRANSFER（传输中心）

| 属性 | 值 |
|------|-----|
| ID | `PAGE-TRANSFER` |
| 中文名称 | 传输中心 |
| 页面职责 | 展示上传/下载任务列表及进度 |
| 数据源 | `transferManager.uploadModel`、`transferManager.downloadModel`（内存中的任务队列） |
| 可用操作 | 暂停、继续、取消、重试传输任务 |
| 功能编号 | O-08（上传进度）、O-09（下载进度） |
| 实现状态 | `[已实现]` 当前以独立页面 `TransferCenterPage` 存在 |

传输中心不是文件视图模式。它不展示文件列表、不支持文件夹钻取、不与资源管理器的三栏布局绑定。它是一个独立的全局任务监控页。

### 4.2 PAGE-SETTINGS（设置/个人信息）

| 属性 | 值 |
|------|-----|
| ID | `PAGE-SETTINGS` |
| 中文名称 | 设置 |
| 页面职责 | 查看和修改用户资料、修改密码、查看存储统计 |
| 数据源 | `GET /api/user/profile`、`GET /api/user/storage` |
| 可用操作 | 修改昵称、修改头像、修改密码 |
| 功能编号 | O-26, O-27, O-28, O-29 |
| 实现状态 | `[已实现]` 当前以独立页面 `SettingsPage` 存在 |

设置页不是文件视图模式。它展示的是用户账户信息而非文件内容。

### 4.3 独立功能页与文件视图模式的关系

| 维度 | 文件视图模式 (VIEW-*) | 独立功能页 (PAGE-*) |
|------|----------------------|-------------------|
| Sidebar 行为 | 高亮当前视图模式，不替换 StackView 页面 | 替换 StackView 栈顶页面 |
| 共享布局 | 共享资源管理器三栏框架 | 独立页面布局 |
| 文件夹钻取 | 部分支持（VIEW-MYFILES） | 不涉及 |
| 数据源 | 文件/分享/回收站 API | 传输任务队列 / 用户信息 API |

## 5. Owner 侧 `已共享` 与访客分享浏览的区分

这是 IA 层面最关键的概念隔离之一。`VIEW-SHARED`（已共享）和 Visitor Shell 的分享浏览虽然都涉及"分享"概念，但属于完全不同的功能流和认证域。

### 5.1 概念对照

| 维度 | VIEW-SHARED（Owner 侧已共享） | Visitor Shell 分享浏览 |
|------|------|------|
| 触发方式 | Owner 在 Sidebar 点击"已共享"视图模式 | 访客通过分享链接进入 |
| 认证域 | JWT（Owner Auth Domain） | Share Token（Visitor Auth Domain） |
| 视角 | 分享的 **创建者/管理者** | 分享的 **消费者/访问者** |
| 可见数据 | 自己创建的所有分享记录（含已过期、已取消） | 单个分享的文件/文件夹内容 |
| 核心操作 | 创建分享、更新设置、取消分享 | 浏览文件、下载文件 |
| Shell 归属 | Owner Shell，资源管理器上下文内的视图模式 | 独立 Visitor Shell |
| 页面/视图 | `VIEW-SHARED`（视图模式） | `ShareBrowsePage`（页面） |

### 5.2 数据流隔离

```
Owner 侧:
  Sidebar "已共享" → VIEW-SHARED 激活 → 调用 GET /api/share（JWT 认证）
  → 展示分享列表 → 管理分享（创建/更新/取消）

Visitor 侧:
  分享链接 → ShareVerifyPage（输入密码） → 获取 Share Token
  → ShareBrowsePage → 调用 GET /api/share/browse/{share_id}（Share Token 认证）
  → 浏览文件/下载
```

这两条数据流使用不同的后端接口、不同的认证头、不同的数据模型，在 IA 和实现层面都完全隔离。

## 6. 页面 taxonomy 与对象分类

本节建立 IA 层面的页面 taxonomy 约束，明确页面（page）、视图模式（view mode）、面板（panel）、组件（component）、瞬态 UI（transient UI）五类对象的边界。详细的组件级实现映射由 DOC-04 定义。

### 6.1 对象分类定义

| 类型 | 前缀 | 定义 | 特征 | 示例 |
|------|------|------|------|------|
| 页面 (page) | `PAGE-` | 在 StackView 中独立存在的完整内容区域 | 有自己的 Header 标题和副标题；通过 Sidebar 独立页面入口触发 `stackView.replace()` | `PAGE-DRIVE`、`PAGE-TRANSFER`、`PAGE-SETTINGS`、`PAGE-LOGIN`、`PAGE-SPLASH` |
| 视图模式 (view mode) | `VIEW-` | 资源管理器上下文内的数据视角，不是独立页面 | 共享 `PAGE-DRIVE` 的三栏布局；切换不触发 StackView 操作；通过 Sidebar 文件视图入口激活 | `VIEW-MYFILES`、`VIEW-RECENT`、`VIEW-SHARED`、`VIEW-TRASH`、`VIEW-FAVORITES` |
| 面板 (panel) | `COMP-` | 嵌入页面或弹出显示的功能区域，承载特定交互能力 | 不是 StackView 的独立项；生命周期依附于父页面 | `COMP-FOLDERTREE`（目录树面板，Popup 弹出） |
| 组件 (component) | `COMP-` | 可复用的 UI 元素，嵌入页面/面板中使用 | 不独立导航；通过属性和信号与父级通信 | `COMP-BREADCRUMB`（面包屑导航栏）、`COMP-PAGESTATEVIEW`（页面状态切换视图） |
| 瞬态 UI (transient) | 无统一前缀 | 模态或非模态的临时浮层，不参与导航栈 | 由用户操作触发显示，关闭后回到触发前的状态 | 对话框（新建文件夹、重命名、删除确认）、文件选择器、分享创建弹窗、toast 通知 |

### 6.2 Taxonomy 不变量

1. `FolderTreePanel` 是面板（`COMP-FOLDERTREE`），不是页面。它以 Popup 形式弹出，嵌入在 `PAGE-DRIVE` 中。
2. `BreadcrumbBar` 是组件（`COMP-BREADCRUMB`），不是页面。它嵌入在 `PAGE-DRIVE` 的内容区内。
3. `PageStateView` 是组件（`COMP-PAGESTATEVIEW`），不是页面。它根据 `pageState` 属性在 loading/empty/content/error 之间切换显示。
4. 五个文件视图模式（`VIEW-*`）不是五个独立页面，而是 `PAGE-DRIVE` 内部的五种数据视角。
5. `PAGE-DRIVE` 是唯一承载文件视图模式的页面。Sidebar 的文件视图入口切换 `PAGE-DRIVE` 内部的数据绑定，不替换 StackView。

### 6.3 分类判断规则

遇到新的 UI 元素时，按以下规则判断其 taxonomy 类型：

| 问题 | 判断 |
|------|------|
| 它是否在 StackView 中作为独立项存在？ | 是 → page（`PAGE-`） |
| 它是否是资源管理器上下文中的数据视角？ | 是 → view mode（`VIEW-`） |
| 它是否是弹出式或嵌入式功能区域？ | 是 → panel（`COMP-`） |
| 它是否是可复用的原子级 UI 元素？ | 是 → component（`COMP-`） |
| 它是否是临时浮层，关闭后恢复原始状态？ | 是 → transient UI |

## 7. 功能视图到后端 API 映射

本节概述每个功能视图对应的 API 范围。具体的请求/响应结构和错误处理由 DOC-02 和 DOC-03 定义。

### 7.1 资源管理器上下文（PAGE-DRIVE）

| 视图模式 | 主要 API | 辅助 API |
|----------|---------|---------|
| VIEW-MYFILES | `GET /api/file/list` | `GET /api/folder/tree`, `GET /api/folder/{id}/breadcrumb`, `GET /api/file/search`, `GET /api/file/{id}` |
| VIEW-RECENT | `GET /api/file/list`（按 `updated_at` 排序） | `GET /api/file/{id}` |
| VIEW-SHARED | `GET /api/share` | `GET /api/share/{id}`, `POST /api/share`, `PUT /api/share/{id}`, `DELETE /api/share` |
| VIEW-TRASH | `GET /api/trash` | `POST /api/trash/restore`, `DELETE /api/trash`, `DELETE /api/trash/all` |
| VIEW-FAVORITES | 待确认 | 待确认 |

### 7.2 独立功能页

|------|---------|

| PAGE-SETTINGS | `GET /api/user/profile`, `PATCH /api/user/profile`, `PUT /api/user/password`, `GET /api/user/storage` |

### 7.3 Visitor Shell

| 页面/阶段 | API |
|-----------|-----|
