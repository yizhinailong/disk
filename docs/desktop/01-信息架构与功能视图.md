# 桌面客户端 - 信息架构与功能视图

## 1. 文档说明

### 1.1 文档目的

本文定义桌面客户端的 Shell、独立页面、PAGE-DRIVE 文件视图模式及其功能边界。布局与交互由 DOC-02 负责，状态和导航由 DOC-03 负责，实现与测试证据由 DOC-04 负责。

### 1.2 权威来源

- DOC-00 的产品边界、状态标签与认证域规则；
- `clients/desktop/qml/Main.qml` 与 `clients/desktop/qml/shells/` 的当前 Shell 结构；
- `clients/desktop/qml/pages/` 与 `clients/desktop/qml/components/drive/` 的当前页面/视图结构；
- DOC-04 的稳定实现锚点和可执行测试证据。

### 1.3 冻结不变量

1. 三个文件视图复用一个 PAGE-DRIVE 主机；文件类别入口切换 VIEW，不创建新的 Owner 顶层页面。
2. PAGE-DRIVE、PAGE-TRANSFER、PAGE-SETTINGS 是 Owner Shell 唯一三个顶层页面。
3. Visitor Shell 只承载 PAGE-SHARE-VERIFY 和 PAGE-SHARE-BROWSE。
4. Admin Shell 有四个内部目的地，使用持久化 Loader，不描述为 Owner 页面或 Visitor 页面。
5. `已共享` 始终区分 Owner 管理视图与 Visitor 分享浏览。

## 2. Shell 架构

### 2.1 顶层路由

`Main.qml` 根据 `ShellController.currentShell` 呈现一个活动 Shell。初始化先进入 PAGE-SPLASH，再根据 Owner 会话和角色进入认证、Owner 或 Admin；分享入口可转入 Visitor。

| Shell/入口 | 页面或目的地 | 当前状态 | 证据 |
|---|---|---|---|
| Splash | PAGE-SPLASH | `[已实现]` | DOC-04 §3.1、§6.1 |
| Auth Shell | PAGE-LOGIN、PAGE-REGISTER | `[已实现]` | DOC-04 §3.1、§6.2 |
| Owner Shell | PAGE-DRIVE、PAGE-TRANSFER、PAGE-SETTINGS | `[已实现]` | DOC-04 §3.1、§6.3 |
| Visitor Shell | PAGE-SHARE-VERIFY、PAGE-SHARE-BROWSE | `[已实现]` | DOC-04 §3.1、§6.4 |
| Admin Shell | PAGE-ADMIN-USERS、PAGE-ADMIN-SHARES、PAGE-ADMIN-LOGS、PAGE-ADMIN-SYSTEM | `[已实现]` | DOC-04 §3.1、§6.5 |

活动 Shell 互斥不等于会话互斥。有效 Owner Session 可在 Visitor Shell 活动期间保留；请求仍由认证域隔离，见 DOC-00 §3.5。

### 2.2 Owner Shell

Owner Shell 由固定 Header、分组 Sidebar 和一个 StackView 页面主机组成：

```text
OwnerShell
├── Header
├── Sidebar
│   ├── 文件：我的文件 / 已共享 / 回收站
│   ├── 工具：传输中心
│   ├── 账户：设置
│   └── 会话：退出登录
└── StackView
    ├── PAGE-DRIVE (持久化 DriveBrowserPage 实例)
    ├── PAGE-TRANSFER
    └── PAGE-SETTINGS
```

`我的文件`、`已共享`、`回收站` 调用 `showDriveViewMode(...)` 并复用 PAGE-DRIVE；传输中心和设置调用 `showPage(...)` 替换 StackView 内容。运行时测试确认 DriveBrowser 主机在模式切换以及从独立页面返回时保持身份。

### 2.3 Visitor Shell

Visitor Shell 使用自己的 StackView：

```text
VisitorShell
└── StackView
    ├── PAGE-SHARE-VERIFY
    └── PAGE-SHARE-BROWSE
```

它没有 Owner Sidebar，不引用 Owner 文件导航；页面由 Visitor Session 状态和 `ShellController.pageState` 驱动。分享认证失败回到验证状态，不把请求降级为 Owner 域。

### 2.4 Admin Shell

Admin Shell 使用固定 Header、Sidebar 与四个持久化 Loader：

```text
AdminShell
├── Header
├── Sidebar
│   ├── 用户管理
│   ├── 分享管理
│   ├── 操作日志
│   ├── 系统状态
│   └── 退出登录
└── adminPageHost
    ├── adminUsersPageLoader
    ├── adminSharesPageLoader
    ├── adminLogsPageLoader
    └── adminSystemPageLoader
```

四个 Loader 保留各目的地实例，只切换 `visible/active`。Admin 使用 Owner JWT 和角色守卫，不引入 Admin 专用令牌域。

## 3. 页面与视图 taxonomy

### 3.1 对象分类

| 类别 | 定义 | 当前对象 |
|---|---|---|
| Shell | 顶层窗口与导航容器 | AuthShell、OwnerShell、VisitorShell、AdminShell |
| 独立页面 | Shell 导航的内容目的地 | PAGE-DRIVE、PAGE-TRANSFER、PAGE-SETTINGS 等 |
| 文件视图模式 | PAGE-DRIVE 内的数据源/操作模式 | VIEW-MYFILES、VIEW-SHARED、VIEW-TRASH |
| 嵌入组件 | 页面内可复用区域 | 工具栏、状态卡、树、面包屑、上下文菜单 |
| Transient UI | 短时覆盖反馈 | Dialog、Toast、Progress、规划中的 Skeleton |

文件视图模式可以拥有独立 QML 组件文件，但仍不因此成为独立页面。

### 3.2 页面 ID

| ID | 所属 Shell | 含义 |
|---|---|---|
| PAGE-SPLASH | Splash | 初始化与会话恢复入口 |
| PAGE-LOGIN | Auth | 登录 |
| PAGE-REGISTER | Auth | 注册 |
| PAGE-DRIVE | Owner | 持久化资源管理器主页 |
| PAGE-TRANSFER | Owner | 上传/下载任务中心 |
| PAGE-SETTINGS | Owner | 个人信息、密码和服务端连接设置 |
| PAGE-SHARE-VERIFY | Visitor | 分享 ID/密码验证 |
| PAGE-SHARE-BROWSE | Visitor | 分享目录浏览与访客下载 |
| PAGE-ADMIN-USERS | Admin | 用户查询、详情和状态/角色/空间操作 |
| PAGE-ADMIN-SHARES | Admin | 全局分享查询、详情与强制取消 |
| PAGE-ADMIN-LOGS | Admin | 操作日志查询 |
| PAGE-ADMIN-SYSTEM | Admin | 概览、存储、连接和系统信息 |

### 3.3 VIEW-MYFILES

VIEW-MYFILES 是 PAGE-DRIVE 的 Owner 文件管理模式。

| 能力 | 当前状态 | 说明/证据 |
|---|---|---|
| 文件夹树、面包屑、列表、上级导航 | `[已实现]` | DOC-04 §4.1、§6.6 |
| 文件夹双击进入、文件双击详情 | `[已实现]` | DOC-04 §4.2、§6.7 |
| 新建、重命名、移动、复制、删除 | `[已实现]` | DOC-04 §4.2、§6.8 |
| 上传、下载、分享创建 | `[已实现]` | DOC-04 §4.2、§6.9 |
| 搜索与六种排序 | `[已实现]` | DOC-04 §4.3、§6.7 |
| 行点击单选与复选框多选 | `[已实现]` | DOC-04 §4.4、§6.7 |
| 上下文菜单 | `[已实现]` | DOC-04 §4.5、§6.7 |
| 紧凑布局切换（隐藏列表列头/次要列） | `[已实现]` | DOC-04 §4.3、§6.7 |
| 真正二维网格 | `[规划]` | DOC-02 §3.5.1 是唯一规划定义 |
| Owner 可见分页/加载更多 | `[规划]` | DOC-02 §3.7 是唯一规划定义 |
| 内部/外部拖放 | `[规划]` | DOC-02 §4.5.1/§4.5.2 是唯一规划定义 |

### 3.4 VIEW-SHARED

VIEW-SHARED 展示当前 Owner 创建的分享，数据由 `ShareManager` 提供。当前已实现列表、空/错/加载/批量结果状态、链接复制反馈和详情/编辑/取消；Toolbar 中的访客入口已有接线，但现有 Quick Test 仍读取拆分前的旧组件，因此该入口为 `[待验证]`。具体证据与缺口见 DOC-04 §4.6、§6.10。

它不是 Visitor 分享浏览，也不使用 `X-Share-Token` 获取 Owner 分享列表。

### 3.5 VIEW-TRASH

VIEW-TRASH 展示 Owner 回收站，数据由 `TrashManager` 提供。当前已实现列表、空/错/加载/批量结果状态、复选框选择、恢复、永久删除和清空操作。具体证据见 DOC-04 §4.7、§6.11。

### 3.6 视图模式切换

`DriveBrowserPage.activateViewMode(mode)` 是 PAGE-DRIVE 内部模式切换入口：

- 复用同一个 DriveBrowser 实例；
- 清理跨模式选择并收起文件夹导航器；
- 将刷新分发到 Drive、Share 或 Trash Manager；
- 保留各子视图自身的已加载内容状态，以便切回；
- 不 push `ShareManagementPage` 或 `TrashPage`，当前树中也不存在这两个页面文件。

上述行为为 `[已实现]`，证据见 DOC-04 §3.1、§6.3、§6.6。

## 4. 独立功能页

### 4.1 PAGE-TRANSFER

PAGE-TRANSFER 是 `[已实现]` 的 Owner 独立页面，包含上传/下载 Tab、任务列表、进度、状态详情、暂停/继续以及清理已完成任务。它读取 `TransferManager` 暴露的上传/下载 Model，证据见 DOC-04 §4.8、§6.12。

### 4.2 PAGE-SETTINGS

PAGE-SETTINGS 包含个人资料、密码修改和服务端连接设置。页面和 Manager 已存在；当前可执行测试直接覆盖服务端连接区、页面基本布局和密码请求，但没有完整覆盖资料读取/更新的渲染交互，因此：

- `[已实现]` 服务端连接设置与密码修改；
- `[待验证]` 个人资料读取与更新的完整用户流程。

证据与缺口见 DOC-04 §4.9、§6.13。

## 5. Owner 已共享与 Visitor 分享浏览

| 维度 | VIEW-SHARED | PAGE-SHARE-BROWSE |
|---|---|---|
| 用户身份 | Owner | Visitor |
| 认证头 | `Authorization` | `X-Share-Token` |
| 数据范围 | Owner 创建的分享记录 | 单个已验证分享的内容 |
| 主要操作 | 复制、详情、编辑、取消 | 目录浏览、选择保存位置、下载 |
| 导航归属 | PAGE-DRIVE 内部模式 | Visitor Shell 独立页面 |
| 状态 | `[已实现]` | `[已实现]` |
| 证据 | DOC-04 §4.6、§6.10 | DOC-04 §4.10、§6.4 |

两者可以共享视觉组件或模型思想，但不得共享认证头、路由状态或 Manager 调用路径。

## 6. 功能视图与 API 域

| 功能区域 | 主要 Manager | API 契约区域 |
|---|---|---|
| VIEW-MYFILES | DriveManager、TransferManager、ShareManager | 文件、文件夹、上传、下载、分享 |
| VIEW-SHARED | ShareManager | Owner 分享管理 |
| VIEW-TRASH | TrashManager | 回收站 |
| PAGE-TRANSFER | TransferManager | 上传/下载生命周期 |
| PAGE-SETTINGS | ProfileManager、NetworkSettingsManager | 用户资料、密码、客户端连接设置 |
| Visitor 页面 | VisitorFlow、TransferManager | 分享验证、浏览、访客下载 |
| Admin 目的地 | AdminManager | 管理员用户、分享、日志、系统接口 |

请求和响应字段以 `docs/design/02-API接口设计.md` 为准；本表只定义信息架构归属。
