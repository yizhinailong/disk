# 桌面客户端 - 页面布局与交互规范

## 1. 文档说明

### 1.1 文档目的

本文规定 Owner Shell 与 PAGE-DRIVE 的布局、选择、鼠标交互和反馈。它明确区分当前可验证行为与规划行为，避免把存在属性、占位按钮或局部样式切换误判为完整功能。

### 1.2 权威来源

- DOC-00 的状态与证据规则；
- DOC-01 的 Shell、页面和 VIEW taxonomy；
- DOC-03 的状态、选择和导航模型；
- DOC-04 的实现锚点与可执行测试证据；
- `clients/desktop/qml/shells/OwnerShell.qml`、`clients/desktop/qml/pages/DriveBrowserPage.qml` 与 `clients/desktop/qml/components/drive/`。

### 1.3 冻结不变量

1. Shell Header 和 Sidebar 不进入 PAGE-DRIVE 的视图切换逻辑。
2. 三个文件视图复用一个 PAGE-DRIVE 主机。
3. 单击行不打开文件夹；文件夹打开使用双击或上下文菜单“打开”。
4. 当前多选入口是复选框；Ctrl、Shift、框选与 Ctrl+A 在完整实现前保持规划。
5. 当前所谓紧凑布局仍由 `ListView` 呈现，不能称为真实网格。
6. Manager 支持页码不等于用户可见分页/加载更多。
7. 内部拖放、外部拖入上传和骨架屏保持规划，直到存在端到端实现和测试。

## 2. Owner Shell 布局

### 2.1 Header

Owner Header 固定显示当前目的地标题/副标题，属于 Shell 层。PAGE-DRIVE 的搜索、排序、文件操作和视图切换必须留在页面内部，不在 Header 复制第二套控件。

此边界为 `[已实现]`，实现与运行时证据见 DOC-04 §3.1、§6.3。

### 2.2 Sidebar

Sidebar 从上到下分为文件、工具、账户、会话区域：

| 入口 | 行为 | 当前状态 | 证据 |
|---|---|---|---|
| 我的文件 | 进入 PAGE-DRIVE 的 VIEW-MYFILES | `[已实现]` | DOC-04 §3.1、§6.3 |
| 已共享 | 复用 PAGE-DRIVE 并切换 VIEW-SHARED | `[已实现]` | DOC-04 §3.1、§6.3 |
| 回收站 | 复用 PAGE-DRIVE 并切换 VIEW-TRASH | `[已实现]` | DOC-04 §3.1、§6.3 |
| 传输中心 | 替换为 PAGE-TRANSFER | `[已实现]` | DOC-04 §4.8、§6.12 |
| 设置 | 替换为 PAGE-SETTINGS | `[已实现]` | DOC-04 §4.9、§6.13 |
| 退出登录 | 走 Owner Session 退出路径 | `[已实现]` | DOC-04 §3.1、§6.3 |

Sidebar 在压缩高度下使用可滚动导航区，并将存储/会话卡片固定在底部；当前 Quick Test 验证分组、可见性和活动条样式。

## 3. PAGE-DRIVE 布局

### 3.1 结构

```text
DriveBrowserPage
├── COMP-DRIVE-TOOLBAR       DriveToolbarCard
├── COMP-DRIVE-STATUS        DriveStatusCard
├── COMP-FOLDER-TREE         FolderTreePanel（仅 VIEW-MYFILES）
├── VIEW-MYFILES             DriveMyFilesView
│   ├── COMP-BREADCRUMB      BreadcrumbBar
│   ├── 搜索 / 排序 / 紧凑布局切换
│   ├── PageStateView
│   ├── fileListView
│   └── COMP-CONTEXT-MENU    DriveContextMenu
├── VIEW-SHARED              DriveSharedView
├── VIEW-TRASH               DriveTrashView
├── Dialogs                  移动/复制/分享/详情等
└── COMP-TOAST               driveToast
```

上述拆分为 `[已实现]`，稳定组件和测试锚点见 DOC-04 §4.1、§6.6。`DriveBrowserPage` 仍负责状态编排、Manager 信号和操作对话框；具体视图渲染已经从单体页面拆分到 `components/drive`。

### 3.2 COMP-DRIVE-TOOLBAR

工具栏根据当前 VIEW 和选择状态显示可用命令：

| VIEW | 当前命令 | 状态 |
|---|---|---|
| VIEW-MYFILES | 返回上级、文件夹树开关、刷新、新建文件夹、上传、重命名、移动、复制、删除、下载、创建分享 | `[已实现]` |
| VIEW-SHARED | 刷新、取消所选分享 | `[已实现]` |
| VIEW-TRASH | 刷新、恢复所选、永久删除所选、清空回收站 | `[已实现]` |

按钮按 VIEW、选择数量和选中类型门控；证据见 DOC-04 §4.2、§4.6、§4.7 与 §6.6。

VIEW-SHARED 的访客分享码输入与访问按钮已位于 `DriveToolbarCard`，但对应 Quick Test 仍读取 `DriveSharedView`，因此完整入口交互为 `[待验证]`，见 DOC-04 §4.6。

### 3.3 COMP-DRIVE-STATUS

状态卡显示当前 VIEW 标题、范围标签和可选的搜索/选择摘要。它只呈现派生状态，不发起导航。当前组件为 `[已实现]`，证据见 DOC-04 §4.1、§6.6。

### 3.4 VIEW-MYFILES 内容面板

`DriveMyFilesView` 按以下顺序组织内容：面包屑、搜索/排序/布局行、表头、`PageStateView` 和 `fileListView`。

| 状态 | 当前呈现 | 状态 |
|---|---|---|
| STATE-LOADING | 首次/目录切换显示加载；保留式刷新可让缓存内容继续可见 | `[已实现]` |
| STATE-CONTENT | 显示文件列表 | `[已实现]` |
| STATE-EMPTY | 显示空目录信息 | `[已实现]` |
| STATE-ERROR | 显示错误与重试入口 | `[已实现]` |

证据见 DOC-04 §4.1、§6.6；状态转换规则见 DOC-03 §4。

### 3.5 文件行

当前 `fileListView` 行包含复选框、名称、类型、大小和更新时间。长名称使用确定性 elide，并保留可披露完整名称的方式。选择高亮由 `isItemSelected(id)` 决定。

#### 3.5.1 列表布局

- `[已实现]` `currentViewLayout == "list"` 时显示表头和各信息列；
- `[已实现]` 切换到当前紧凑布局时仍使用同一 `ListView`，隐藏表头和次要列并增大行高；
- `[规划]` 真实网格必须采用二维多列项目布局，给每个项目稳定 tile 尺寸，并保持选择、双击、右键和键盘行为一致。

前两项证据见 DOC-04 §4.3、§6.7。只有第三项可以称为“网格视图”。

### 3.6 搜索与排序

| 能力 | 当前行为 | 状态 | 证据 |
|---|---|---|---|
| 搜索 | 输入查询后调用 `submitSearch()`；清空调用 `clearSearch()`；目录/模式切换重置查询 | `[已实现]` | DOC-04 §4.3、§6.7 |
| 排序 | 六种 sort key 通过 `applySort()` 写入列表请求 | `[已实现]` | DOC-04 §4.3、§6.7 |
| 服务端结果 | `DriveManager.searchFiles` 与 `listFiles(..., sort)` 更新同一列表 Model | `[已实现]` | DOC-04 §5.2、§6.8 |

搜索与排序只属于 VIEW-MYFILES，不应影响 VIEW-SHARED 或 VIEW-TRASH 的数据源。

### 3.7 Owner 可见分页/加载更多

`DriveManager` 及分页信号具备页码相关数据，但当前 PAGE-DRIVE 没有用户可见页码、下一页、无限滚动触发器或加载更多反馈。因此完整能力为 `[规划]`。

完成标准：

1. 用户可见地触发或感知下一页加载；
2. 加载期间不重复请求，目录/搜索/排序变化会重置分页；
3. 新页与当前选择/空态/错误态正确合并；
4. Qt Quick Test 覆盖首屏、后续页、失败、重试和终止条件。

本节是该规划能力的唯一规范定义，其他文档只引用本节。

## 4. 交互矩阵

### 4.1 单击与复选框

| 操作 | 当前行为 | 状态 |
|---|---|---|
| 单击文件/文件夹行 | 清理原选择并选择当前项，不打开 | `[已实现]` |
| 单击未选复选框 | 将项目加入 `selectedItemIds/selectedItemKinds/selectedItemNames` | `[已实现]` |
| 单击已选复选框 | 从多选集合移除该项目 | `[已实现]` |
| 单击空白区 | 不定义为隐式清空；显式模式/目录切换会清空 | `[已实现]` |

证据见 DOC-04 §4.4、§6.7。

### 4.2 双击

| 目标 | 当前行为 | 状态 |
|---|---|---|
| 文件夹行 | 调用 `navigateToFolder(id)`，刷新树、面包屑和列表 | `[已实现]` |
| 文件行 | 打开 `FileDetailDialog` | `[已实现]` |

证据见 DOC-04 §4.2、§6.7。双击不是单击选择的替代；第一次点击仍可更新选择状态。

### 4.3 右键与 COMP-CONTEXT-MENU

当前右键行为为 `[已实现]`：

- 右键未选行时先将其设为唯一选择，再打开菜单；
- 右键已选行时保留现有多选集合；
- 右键列表空白区打开当前目录菜单，并保留现有选择；
- 文件夹目标显示打开、刷新、新建文件夹、上传、创建分享、重命名、移动、复制、删除等适用动作；
- 文件目标显示详情、下载、刷新、上传、创建分享、重命名、移动、复制、删除等适用动作；
- `DriveContextMenu` 根据目标类型和选择状态门控动作。

准确的菜单项对象名和测试函数见 DOC-04 §4.5、§6.7。

面包屑节点专用菜单、粘贴命令和更丰富的空白区排序菜单尚不存在；若未来需要，应作为新需求评审，不得由当前上下文菜单状态推断。

### 4.4 多选

当前模型支持数组化选择并把集合传给移动、复制、删除、下载、分享、恢复、永久删除和取消分享等适用操作。当前入口和限制为：

- `[已实现]` 行单击建立唯一选择；
- `[已实现]` 复选框逐项添加/移除，工具栏显示选择数量；
- `[已实现]` 目录导航和 VIEW 切换清空选择；
- `[已实现]` 右键遵循 §4.3 的选择保持规则；
- `[规划]` Ctrl+单击切换选择；
- `[规划]` Shift+单击范围选择；
- `[规划]` 鼠标框选/套索选择；
- `[规划]` Ctrl+A 全选当前已加载集合。

已实现项证据见 DOC-04 §4.4、§6.7。规划修饰键能力的统一状态模型由 DOC-03 §5 定义。

### 4.5 拖放

以下两个行为均为 `[规划]`，当前没有端到端 QML 拖放处理器和可执行测试：

#### 4.5.1 内部拖放

- 将所选文件/文件夹拖到目标文件夹；
- 拖到自身、子目录或无权限目标时拒绝；
- 成功后保持当前目录并刷新，失败时保持选择并显示错误；
- 支持鼠标取消和清晰的目标高亮。

#### 4.5.2 外部拖入上传

- 接收操作系统文件 URL；
- 明确目标为当前文件夹或悬停文件夹；
- 转交 `TransferManager` 创建上传任务；
- 对目录、重复文件、不支持 URL 和容量错误给出反馈。

存在工具栏上传入口不等于外部拖入已实现。本节是拖放规划的唯一规范定义。

### 4.6 Hover 与键盘

- `[已实现]` 行、按钮和菜单使用现有控件 Hover/视觉状态；具体皮肤不改变选择语义；
- `[已实现]` 表单、按钮和列表保留 Qt 默认焦点/激活行为；
- `[规划]` 文件列表专用的完整键盘选择合同（方向键锚点、Shift 扩选、Ctrl+A、Delete、Enter）须与 DOC-03 §5 一起实现和测试。

## 5. Transient Feedback

### 5.1 内联错误

字段校验、登录/注册错误、分享密码错误和页面可恢复错误优先内联显示。错误文本必须来自 Manager/适配层的用户可读消息，不显示原始 JSON 或堆栈。

认证页 busy/错误行为为 `[已实现]`，证据见 DOC-04 §6.2。PAGE-DRIVE 的加载/空/错状态为 `[已实现]`，证据见 DOC-04 §6.6。

### 5.2 Dialog

| Dialog | 状态 | 当前锚点/证据 |
|---|---|---|
| 新建文件夹、重命名、删除确认 | `[已实现]` | `DriveBrowserPage.qml`；DOC-04 §4.2、§6.8 |
| 移动、复制目标选择 | `[已实现]` | `moveDialog`、`copyDialog`；DOC-04 §4.2、§6.8 |
| 创建分享与成功结果 | `[已实现]` | `createShareDialog`；DOC-04 §4.6、§6.10 |
| 文件详情 | `[已实现]` | `FileDetailDialog.qml`；DOC-04 §4.2、§6.9 |
| Owner 分享详情 | `[已实现]` | `OwnerShareDetailDialog.qml`；DOC-04 §4.6、§6.10 |

破坏性操作必须有明确目标和确认；对话框关闭后不得残留上次成功/错误状态。

### 5.3 Toast

`driveToast` 用于成功或轻量失败反馈，完成 mutation 后由 `finishMutationSuccess()` 触发并自动消失。该行为为 `[已实现]`，证据见 DOC-04 §4.2、§6.7。

Toast 不替代需用户决策的 Dialog，也不替代持续任务的 Progress。

### 5.4 Progress

上传、下载任务在 PAGE-TRANSFER 显示进度、状态详情和暂停/继续控制。该行为为 `[已实现]`，证据见 DOC-04 §4.8、§6.12。

### 5.5 Skeleton

骨架屏为 `[规划]`。当前 `PageStateView` 的 loading 指示和保留缓存内容逻辑不是骨架屏。完成标准包括与内容行稳定同构的占位布局、首次加载与保留刷新策略、Reduced Motion 兼容以及 Qt Quick Test。

本节是骨架屏规划的唯一规范定义。

## 6. VIEW 特定差异

| 维度 | VIEW-MYFILES | VIEW-SHARED | VIEW-TRASH |
|---|---|---|---|
| 数据源 | DriveManager | ShareManager | TrashManager |
| 导航 | 文件夹树/面包屑/双击目录 | 无文件夹钻取 | 无文件夹钻取 |
| 选择 | 行单选 + 复选框多选 | 复选框选择分享 | 复选框选择回收站项 |
| 主操作 | 文件管理、上传、下载、分享 | 复制、详情、编辑、取消 | 恢复、永久删除、清空 |
| 搜索/排序 | `[已实现]` | 不适用 | 不适用 |
| 页面状态 | `[已实现]` | `[已实现]` | `[已实现]` |
| 证据 | DOC-04 §4.1-§4.5 | DOC-04 §4.6 | DOC-04 §4.7 |
