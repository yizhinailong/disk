## 2. 产品定义

### 2.1 产品形态

桌面客户端是一个原生桌面应用，使用 C++/Qt（QML）技术栈构建，通过 HTTPS 调用网盘后端 RESTful API，为用户提供本地化的文件管理体验。

桌面客户端内部包含两个独立产品流：

| 产品流 | 说明 | 认证域 |
|--------|------|--------|
| 所有者流（Owner Session） | 注册用户登录后管理自己的文件、文件夹、分享、回收站等 | JWT（Access Token + Refresh Token） |
| 访客流（Visitor Session） | 任意用户通过分享链接访问他人分享的文件，无需注册登录 | 分享令牌（Share Token） |

两个产品流共享同一个桌面应用窗口和导航框架，但认证状态、API 路由和数据模型完全独立。所有者流和访客流不会同时处于活跃状态。

### 2.2 技术定位

| 层级 | 技术 | 职责 |
|------|------|------|
| UI 层 | QML（Qt Modeling Language） | 声明式界面，不承载业务逻辑 |
| 业务逻辑层 | C++ | 网络请求、令牌管理、数据模型、状态机 |
| 构建 | CMake + Qt 6 CMake API | `qt_add_qml_module`、`qt_standard_project_setup` |
| 测试 | Qt Test + Qt Quick Test | 单元测试 + QML 离屏测试 |
| 平台 | Linux（首选）/ Windows（兼容） | 仅使用 Qt 跨平台 API |

数据流方向严格自上而下：QML → managers → auth/network → models → QML 绑定。QML 文件全部为纯声明式，JavaScript 仅限于格式化函数和 UI 状态追踪。

### 2.3 平台策略

**Linux-first / Windows-ready**：所有代码必须使用 Qt 跨平台 API，不得引入平台专有系统调用。

| 平台 | 策略 | 说明 |
|------|------|------|
| Linux (x86_64) | 首选开发与测试平台 | Wayland/X11，对应 `linux-debug-clang` 构建预设 |
| Windows (x86_64) | 架构兼容，首版不阻塞发布 | 代码须保持跨平台，首版验收仅要求 Linux 通过 |

Windows 构建须能在 CI 中成功编译，但首版不要求 Windows 端到端测试通过。

### 2.4 与后端的关系

桌面客户端是纯消费端。它不发明新的后端 API，不修改后端行为，不引入新的后端依赖。所有功能均对接已有后端接口。后端构建目标 `disk` 不受桌面客户端引入的影响，在 `DISK_ENABLE_DESKTOP=OFF`（默认）时完全不依赖 Qt。

### 2.5 当前实现概要

当前 `OwnerShell.qml` 是一个 `ApplicationWindow`，内部使用 `RowLayout` 分为左侧导航栏和右侧内容区。右侧内容区使用 `StackView`，初始页面为 `DriveBrowserPage`。侧栏分为两组：**File Views**（文件视图模式入口组：My Files、Shares、Trash）和 **Independent Pages**（独立页面入口组：Transfers、Settings）。Shares 和 Trash 点击后通过 `showDriveViewMode()` 在 `DriveBrowserPage` 内部切换视图模式，不替换 StackView。Transfers 和 Settings 点击后通过 `stackView.replace()` 切换为独立页面。

`DriveBrowserPage` 内部的文件夹钻取采用同页切换 `currentFolderId` 的方式，而非 `StackView push` 新页面。这一行为已被 quick test（`tst_drive_browser_navigation.qml`）验证。

> 上述描述仅为现状参考。本文档是治理/规范文档，不是实现状态的转储。当规范与实现冲突时，以规范（本系列 DOC-00 至 DOC-06）为准。

## 3. 核心产品模型

### 3.1 资源管理器定位

桌面客户端的文件相关主页采用 **资源管理器（Explorer）模型**：

### 3.2 所有者流（Owner Session）

所有者是已注册并登录的用户，通过 JWT 令牌对与后端交互。

| 令牌类型 | 有效期 | 说明 |
|----------|--------|------|
| Access Token | 2 小时 | 携带于 `Authorization: Bearer` 请求头 |
| Refresh Token | 7 天 | 用于无感刷新 Access Token |

所有者流的桌面端职责：

1. 安全存储令牌（使用系统密钥环或加密本地存储）
2. Access Token 过期前自动刷新，刷新失败则引导重新登录
3. 登出时清除本地令牌并调用后端黑名单接口
4. 支持单账户登录

### 3.3 访客流（Visitor Session）

访客通过分享链接访问他人文件，无需注册或登录。

| 令牌类型 | 获取方式 | 说明 |
|----------|----------|------|
| Share Token | 调用 `/api/share/access/{share_id}` 并传入分享密码（如有） | 携带于 `X-Share-Token` 请求头 |

访客流的桌面端职责：

1. 从分享链接中提取 `share_id`
2. 如有密码保护，弹出密码输入框
3. 获取 Share Token 后访问浏览和下载接口
4. Share Token 过期后提示用户重新验证

### 3.4 认证域隔离规则

- 所有者令牌和访客令牌不可混用
- 后端对两类令牌使用不同的 Filter 校验：`JwtAuthFilter` 校验所有者请求，`ShareAuthFilter` 校验访客请求
- 桌面端通过全局状态机区分当前活跃的认证域，UI 层据此切换导航和功能入口
- 访客流运行在独立的 Visitor Shell 中，不进入 Owner Shell 的导航树

## 6. 范围边界

### 6.1 首页定位

桌面客户端的首页（即所有者登录后的默认页面）是文件浏览视图。当前实现中，`OwnerShell` 的 `StackView` 初始项为 `DriveBrowserPage`。

在资源管理器模型下，首页不再是单一的"文件列表页"，而是一个共享的资源管理器上下文。文件类侧栏入口（我的文件、最近使用、已共享、回收站、收藏）是该上下文中的不同视图模式。非文件主页流（传输中心、设置/个人信息）作为独立功能页纳入完整文档范围，但不在资源管理器主内容区内切换。

| V-01 | 打开分享链接 | URL/协议唤起 | 提取 share_id |
| V-02 | 分享验证 | `POST /api/share/access/{share_id}` | 密码验证 |
| V-03 | 浏览分享 | `GET /api/share/browse/{share_id}` | 文件夹层级浏览 |
| V-04 | 下载分享文件 | `GET /api/share/download/{share_id}/{file_id}` | 单文件下载 |

### 6.3 非范围

以下功能明确排除在首版范围之外：

| 功能 | 排除理由 |
|------|----------|
| 离线同步（offline sync） | 需要本地数据库、冲突解决策略、增量同步协议 |
| 实时通知（real-time notifications） | 后端尚无 WebSocket/SSE 推送能力 |
| 预览引擎（preview engine） | 文档/图片/视频预览需专用渲染组件 |
| 版本历史（version history） | 后端不支持文件版本管理 |
| 协同编辑（collaborative editing） | 需 OT/CRDT 算法和实时协作服务 |
| 多账户同时在线 | 首版仅支持单账户登录 |
| 系统托盘集成 | 最小化到托盘等桌面集成功能 |
| 自动更新 | 不内置自动更新机制 |
| 国际化（i18n） | 首版仅中文界面 |
| 拖拽上传 | 首版使用文件选择对话框上传 |

### 7.1 核心术语

| 术语 | 英文 | 定义 |
|------|------|------|
| 所有者 | Owner | 已注册并登录的用户 |
| 访客 | Visitor | 通过分享链接访问文件的用户，无需注册 |
| 所有者 Shell | Owner Shell | 所有者登录后的主界面容器，包含 Sidebar、Header、StackView |
| 访客 Shell | Visitor Shell | 访客通过分享链接进入的独立浏览/下载流，不进入 Owner Shell 导航树 |
| 资源管理器 | Explorer | 文件相关主页的三栏布局模型：Header + Sidebar + 主内容区 |
| 视图模式 | View Mode | Sidebar 中文件类入口对应同一资源管理器上下文的不同数据视图 |
| 面包屑 | Breadcrumb | 顶部显示的当前目录路径，可点击跳转 |
| 目录树 | Folder Tree | 左侧栏或弹出面板中显示的文件夹层级结构 |
| 回收站 | Trash | 已删除文件的暂存区，30 天自动清理 |
| 状态标签 | Status Label | `已实现 / 规划 / 待验证` 三态标注，标识文档条目的落地状态 |
| 分片上传 | Chunked Upload | 将文件按 5MB 分片逐个上传 |
| 断点续传 | Resume Transfer | 上传或下载中断后从断点继续 |
| 秒传 | Instant Upload | 通过文件哈希匹配已有文件，跳过数据传输 |
| 存储配额 | Storage Quota | 用户可使用的最大存储空间（默认 10 GB） |
| 单航班刷新 | Single-flight Refresh | 多个请求同时遭遇 401 时，只有一个刷新请求执行，其余等待同一结果 |
| 混合契约 | Mixed Contract | 文档条目同时包含已实现、规划和待验证状态的标注策略 |

## 8. 冻结不变量

以下约束在本系列中不可被后续文档违反：

1. **单一权威**：`docs/desktop/00-06` 是唯一规范源。旧系列和 `final-report-zh.md` 仅作为历史参考。
2. **纯消费端**：桌面客户端不发明新的后端 API，不修改后端行为。
3. **认证域隔离**：所有者令牌和访客令牌不可混用，两类令牌使用不同的后端 Filter 校验。
4. **资源管理器模型**：文件相关侧栏入口是同一资源管理器上下文中的视图模式，不是独立页面产品。
5. **Linux-first / Windows-ready**：代码须保持跨平台，首版验收仅要求 Linux 通过。
6. **防误写**：不得把未实现的能力标注为 `已实现`。
7. **ID 体系**：`VIEW-`、`PAGE-`、`COMP-`、`STATE-`、`FLOW-`、`CASE-` 前缀是新系列的首要追踪体系。旧 `O-01 ~ O-29` / `V-01 ~ V-04` 编号仅用于兼容追踪。
