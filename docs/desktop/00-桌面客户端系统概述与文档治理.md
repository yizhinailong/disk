# 桌面客户端 - 系统概述与文档治理

## 1. 文档说明

### 1.1 文档目的

本文定义 Disk 桌面客户端的产品边界、核心会话模型、文档职责和证据规则。DOC-00 至 DOC-06 是桌面客户端架构、交互、状态和验证的核心权威系列；任何状态提升都必须能在当前工作树中找到实现与可执行测试证据。

### 1.2 读者对象

- 产品与交互设计人员；
- Qt/QML 与 C++ 开发人员；
- 测试、评审和发布人员；
- 维护桌面客户端文档的贡献者。

### 1.3 权威来源

权威性按以下顺序解释：

1. 本系列对产品语义、页面 taxonomy 和状态标签的明确规定；
2. `docs/design/02-API接口设计.md` 的后端 API 契约；
3. 当前桌面实现与可执行测试，其中证据索引由 DOC-04 维护；
4. DOC-07 中文 UI 术语表与 DOC-08 管理员功能设计，作为专项补充资料。

当前实现的入口锚点为：

### 1.4 状态标签

本系列只允许以下三种状态：

| 标签 | 判定标准 |
|---|---|
| `[已实现]` | 当前实现锚点存在，并且至少有一个可执行测试覆盖该行为；证据登记在 DOC-04 |
| `[待验证]` | 当前实现锚点存在，但尚无足够的可执行测试证明完整用户行为 |
| `[规划]` | 当前工作树没有完整端到端行为；属性、占位控件或局部视觉变化不能单独提升状态 |

状态描述必须限定具体行为。一个区域可同时包含已实现能力和规划能力，但不能用区域级 `[已实现]` 掩盖未完成的子能力。

## 2. 产品定义

### 2.1 产品形态

Disk Desktop 是独立的 Qt 6/QML 桌面应用，目标平台为 Linux 与 Windows。它复用后端 REST API，但拥有独立的 CMake 工程、窗口生命周期、导航模型、认证域和传输任务模型。

客户端不是 Web 页面包装，也不把后端控制器逻辑复制到 QML。QML 负责呈现和交互，C++ Manager 负责请求编排，Model 暴露可绑定数据，`RequestFactory` 负责认证域隔离。

### 2.2 当前实现概要

下列产品骨架已经由 DOC-04 的实现与测试证据确认：

- `[已实现]` splash 后根据会话状态进入认证、Owner 或 Admin Shell；访客入口进入 Visitor Shell；
- `[已实现]` Owner Shell 只有三个顶层页面：PAGE-DRIVE、PAGE-TRANSFER、PAGE-SETTINGS；
- `[已实现]` VIEW-MYFILES、VIEW-SHARED、VIEW-TRASH 在同一个 PAGE-DRIVE 主机内切换；
- `[已实现]` Admin Shell 提供用户、分享、操作日志、系统状态四个持久化 Loader 目的地；
- `[已实现]` Owner JWT 与 Visitor 分享令牌分别写入 `Authorization` 和 `X-Share-Token`，不会混用；
- `[已实现]` 上传、下载与传输中心通过 `TransferManager` 和任务 Model 串联；
- `[规划]` 真正的网格视图、所有者可见分页/加载更多、内部拖放、外部拖入上传和骨架屏。

详细能力状态不得从本节推断，应查阅 DOC-02、DOC-03 与 DOC-04。

### 2.3 平台策略

- 使用 C++23、Qt 6、Qt Quick Controls；
- 根后端工程与 `clients/desktop/` 是两个独立 CMake 工程；
- 桌面端警告保持 advisory，不使用 `-Werror`；
- 平台差异必须封装在边界层，不能扩散为两套导航或产品语义。

### 2.4 与后端的关系

- API 路径、请求字段、响应字段和错误码以 `docs/design/02-API接口设计.md` 为准；
- 桌面文档决定 API 能力如何被组织为 Shell、页面、视图、状态和交互；
- 后端存在某个 API 不等于桌面端已经提供相应用户行为；
- 桌面能力只有满足 §1.4 证据规则后才能标记为 `[已实现]`。

## 3. 核心产品模型

### 3.1 资源管理器定位

Owner 首页是 PAGE-DRIVE。它保存文件夹路径、选择、模式状态和 Manager 信号连接；三个文件视图模式只替换 PAGE-DRIVE 内部内容，不进入 Owner Shell 的页面栈。

### 3.2 Owner Session

Owner Session 使用访问令牌和刷新令牌，覆盖以下能力：

- 我的文件、已共享、回收站；
- 上传、下载和传输任务；
- 个人与连接设置；
- 管理员角色对应的 Admin Shell。

Owner 认证失效时，路由守卫按照 DOC-03 清理或刷新 Owner 状态；它不能借用 Visitor 分享令牌继续请求。

### 3.3 Visitor Session

Visitor Session 由分享 ID、可选密码和分享令牌驱动，只允许在 Visitor Shell 的验证与分享浏览页面之间导航。Visitor 下载通过分享认证域发起，不得携带 Owner JWT。

进入 Visitor Shell 不会隐式注销一个仍然有效的 Owner Session。活动窗口 Shell 只有一个，但 Owner 与 Visitor 会话状态可以同时存在；返回 Owner Shell 时仍须通过 Owner 路由守卫。

### 3.4 Admin Session

Admin 使用 Owner 认证域和管理员角色，不建立第三套令牌域。Admin Shell 与 Owner Shell 是互斥的活动 UI 壳层；角色变化或认证失败由 `ShellController` 回到登录流程。

### 3.5 认证域隔离规则

| 请求域 | 请求头 | 允许来源 | 禁止行为 |
|---|---|---|---|
| Public | 无认证头 | 登录、注册、分享验证前请求 | 注入任一会话令牌 |
| Owner | `Authorization: Bearer <token>` | Owner/Admin 功能 | 携带 `X-Share-Token` |
| Visitor | `X-Share-Token: <token>` | Visitor 分享浏览/下载 | 携带 `Authorization` |

此规则由 `clients/desktop/src/network/RequestFactory.hpp` 实现，并由 DOC-04 所列 `test_request_factory.cpp` 与路由测试验证。

## 5. 文档治理

### 5.1 ID 前缀

| 前缀 | 用途 | 示例 |
|---|---|---|
| `VIEW-` | PAGE-DRIVE 内的文件视图模式 | `VIEW-MYFILES` |
| `PAGE-` | Shell 内独立导航目的地 | `PAGE-TRANSFER` |
| `COMP-` | 可复用或嵌入式 UI 组件 | `COMP-BREADCRUMB` |
| `STATE-` | 页面或会话状态 | `STATE-LOADING` |
| `FLOW-` | 跨状态/页面的用户流程 | `FLOW-VISITOR-ACCESS` |
| `CASE-` | DOC-05/06 验证用例 | `CASE-STATUS-001` |

ID 必须在定义文档首次出现时给出含义，后续文档只能引用，不能悄悄改变 taxonomy。

### 5.2 锚点规则

- 当前路径使用从仓库根开始的完整相对路径；
- QML 证据使用文件加组件名、属性、函数或 `objectName`；
- C++ 证据使用文件加类/方法；
- 测试证据使用测试文件加测试函数；
- 禁止用易漂移的源码行号作为唯一证据；
- 不存在的规划文件不能伪装成当前路径；规划能力应描述行为和预期所有者，不预造文件名。

### 5.3 状态变更流程

1. 先更新负责该行为的 DOC-01/02/03 条目；
2. 在 DOC-04 登记实现锚点和可执行测试；
3. 更新 DOC-05/06 的验证门禁与用例映射；
4. 运行 DOC-05 全部 P0/P1 命令；
5. 在评审中附上测试结果和边界检查结果。

## 6. 范围边界

### 6.1 In Scope

- Auth、Owner、Visitor、Admin Shell；
- PAGE-DRIVE、PAGE-TRANSFER、PAGE-SETTINGS；
- VIEW-MYFILES、VIEW-SHARED、VIEW-TRASH；
- 文件列表、树、面包屑、搜索、排序、选择、上下文菜单和文件操作；
- 分享创建/管理与访客浏览；
- 上传、下载、恢复与完整性反馈；
- 页面状态、对话框、Toast、进度与规划中的骨架屏；
- C++ Manager/Model/Network 与 QML 的绑定关系；
- Qt Test、Qt Quick Test 和文档一致性验证。

### 6.2 非范围

- 后端 API 的重新定义；
- 移动端和 Web 客户端设计；
- 操作系统内核级虚拟盘挂载；
- 第三方登录、短信登录、二维码登录；
- 文档没有证据的能力自动视为已实现。

## 7. 术语表

| 术语 | 定义 |
|---|---|
| Shell | 顶层窗口与导航容器；任一时刻只有一个活动 Shell |
| Session | 认证状态域；Owner 与 Visitor 状态可以并存，但请求头必须隔离 |
| PAGE-DRIVE | Owner Shell 的持久化资源管理器主页 |
| 文件视图模式 | PAGE-DRIVE 内部的数据源与操作集合，不是独立 StackView 页面 |
| Owner `已共享` | 所有者管理自己创建的分享 |
| Visitor 分享浏览 | 访客凭分享 ID/密码/令牌访问分享内容 |
| 页面状态 | loading、content、empty、error 等互斥呈现状态 |
| Transient Feedback | Dialog、Toast、Progress、Skeleton 等短期反馈 |
| 真实网格视图 | 使用二维、多列项目布局呈现文件；仅隐藏列表列标题不算完成 |
| 可见分页/加载更多 | 用户可以看见并触发或感知下一页加载；Manager 内有页码参数不算完成 |

## 8. 冻结不变量

1. VIEW-MYFILES、VIEW-SHARED、VIEW-TRASH 共享一个 PAGE-DRIVE 主机。
2. Owner Shell 的顶层页面只有 PAGE-DRIVE、PAGE-TRANSFER、PAGE-SETTINGS。
3. Admin Shell 的四个目的地为用户、分享、操作日志和系统状态。
4. 活动 Shell 互斥，但 Owner 与 Visitor Session 可以并存。
5. Owner 与 Visitor 认证头绝不混用。
6. `[已实现]` 必须同时有当前实现与可执行测试证据。
7. 真正网格、所有者可见分页/加载更多、内部拖放、外部拖入上传和骨架屏在完整证据出现前保持 `[规划]`。
8. DOC-04 使用稳定符号/对象名/测试函数，不使用源码行号作为唯一锚点。
9. 退役历史文件不是当前工作树路径，也不是现行规范。
