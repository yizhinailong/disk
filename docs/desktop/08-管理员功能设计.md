# 桌面客户端 — 管理员功能设计

## 1. 文档说明

### 1.1 文档目的

本文档定义桌面客户端的管理员功能模块。目标是将后端管理员 API 接口（`docs/design/02-API接口设计.md`）映射为桌面客户端的 Shell 结构、页面组件、导航规则和错误处理规范，为实现和验证提供唯一 IA 基线。

管理员功能以 **AdminShell** 的形式呈现——一个与 OwnerShell、VisitorShell 并列的独立 Shell，在管理员用户登录后由 ShellController 自动路由进入。AdminShell 不包含普通用户文件浏览和回收站操作。

### 1.2 权威来源

| 来源 | 路径 | 用途 |
|------|------|------|
| 文档治理基线 | `docs/desktop/00-桌面客户端系统概述与文档治理.md` | ID 前缀体系、状态标签语义、认证域隔离规则 |
| 信息架构与功能视图 | `docs/desktop/01-信息架构与功能视图.md` | 三 Shell 架构、AdminShell 定义、五类对象 taxonomy |
| 状态模型与导航模型 | `docs/desktop/03-状态模型与导航模型.md` | FLOW-ADMIN-LOGIN 导航流、AdminShell 页面注册 |

### 1.3 冻结不变量

1. 管理员功能是 **AdminShell**（独立 Shell），不是 OwnerShell 内的页面或视图模式。管理员登录后由 `ShellController` 路由到 AdminShell，不进入 OwnerShell。
2. AdminShell 使用左侧 Navigation Rail + 右侧 StackView 的布局结构，与 OwnerShell 的设计模式一致但完全独立。
3. AdminShell 的 Navigation Rail 包含 **4 个导航项**：用户管理、分享管理、操作日志、系统监控。不包含普通用户文件浏览入口。
4. 管理员 API 调用使用 JWT（`Authorization: Bearer`），与普通 Owner API 相同，但后端校验 `is_admin` 权限。
5. 管理后台只消费已有后端接口，包括 `/api/admin/*` 管理接口和 `/api/logs` 操作日志接口，不发明新的接口。
6. 管理员功能不修改 OwnerShell 或 VisitorShell 的任何状态和页面。

## 2. Shell 架构

### 2.1 AdminShell 定位

AdminShell 是管理员用户登录后的主界面容器。当登录成功后，`OwnerSessionManager.DecodeRoleFromJwt()` 从 JWT payload 中提取 `role` 字段；若 `role === 1`，`ShellController` 调用 `navigateToAdmin()` 将 Main.qml 的活跃 Shell 切换为 AdminShell，而不是 OwnerShell。

AdminShell 不包含文件浏览、传输中心、设置等所有者功能。管理员如需使用文件管理功能，需要以普通用户身份登录（即 `role === 0` 的账户）。

### 2.2 AdminShell 结构

```
AdminShell (ApplicationWindow)
├── Navigation Rail                      # 左侧导航栏（固定可见）
│   ├── 品牌区                           # Disk / Admin
│   ├── 导航项组
│   │   ├── 用户管理（PAGE-ADMIN-USERS）
│   │   ├── 分享管理（PAGE-ADMIN-SHARES）
│   │   ├── 操作日志（PAGE-ADMIN-LOGS）
│   │   └── 系统监控（PAGE-ADMIN-SYSTEM）
│   └── 会话区                           # 登出按钮
└── 内容区
    ├── Header                           # 页面标题 + 副标题
    └── StackView                        # 页面内容
        ├── 用户管理页 (PAGE-ADMIN-USERS)   # 默认首页
        ├── 分享管理页 (PAGE-ADMIN-SHARES)
        ├── 操作日志页 (PAGE-ADMIN-LOGS)
        └── 系统监控页 (PAGE-ADMIN-SYSTEM)
```

### 2.3 AdminShell 导航规则

| 导航目标 | 行为 | StackView 操作 | 状态 |
|----------|------|---------------|------|
| PAGE-ADMIN-USERS（用户管理） | 替换 StackView 栈顶为用户管理页面 | `stackView.replace()` | `[已实现]` |
| PAGE-ADMIN-SHARES（分享管理） | 替换 StackView 栈顶为分享管理页面 | `stackView.replace()` | `[已实现]` |
| PAGE-ADMIN-LOGS（操作日志） | 替换 StackView 栈顶为操作日志页面 | `stackView.replace()` | `[已实现]` |
| PAGE-ADMIN-SYSTEM（系统监控） | 替换 StackView 栈顶为系统监控页面 | `stackView.replace()` | `[已实现]` |
| 登出 | 清理 Session，切换到 PAGE-LOGIN | Shell 替换 | `[已实现]` |

AdminShell 首页为 `PAGE-ADMIN-USERS`（用户管理），Navigation Rail 的默认高亮项为"用户管理"。

### 2.4 认证与权限

| 维度 | 说明 |
|------|------|
| 访问条件 | 所有者 JWT + `role === 1` |
| Shell 路由 | 登录后 `ShellController` 根据 `role` 决定进入 OwnerShell 或 AdminShell |
| API 鉴权 | 后端 `AdminAuthFilter` 校验 JWT 中的 `is_admin` 字段 |
| 降级处理 | 非管理员用户不会进入 AdminShell，因此不存在权限不足的 UI 降级场景 |

## 5. 错误处理

### 5.1 管理员功能错误码

桌面客户端对管理员 API 的错误响应进行统一处理，显示中文用户友好的错误提示。

| 错误码 | 英文描述 | 中文用户提示 | 处理方式 |
|--------|---------|-------------|---------|
| 80001 | Permission denied | 您没有管理员权限，无法访问此功能 | 提示后返回登录页 |
| 80002 | User not found | 用户不存在，可能已被删除 | 刷新用户列表，移除该行 |
| 80003 | Cannot modify own role | 无法修改自己的管理员角色 | 提示"不能修改自己的角色"，操作取消 |
| 80004 | Cannot delete last admin | 无法删除最后一个管理员账户 | 提示"不能删除最后一个管理员"，操作取消 |
| 80005 | Share not found | 分享不存在或已失效 | 刷新分享列表，移除该行 |
| 80006 | Database error | 数据库错误，请稍后重试 | 显示重试按钮，用户可选择重试 |
| 80007 | Internal server error | 服务器内部错误，请稍后重试 | 显示重试按钮，用户可选择重试 |

### 5.2 错误处理流程

```
API 调用
  ↓
[成功] → 更新 UI → 显示成功提示（如"用户状态已更新"）
  ↓
[失败 4xx] → 解析错误码 → 显示对应中文提示 → 用户确认后关闭
  ↓
[失败 5xx] → 显示通用错误提示（80006/80007）→ 显示重试按钮
  ↓
[网络错误] → 显示"网络连接失败，请检查网络" → 显示重试按钮
```

## 7. 冻结不变量

以下约束在本文档中不可违反：

1. **独立 Shell 约束**：管理员功能是 AdminShell，与 OwnerShell 和 VisitorShell 并列的独立 Shell。管理员登录后不进入 OwnerShell。
2. **四导航项约束**：AdminShell 的 Navigation Rail 仅包含用户管理、分享管理、操作日志、系统监控四个导航项，不包含文件浏览、传输中心、设置等入口。
3. **纯消费端约束**：桌面客户端不发明新的管理员 API，只对接已有后端管理接口和操作日志接口。
4. **认证域约束**：管理员 API 使用与普通 Owner API 相同的 JWT（`Authorization: Bearer`），通过后端 Filter 校验 `is_admin` 权限。
5. **破坏性操作确认约束**：删除用户、强制取消分享等破坏性操作必须经过 `COMP-ADMIN-CONFIRM` 二次确认。
6. **ID 前缀约束**：管理员模块页面使用 `PAGE-ADMIN-*` 前缀，组件使用 `COMP-ADMIN-*` 前缀，不得与现有 `PAGE-*`、`COMP-*` 组件 ID 冲突。
7. **无普通文件功能约束**：AdminShell 不包含普通用户文件浏览、上传、下载和回收站操作。
