# 桌面客户端 — 管理员功能设计

## 1. 文档说明

### 1.1 文档目的

本文档定义桌面客户端的管理员功能模块。目标是将后端管理员 API 接口（`docs/design/02-API接口设计.md`）映射为桌面客户端的页面结构、组件设计、导航规则和错误处理规范，为实现和验证提供唯一 IA 基线。

管理员功能是桌面客户端的独立功能域，与文件管理（VIEW-MYFILES）、分享管理（VIEW-SHARED）、回收站（VIEW-TRASH）并列，位于 Owner Shell 的侧栏入口组。

### 1.2 权威来源

| 来源 | 路径 | 用途 |
|------|------|------|
| 文档治理基线 | `docs/desktop/00-桌面客户端系统概述与文档治理.md` | ID 前缀体系、状态标签语义、认证域隔离规则 |
| 信息架构与功能视图 | `docs/desktop/01-信息架构与功能视图.md` | Shell 架构、独立功能页定义、五类对象 taxonomy |
| 组件页面与实现映射 | `docs/desktop/04-组件页面与实现映射.md` | 规范条目映射方式、C++/QML 绑定约定 |
| 后端 API 接口设计 | `docs/design/02-API接口设计.md` | 管理员接口路由、请求/响应结构（L1 权威） |
| 后端管理员服务设计 | `docs/design/00-系统概述.md` | 管理员角色说明、系统级统计接口范围 |

### 1.3 冻结不变量

1. 管理员页面是 **独立页面（PAGE-）**，不是文件视图模式（VIEW-）。它通过 `stackView.replace()` 切换，不共享 PAGE-DRIVE 的三栏布局。
2. 管理员入口在 Sidebar 中独立展示，仅对 `role === 1` 的用户可见。
3. 管理员 API 调用使用 JWT（`Authorization: Bearer`），与普通 Owner API 相同，但后端校验 `is_admin` 权限。
4. 所有 13 个管理员接口的状态均为 `[规划]`，桌面端不发明新的接口。
5. 管理员功能不修改文件视图模式、分享视图模式、回收站视图模式的状态。

## 2. 功能概述

### 2.1 管理员面板定位

管理员功能面向具有管理员角色（`role === 1`）的已登录用户，提供系统级别的用户管理、分享管理、存储统计和系统状态监控能力。

管理员面板不属于资源管理器上下文。它是 Owner Shell 的一个独立功能页，通过侧栏入口触发 `stackView.replace()` 切换，不与文件视图模式共享布局或状态。

### 2.2 管理员面板结构

管理员面板由一个主页面和三个子标签页组成：

```
PAGE-ADMIN（管理员）
├── 用户Tab（COMP-ADMIN-USERS-TAB）
│     ├── 用户列表（搜索、筛选、分页）
│     └── 用户操作（查看详情、变更状态、变更角色、删除）
├── 分享Tab（COMP-ADMIN-SHARES-TAB）
│     ├── 分享列表（筛选、分页）
│     └── 分享操作（查看详情、强制取消）
└── 系统Tab（COMP-ADMIN-SYSTEM-TAB）
      ├── 概览统计（总用户数、总文件数、总存储空间、使用率）
      └── 系统状态（版本、运行时长、数据库状态、Redis 状态）
```

### 2.3 认证与权限

| 维度 | 说明 |
|------|------|
| 访问条件 | 所有者 JWT + `role === 1` |
| 入口可见性 | Sidebar 管理员入口对 `role !== 1` 用户隐藏 |
| API 鉴权 | 后端 `AdminAuthFilter` 校验 JWT 中的 `is_admin` 字段 |
| 降级处理 | 非管理员用户尝试访问管理员 API 时返回 403，UI 提示"权限不足" |

## 4. 页面设计

### 4.1 PAGE-ADMIN（管理员主页面）

#### 4.1.1 布局结构

```
OwnerShell
└── StackView
      └── PAGE-ADMIN（AdminPage.qml）
            ├── Header
            │     ├── 页面标题："管理员"
            │     └── 页面副标题："系统管理面板"
            └── Content
                  ├── TabBar（TabBarLayout）
                  │     ├── 用户Tab（中文标签）
                  │     ├── 分享Tab（中文标签）
                  │     └── 系统Tab（中文标签）
                  └── SwipeView（currentIndex 联动 TabBar）
                        ├── COMP-ADMIN-USERS-TAB（index=0）
                        ├── COMP-ADMIN-SHARES-TAB（index=1）
                        └── COMP-ADMIN-SYSTEM-TAB（index=2）
```

#### 4.1.2 组件规格

| 元素 | 规格 | 状态 |
|------|------|------|
| TabBar | Qt Quick Controls 的 TabBar，3 个 tab，currentIndex 绑定 SwipeView.currentIndex | `[规划]` |
| SwipeView | Qt Quick Controls 的 SwipeView，3 个 page，orientation=Horizontal，interactive=true | `[规划]` |
| Header | 与其他独立功能页（PAGE-TRANSFER、PAGE-SETTINGS）保持一致的 Header 风格 | `[规划]` |

COMP-ADMIN-USERS-TAB

| 元素 | 规格 | 状态 |

### 5.2 AdminManager C++ 类职责

| 方法 | 职责 | 返回类型 |
|------|------|---------|
| `listUsers(...)` | 调用 `GET /api/admin/users`，解析用户列表 JSON 到 `AdminUserListModel` | `drogon::Task<Result<std::vector<User>>>>` |
| `getUserDetail(userId)` | 调用 `GET /api/admin/users/{id}`，返回用户详情 JSON | `drogon::Task<Result<UserDetail>>` |
| `changeUserStatus(userId, newStatus)` | 调用 `PUT /api/admin/users/{id}/status`，处理 204 No Content | `drogon::Task<Result<void>>` |
| `changeUserRole(userId, newRole)` | 调用 `PUT /api/admin/users/{id}/role`，处理 204 No Content | `drogon::Task<Result<void>>` |
| `softDeleteUser(userId)` | 调用 `DELETE /api/admin/users/{id}`，处理 204 No Content | `drogon::Task<Result<void>>` |

## 6. 导航规则

### 6.1 管理员入口可见性

管理员入口（Sidebar 中的"管理员"按钮）对所有已登录用户显示，但实际可访问性由后端 `AdminAuthFilter` 控制。

| 条件 | Sidebar 入口显示 | 页面访问 |
|------|-----------------|---------|

## 7. 错误处理

### 7.1 管理员功能错误码

桌面客户端对管理员 API 的错误响应进行统一处理，显示中文用户友好的错误提示。

| 错误码 | 英文描述 | 中文用户提示 | 处理方式 |
|--------|---------|-------------|---------|
| 80001 | Permission denied | 您没有管理员权限，无法访问此功能 | 提示后返回上一页或跳转登录页 |
| 80002 | User not found | 用户不存在，可能已被删除 | 刷新用户列表，移除该行 |
| 80003 | Cannot modify own role | 无法修改自己的管理员角色 | 提示"不能修改自己的角色"，操作取消 |
| 80004 | Cannot delete last admin | 无法删除最后一个管理员账户 | 提示"不能删除最后一个管理员"，操作取消 |
| 80005 | Share not found | 分享不存在或已失效 | 刷新分享列表，移除该行 |
| 80006 | Database error | 数据库错误，请稍后重试 | 显示重试按钮，用户可选择重试 |
| 80007 | Internal server error | 服务器内部错误，请稍后重试 | 显示重试按钮，用户可选择重试 |

### 7.2 错误处理流程

```
API 调用
  ↓
[成功] → 更新 UI → 显示成功提示（如"用户状态已更新"）
  ↓
[失败 4xx] → 解析错误码 → 显示对应中文提示 → 用户确认后关闭
  ↓
[失败 5xx] → 显示通用错误提示（80006/80007）→ 显示重试按钮
  ↓
[网络错误] → 显示"网络连接失败，请检查网络" → 显示重试按钮
```

### 7.3 错误展示位置

| 场景 | 展示位置 | 状态 |
|------|---------|------|
| API 调用失败（非破坏性操作） | 列表上方红色横幅，自动消失 5 秒 | `[规划]` |
| 破坏性操作确认前失败 | Dialog 内红色文字说明，操作取消 | `[规划]` |
| 分页加载失败 | 列表区域显示错误状态视图，含重试按钮 | `[规划]` |
| 网络错误 | 全页 error 状态视图（参考 `COMP-PAGESTATEVIEW`） | `[规划]` |

## 9. 冻结不变量

以下约束在本文档中不可违反：

1. **独立页面约束**：管理员面板是 `PAGE-ADMIN`，不是文件视图模式。它通过 `stackView.replace()` 切换，不共享 `PAGE-DRIVE` 的三栏布局。
2. **角色可见性约束**：Sidebar 管理员入口对 `role !== 1` 用户可见但访问受限，后端返回 403 时 UI 提示"权限不足"。
3. **纯消费端约束**：桌面客户端不发明新的管理员 API，所有 13 个接口均对接已有后端接口。
4. **防误写约束**：本文档所有功能条目的状态标签均为 `[规划]`，不得标注为 `[已实现]`。
5. **认证域约束**：管理员 API 使用与普通 Owner API 相同的 JWT（`Authorization: Bearer`），通过后端 Filter 校验 `is_admin` 权限。
6. **破坏性操作确认约束**：删除用户、强制取消分享等破坏性操作必须经过 `COMP-ADMIN-CONFIRM` 二次确认。
7. **ID 前缀约束**：管理员模块组件使用 `COMP-ADMIN-*` 前缀，不得与现有 `COMP-*` 组件 ID 冲突。
