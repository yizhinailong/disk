# 开发指南

本文档面向 Disk Vue Web 客户端的开发者，涵盖环境搭建、开发命令、代码规范、Git 工作流、目录组织以及构建部署等内容。

---

## 1. 环境要求

### 1.1 运行时与工具

| 工具 | 最低版本 | 说明 |
|------|----------|------|
| Bun | >= 1.1 | 包管理与构建工具，替代 npm |
| Node.js | >= 18.0 | Bun 底层依赖的运行时 |

> 虽然 Bun 自带了 Node.js 兼容层，但某些 CI 环境或 IDE 插件仍需要系统安装 Node.js。建议同时安装 Node.js 18+ 作为备用。

### 1.2 编辑器推荐

- **VS Code** + **Volar**（Vue 官方语言支持插件）
- 推荐安装以下扩展：
  - `Vue.volar` — Vue 3 单文件组件支持
  - `dbaeumer.vscode-eslint` — ESLint 集成
  - `esbenp.prettier-vscode` — 代码格式化
  - `bradlc.vscode-tailwindcss` — Tailwind CSS 智能提示（如项目使用）

## 2. 快速开始

### 2.1 克隆仓库

```bash
git clone https://github.com/yourusername/disk.git
cd disk/clients/disk-web
```

### 2.2 安装依赖

```bash
bun install
```

> 首次安装会拉取 `element-plus`、`pinia`、`vue-router`、`axios` 等核心依赖，以及 `vitest`、`playwright` 等开发依赖。

### 2.3 启动开发服务器

```bash
bun run dev
```

默认开发服务器地址为 `http://localhost:5173`。Vite 提供热模块替换（HMR），修改代码后页面会自动刷新。

## 3. 开发命令

所有命令均通过 `bun run <script>` 执行，定义在 `package.json` 的 `scripts` 字段中。

| 命令 | 作用 |
|------|------|
| `bun run dev` | 启动 Vite 开发服务器，带 HMR |
| `bun run build` | 执行生产构建，输出到 `dist/` |
| `bun run preview` | 本地预览生产构建产物 |
| `bun run test` | 运行 Vitest 单元测试 |
| `bun run test:e2e` | 运行 Playwright E2E 测试 |
| `bun run lint` | 运行 ESLint 检查代码风格 |
| `bun run typecheck` | 运行 `vue-tsc` 进行 TypeScript 类型检查 |

### 3.1 常用组合

```bash
# 提交前检查：类型 + 风格
bun run typecheck && bun run lint

# 完整验证：单元测试 + 类型 + 构建
bun run test && bun run typecheck && bun run build
```

## 4. 代码规范

### 4.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| Vue 组件 | PascalCase | `FileList.vue`, `UserProfile.vue` |
| 组合式函数 | camelCase，以 `use` 开头 | `useAuth`, `useFileUpload` |
| 普通函数 / 方法 | camelCase | `fetchUserList`, `handleSubmit` |
| 常量 | UPPER_SNAKE_CASE | `MAX_UPLOAD_SIZE`, `API_BASE_URL` |
| 类型 / 接口 | PascalCase | `UserProfile`, `FileItem` |
| 枚举 | PascalCase | `FileStatus.Active` |
| Pinia Store | camelCase，以 `use` 开头 + Store 后缀 | `useUserStore`, `useFileStore` |
| 路由页面组件 | PascalCase，与路由名一致 | `DriveBrowserPage.vue` |

### 4.2 文件组织规范

- 组件文件使用 `.vue` 扩展名，放在 `src/components/` 或对应模块目录下。
- 组合式函数放在 `src/composables/`。
- Pinia Store 放在 `src/stores/`。
- API 请求封装放在 `src/api/` 或 `src/services/`。
- 类型定义放在 `src/types/`。
- 工具函数放在 `src/utils/`。

### 4.3 TypeScript 严格模式

项目启用 TypeScript 严格模式（`strict: true`）。要求：

- 禁止隐式 `any`，所有函数参数和返回值必须显式声明类型。
- 优先使用 `interface` 定义对象形状，用 `type` 定义联合类型或工具类型。
- 避免使用非空断言（`!`），除非有充分的边界保证。
- 异步函数统一返回 `Promise<T>`，错误处理通过 `try/catch` 或结果包装类型完成。

### 4.4 Vue 3 组合式 API 规范

- 新组件统一使用 `<script setup>` 语法。
- 逻辑复用优先使用组合式函数（Composables），而非 Options API 的 mixins。
- 响应式状态使用 `ref` 和 `reactive`，优先用 `ref` 处理原始值。
- 计算属性使用 `computed`，副作用使用 `watch` 或 `watchEffect`。
- 生命周期钩子使用 `onMounted`、`onUnmounted` 等，注意在 `onUnmounted` 中清理定时器和事件监听。
- Props 使用 `defineProps` 并显式声明类型，Emits 使用 `defineEmits`。

### 4.5 Pinia Store 规范

- Store 按领域拆分，如 `useAuthStore`、`useFileStore`、`useShareStore`。
- State 定义为返回对象的函数，确保每个实例独立。
- Getters 只读，Actions 处理异步和业务逻辑。
- 不在组件中直接修改 Store 的 State，统一通过 Actions 或 `$patch` 更新。
- 持久化状态（如登录令牌）使用 `pinia-plugin-persistedstate`，按需配置存储键和过期策略。

## 5. Git 工作流

### 5.1 分支策略

采用基于主分支的特性分支模型：

- `main`：主分支，始终保持可构建、可部署状态。
- `feature/<name>`：新功能分支，从 `main` 切出，合并回 `main`。
- `fix/<name>`：缺陷修复分支，从 `main` 切出，合并回 `main`。
- `docs/<name>`：文档更新分支。

### 5.2 Commit 规范

遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```
<type>(<scope>): <subject>

<body>

<footer>
```

常用类型：

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `docs` | 文档更新 |
| `style` | 代码风格调整（不影响逻辑） |
| `refactor` | 重构（既不修复 bug 也不添加功能） |
| `test` | 测试相关 |
| `chore` | 构建、依赖、工具链等杂项 |

示例：

```
feat(auth): 添加登录表单记住密码功能

fix(upload): 修复大文件分片上传进度丢失问题

docs(readme): 更新本地开发环境搭建说明
```

## 6. 目录规范

### 6.1 模块边界

```text
clients/disk-web/
├── public/                 # 静态资源（不经过构建处理）
├── src/
│   ├── api/                  # 后端 API 请求封装（按模块组织）
│   ├── assets/               # 图片、字体、全局样式
│   ├── components/           # 全局通用组件
│   │   ├── common/           # 纯展示型通用组件
│   │   └── business/         # 业务相关可复用组件
│   ├── composables/          # 组合式函数
│   ├── layouts/              # 页面布局组件
│   ├── router/               # Vue Router 配置
│   ├── stores/               # Pinia Store
│   ├── styles/               # 全局样式、变量、混入
│   ├── types/                # 全局 TypeScript 类型
│   ├── utils/                # 工具函数
│   └── views/                # 页面级组件（按功能模块划分）
│       ├── auth/
│       ├── drive/
│       ├── share/
│       ├── trash/
│       └── admin/
├── tests/
│   ├── unit/                 # Vitest 单元测试
│   └── e2e/                  # Playwright E2E 测试
├── docs/                     # 项目文档
├── index.html
├── package.json
├── tsconfig.json
└── vite.config.ts
```

### 6.2 文件命名规则

- 组件文件：PascalCase，如 `FileList.vue`。
- 组合式函数：camelCase，如 `useAuth.ts`。
- Store 文件：camelCase，如 `authStore.ts`。
- 工具函数：camelCase，如 `formatSize.ts`。
- 类型文件：PascalCase 或 camelCase，如 `FileTypes.ts`。
- 样式文件：kebab-case，如 `variables.scss`。
- 测试文件：与被测文件同名，后缀为 `.test.ts` 或 `.spec.ts`，如 `useAuth.test.ts`。

## 7. 构建与部署

### 7.1 环境变量配置

项目使用 Vite 的环境变量机制。根目录下的 `.env` 文件按后缀区分环境：

| 文件 | 作用 |
|------|------|
| `.env` | 所有环境共享的默认变量 |
| `.env.development` | 开发环境专用 |
| `.env.production` | 生产环境专用 |

变量必须以 `VITE_` 前缀开头才能在客户端代码中访问：

```bash
# .env.development
VITE_API_BASE_URL=http://localhost:8080/api
VITE_APP_TITLE=Disk Dev
```

```typescript
// 代码中访问
const apiBase = import.meta.env.VITE_API_BASE_URL;
```

> 不要将敏感信息（如密钥、密码）写入任何 `.env` 文件并提交到仓库。生产环境的敏感配置应通过 CI/CD 流水线或部署平台注入。

### 7.2 构建输出

```bash
bun run build
```

生产构建产物输出到 `dist/` 目录，包含：

- 经过压缩和哈希处理的 JS/CSS 资源
- 从 `public/` 复制的静态文件
- `index.html`（入口页面）

### 7.3 静态资源部署

`dist/` 目录为纯静态文件，可部署到任意静态托管服务：

- Nginx / Caddy 等 Web 服务器
- CDN 对象存储（如阿里云 OSS、腾讯云 COS）
- Vercel / Netlify / Cloudflare Pages 等平台

部署时建议配置：

- 单页应用路由回退：所有路径指向 `index.html`。
- Gzip / Brotli 压缩静态资源。
- 为 JS/CSS 资源设置长期缓存（因文件名含内容哈希）。

### 7.4 代理配置（开发环境）

开发服务器通过 Vite 的 `server.proxy` 配置代理后端 API，避免跨域问题。配置位于 `vite.config.ts`：

```typescript
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
      },
    },
  },
});
```

> 生产环境不依赖此代理，由部署平台或反向代理统一处理 API 转发。

## 8. 常见问题

### Q1: `bun install` 安装依赖很慢或失败？

尝试切换 Bun 的 registry 镜像：

```bash
bun config set registry https://registry.npmmirror.com
```

或者使用代理：

```bash
HTTP_PROXY=http://127.0.0.1:7890 bun install
```

### Q2: 开发服务器启动后页面空白，控制台报错？

检查 `vite.config.ts` 中的 `server.proxy` 配置是否正确指向了后端地址。确认后端服务已启动并监听对应端口。

### Q3: TypeScript 类型检查报错，但代码逻辑看起来没问题？

运行 `bun run typecheck` 查看完整错误信息。常见问题包括：

- Vue 组件 Props 类型未显式声明
- 第三方库缺少类型定义（尝试安装 `@types/xxx`）
- `tsconfig.json` 的 `include` 范围未覆盖到相关文件

### Q4: Playwright E2E 测试无法启动浏览器？

首次运行需要安装浏览器依赖：

```bash
bunx playwright install
bunx playwright install-deps
```

### Q5: Element Plus 组件样式不生效？

确认已在入口文件（如 `main.ts`）中引入样式：

```typescript
import 'element-plus/dist/index.css';
```

如果使用按需引入，确保 `vite.config.ts` 中配置了 `ElementPlusResolver`。

### Q6: 如何同时开发后端和前端？

在仓库根目录分别启动后端和前端：

```bash
# 终端 1：启动后端（仓库根目录）
JWT_SECRET=dev-only-jwt-secret-key-change-in-production-2024 ./build/linux-debug-clang/src/disk

# 终端 2：启动前端（clients/disk-web 目录）
bun run dev
```

前端开发服务器默认代理 `localhost:8080` 的后端 API，无需额外配置。
