## OVERVIEW

High-performance cloud storage system (网盘). C++23/Drogon REST API with JWT auth, chunked file upload with deduplication, file sharing, trash/recycle bin. MySQL + Redis backend.

## STRUCTURE

```
disk/
├── src/
│   ├── controllers/    # HTTP route handlers (Drogon HttpController)
│   ├── services/       # Business logic (coroutine-based, drogon::Task)
│   ├── models/         # Drogon ORM models (auto-generated + custom methods)
│   ├── dtos/           # Request/Response DTOs with inline validation
│   ├── filters/        # HTTP middleware (JWT auth, rate limiting)
│   ├── storage/        # File storage abstraction (IFileStorage → LocalFileStorage)
```

## CONVENTIONS

### Naming
- **Classes/structs**: `PascalCase` — `AuthController`, `RegisterRequest`
- **Methods**: `PascalCase` — `Register()`, `ValidateUsername()` (NOT camelCase)
- **Private members**: `m_` + `snake_case` — `m_db_client`, `m_redis_service`
- **Constants**: `UPPER_SNAKE_CASE` — `DEFAULT_STORAGE_QUOTA`
- **Namespaces**: domain-based — `disk::auth`, `disk::health`, `disk::filters`, `disk::storage`, `disk::utils`, `disk::error`

### Error Handling
- **Result<T>** = `std::expected<T, ErrorInfo>` — never throw exceptions for business logic
- Return errors via `std::unexpected(ErrorInfo(ErrorCode::X))` or `std::unexpected(ErrorInfo(ErrorCode::X, "detail"))`
- Controllers convert `Result<T>` → HTTP response via `Response::FromResult(result, to_json)`

### Async Pattern
- All service methods return `drogon::Task<Result<T>>` (C++20 coroutines)
- Use `co_await` for DB/Redis operations
- All public service methods marked `[[nodiscard]]`
- Trailing return syntax: `auto Method() -> ReturnType`

### DTO Pattern
- Request DTOs: struct with `static FromRequest(req) -> Result<DTO>`, private `Validate*()` methods
- Response DTOs: struct with `ToJson() -> Json::Value`
- DTOs are header-only, namespaced by domain (e.g., `disk::auth::RegisterRequest`)

### Controller Pattern
- Inherit `drogon::HttpController<ClassName>`
- Routes in `METHOD_LIST_BEGIN` / `METHOD_LIST_END` macros
- Handler takes `drogon::HttpRequestPtr`, returns `drogon::Task<drogon::HttpResponsePtr>`
- Zero business logic — delegates to service, converts Result to HTTP via Response helper

### Model Pattern
- Auto-generated by Drogon ORM from `src/models/model.json`
- Custom methods added to `.cpp` files only (`.hpp` is regenerated)
- Models in `drogon_model::disk` namespace

### Singleton Pattern
- Inherit `Singleton<T>`, add `friend class Singleton<T>`, private constructor
- Access via `T::GetInstance()` (returns `shared_ptr`)

## ANTI-PATTERNS

- **NEVER** add business logic in controllers — delegate to services
- **NEVER** include third-party headers in source files — use Pch.hpp precompiled header
- **NEVER** use `throw`/`try-catch` for business error flow — use `Result<T>`
- **NEVER** edit auto-generated model `.hpp` files — custom code goes in `.cpp` only
- **NEVER** use raw DB queries in controllers — use Drogon ORM Mapper/CoroMapper

## UNIQUE STYLES

- **Precompiled header**: `src/utils/Pch.hpp` includes ALL third-party headers; source files must not re-include them
- **Global filter plugin**: JWT auth and rate limiting configured via `drogon::plugin::GlobalFilters` in `config.json` with regex URL exemptions (not per-controller)
- **Content-addressed storage**: Files stored by content hash (MD5); deduplication at physical layer via `LocalFileStorage`
- **Upload flow**: Chunked (5MB default) → temp dir → `AssemblyWorkerPool` assembles → hash verify → promote to final storage
- **TokenService dual init**: `Initialize(secret)` (static, once at startup) + `GetInstance()` (singleton access)
- **StorageMgr static pattern**: `SetInstance()` / `GetInstance()` (not using Singleton template)
- **DownloadResponder**: Separate class for streaming file downloads (not in controller)

## NOTES

- **Build requires**: Clang 21.1.6+, CMake 3.20+, Ninja, ccache, `VCPKG_ROOT` env var set
- **JWT_SECRET**: Required env var; dev default in CMakePresets.json (`dev-only-jwt-secret-key-change-in-production-2024`)
- **Model files are large**: 1-3K lines (auto-generated ORM); custom methods appended at bottom of `.cpp`
- **Integration tests**: Shell scripts requiring live server + MySQL + Redis; run serially (`RUN_SERIAL TRUE`)
- **Test linking**: Some test sources directly include src/*.cpp files (not linked as library); see `test/CMakeLists.txt`
- **ConfigMgr workaround**: `ConfigMgr.cpp` needs `-include drogon/HttpAppFramework.h` compile flag in test target (PCH not available)
- **config.json plugins**: `GlobalFilters` exempt paths are regex patterns; new public endpoints MUST be added to exempt list
- **Docs are in Chinese**: All design documents (`docs/design/`) are written in Chinese
