# AGENTS.md - Code Style Guide for Agentic Development

## Build/Test/Lint Commands

### Build Commands
```bash
# Configure (Linux Debug)
cmake --preset linux-debug-clang

# Build (Linux Debug)
cmake --build --preset linux-debug-clang

# Build (Linux Release)
cmake --build --preset linux-release-clang

# Clean build directory
rm -rf build/linux-debug-clang && cmake --preset linux-debug-clang && cmake --build --preset linux-debug-clang
```

### Test Commands
```bash
# Run all tests
ctest --preset linux-debug-clang

# Run a single test (replace TestName with actual test name)
ctest --preset linux-debug-clang -R TestName -V

# Run tests with verbose output
ctest --preset linux-debug-clang -V
```

### Format Commands
```bash
# Format all files
find src test -name '*.cpp' -o -name '*.hpp' | xargs clang-format -i

# Format specific file
clang-format -i src/controllers/AuthController.cpp

# Check formatting (dry run)
clang-format --dry-run -Werror src/controllers/AuthController.cpp
```

### Clangd Configuration
- Uses .clangd config with Clang-Tidy
- Key warnings: -Wpessimizing-move, -Wredundant-move, -Wunused-result
- Enabled checks: bugprone-*, cert-*, cppcoreguidelines-*, google-*, performance-*, misc-*, modernize-*, readability-*, portability-*
- Disabled checks: misc-unused-parameters, readability-identifier-length, readability-function-cognitive-complexity, readability-magic-numbers

## Code Style Guidelines

### File Organization
- Headers: `.hpp` extension (e.g., `AuthController.hpp`)
- Sources: `.cpp` extension (e.g., `AuthController.cpp`)
- Directory structure:
  - `src/controllers/` - HTTP request handlers
  - `src/models/` - Database models (auto-generated by drogon)
  - `src/services/` - Business logic layer
  - `src/requests/` - Request validation structures
  - `src/utils/` - Utility functions and helpers

### File Headers
Every file must include a Doxygen-style header:
```cpp
/**
 * @file AuthController.hpp
 * @author LiuFeng (liufeng.code@outlook.com)
 * @brief 认证控制器
 * @version 0.1
 * @date 2026-01-14
 *
 * @copyright Copyright (c) 2026
 *
 */
```

### Naming Conventions
- Classes/Structs: `PascalCase` (e.g., `AuthController`, `RegisterRequest`)
- Functions/Methods: `PascalCase` (e.g., `Register`, `ToJson`)
- Private members: `m_` prefix + `snake_case` (e.g., `m_auth_service`, `m_db_client`)
- Local variables: `snake_case` (e.g., `json_ptr`, `username`)
- Constants: `UPPER_SNAKE_CASE` (e.g., `DEFAULT_STORAGE_QUOTA`)
- Namespaces: `lowercase::nested` (e.g., `disk::auth`, `disk::utils`)

### Imports and Include Order
```cpp
// 1. Corresponding header first (in .cpp files)
#include "AuthController.hpp"

// 2. Project headers (relative to src/)
#include "requests/AuthRequest.hpp"
#include "utils/Response.hpp"

// 3. External library headers (Drogon, JWT, etc.)
#include <drogon/HttpController.h>
#include <jwt-cpp/jwt.h>

// 4. Standard library headers
#include <string>
#include <memory>
```

### Type Annotations
Use trailing return types consistently:
```cpp
auto Register(RegisterRequest request) -> drogon::Task<Result<RegisterResponse>>;
auto ValidateUsername() const -> bool;
auto ToJson() const -> Json::Value;
```

Mark functions that don't throw with `noexcept`:
```cpp
auto GetValueOfUsername() const noexcept -> const std::string&;
```

Use `[[nodiscard]]` for functions with important return values:
```cpp
[[nodiscard]]
auto FromRequest(const drogon::HttpRequestPtr& req) -> Result<RegisterRequest>;
```

### Error Handling
Use the `Result<T>` type (alias for `std::expected<T, ErrorInfo>`):
```cpp
// Return success
return std::make_unique<AuthService>(db_client);

// Return error with default message
return std::unexpected(ErrorInfo(ErrorCode::InvalidParameter));

// Return error with custom message
return std::unexpected(ErrorInfo(ErrorCode::ValidationFailed, "Username format invalid"));

// Propagate errors from other functions
if (!result) {
    return PropagateError<NewType>(result);
}

// Check and handle Result
if (!parse_result) {
    co_return Response::Error(parse_result.error());
}
```

Use convenience functions:
```cpp
// Create success
return MakeSuccess(user);

// Create error
return MakeError<User>(ErrorCode::UsernameExists);
return MakeError<User>(ErrorCode::ValidationFailed, "Custom message");
```

### String Formatting
Use string concatenation with logging:
```cpp
LOG_INFO << "User registered: " << username << " (ID: " << id << ")";
```

### Constants and Configuration
Use `constexpr` for compile-time constants:
```cpp
static constexpr uint64_t DEFAULT_STORAGE_QUOTA = 10737418240;
```

### Precompiled Headers
Include `utils/Pch.hpp` in new .cpp files for common headers. Don't duplicate common includes.

### Coroutines (Drogon Tasks)
Use `drogon::Task<T>` for async functions:
```cpp
auto Register(drogon::HttpRequestPtr request) -> drogon::Task<drogon::HttpResponsePtr> {
    // Parse request
    auto parse_result = RegisterRequest::FromRequest(request);
    if (!parse_result) {
        co_return Response::Error(parse_result.error());
    }

    // Await async operations
    auto register_result = co_await m_auth_service->Register(*parse_result);

    // Return response
    co_return Response::Success(data);
}
```

### Structs for Data Transfer
Define request/response structs with validation:
```cpp
struct RegisterRequest {
    std::string username;
    std::string email;
    std::string password;

    [[nodiscard]]
    static auto FromRequest(const drogon::HttpRequestPtr& req) -> Result<RegisterRequest> {
        // Validation logic
        return request;
    }
};
```

### Response Formatting
Use the `Response` class for HTTP responses:
```cpp
// Success with data
co_return Response::Success(data);

// Paginated response
co_return Response::Paginated(items, pagination);

// Error from ErrorInfo
co_return Response::Error(error_info);

// Error from ErrorCode
co_return Response::Error(ErrorCode::InvalidParameter);
```

### Database Operations
Use Drogon ORM with CoroMapper for async operations. Models are auto-generated by `drogon_ctl` - DO NOT EDIT `.hpp` and `.cpp` files in `models/` directory.

### Comments
- Use Chinese for comments that explain business logic
- Use English for technical comments
- Add brief Doxygen comments for public APIs
- Avoid excessive inline comments - let code be self-documenting

### Formatting (Clang-Format)
- Style: Google
- Column limit: 0 (no limit)
- Brace wrapping: Custom (same line for most cases)
- Bin packing: Disabled for arguments and parameters
- Don't add comments unless asked
- Let clang-format handle spacing and alignment
