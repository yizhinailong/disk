# Disk Project - Agent Guidelines

## Build/Test Commands

### Configure and Build
```bash
cmake --preset linux-debug-clang      # Debug
cmake --preset linux-release-clang     # Release
cmake --build --preset linux-debug-clang
cmake --build --preset linux-debug-clang --target disk-test
```

### Run Tests
```bash
# Run all tests
ctest --preset linux-debug-clang

# Run specific test suite
ctest --preset linux-debug-clang -R PasswdHash -V
ctest --preset linux-debug-clang -R AuthRequest -V

# Run single test (CamelCase only, NO underscores)
./build/linux-debug-clang/test/disk-test --gtest_filter="PasswdHash.HashValidPassword"
./build/linux-debug-clang/test/disk-test --gtest_filter="RegisterRequest.ValidParameters"

# List all tests
./build/linux-debug-clang/test/disk-test --gtest_list_tests
```

### Format and Lint
```bash
find src test -name '*.cpp' -o -name '*.hpp' | xargs clang-format -i
clang-format -i src/controllers/AuthController.cpp
```

## Code Style Guidelines

### File Headers
```cpp
/**
 * @file AuthController.hpp
 * @author LiuFeng (liufeng.code@outlook.com)
 * @brief 认证控制器
 * @version 0.1
 * @date 2026-01-14
 *
 * @copyright Copyright (c) 2026
 *
 */
```

### Type Annotations
```cpp
auto Register(RegisterRequest request) -> drogon::Task<Result<RegisterResponse>>;
auto ValidateUsername() const -> bool;
auto GetValueOfUsername() const noexcept -> const std::string&;
[[nodiscard]]
auto FromRequest(const drogon::HttpRequestPtr& req) -> Result<RegisterRequest>;
```

### Error Handling
Use `Result<T>` type (alias for `std::expected<T, ErrorInfo>`):
```cpp
// Return success
return std::make_unique<AuthService>(db_client);
return std::unexpected(ErrorInfo(ErrorCode::InvalidParameter));
return std::unexpected(ErrorInfo(ErrorCode::ValidationFailed, "Username format invalid"));

if (!result) {
    co_return Response::Error(parse_result.error());
}
```

### Naming Conventions
- Classes/Structs: `PascalCase` (e.g., `AuthController`, `RegisterRequest`)
- Functions/Methods: `PascalCase` (e.g., `Register`, `ToJson`)
- Private members: `m_` prefix + `snake_case` (e.g., `m_auth_service`, `m_db_client`)
- Local variables: `snake_case` (e.g., `json_ptr`, `username`)
- Constants: `UPPER_SNAKE_CASE` (e.g., `DEFAULT_STORAGE_QUOTA`)
- Namespaces: `lowercase::nested` (e.g., `disk::auth`, `disk::utils`)

### Imports and Include Order
```cpp
#include "AuthController.hpp"
#include "requests/AuthRequest.hpp"
#include "utils/Response.hpp"
#include <drogon/HttpController.h>
#include <jwt-cpp/jwt.h>
#include <memory>
#include <string>
```

### Precompiled Headers
Include `utils/Pch.hpp` in new .cpp files. Don't duplicate common includes.

### Coroutines (Drogon Tasks)
Use `drogon::Task<T>` for async functions with `co_await` and `co_return`.

### GTest Naming
Use CamelCase, NO underscores (per Google Test FAQ):
```cpp
TEST(PasswdHash, HashValidPassword) { }      // ✅ Correct
TEST(PasswdHash, Hash_ValidPassword) { }    // ❌ Wrong
```

### Constants
```cpp
static constexpr uint64_t DEFAULT_STORAGE_QUOTA = 10737418240;
```

## Project Structure
```
src/
├── controllers/   # HTTP request handlers
├── models/       # Database models (auto-generated by drogon)
├── services/     # Business logic layer
├── requests/     # Request validation structures
└── utils/        # Utility functions and helpers (Pch.hpp, ErrorCode.hpp, etc.)
test/
├── main.cpp       # GTest entry point
├── utils/        # Unit tests for utilities
└── requests/     # Unit tests for request validation
```

## Error Code Ranges
- 0: Success
- 10xxx: General errors
- 40xxx: Authentication errors
- 50xxx: File operations errors
- 60xxx: Share operations errors
